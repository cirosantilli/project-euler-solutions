# Project Euler 453 Solution - Lattice Quadrilaterals

<https://projecteuler.net/problem=453>:

* [453.py](453.py)

This repo contains a fast, exact ([integer](https://ourbigbook.com/codex/integer)) solver for:

- **Problem 453**: `Q(12345, 6789) mod 135707531`

where `Q(m, n)` counts **simple [quadrilaterals](https://ourbigbook.com/codex/quadrilateral)** whose [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) are [lattice points](https://ourbigbook.com/codex/lattice-point) in the [rectangle](https://ourbigbook.com/codex/rectangle)
`0 ≤ x ≤ m`, `0 ≤ y ≤ n` (distinct [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon), no straight [angles](https://ourbigbook.com/codex/angle), no self-intersection).

## Main techniques used

### 1) Combinatorial classification of 4-point sets
For four [lattice points](https://ourbigbook.com/codex/lattice-point) (with no three [collinear](https://ourbigbook.com/codex/collinearity)):

- If the 4 points form a **convex** [quadrilateral](https://ourbigbook.com/codex/quadrilateral), there is **exactly 1** simple [quadrilateral](https://ourbigbook.com/codex/quadrilateral).
- If one point lies **strictly inside** the [triangle](https://ourbigbook.com/codex/triangle) formed by the other three (a **[concave](https://ourbigbook.com/codex/concavity)** case),
  there are **exactly 3** different simple [quadrilaterals](https://ourbigbook.com/codex/quadrilateral) (three different ways to “walk around” the
  [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) without self-intersection).

[Collinearities](https://ourbigbook.com/codex/collinearity) are handled via separate correction terms.

This reduces the problem to counting certain geometric/combinatorial configurations, instead of
enumerating [quadrilaterals](https://ourbigbook.com/codex/quadrilateral) directly.

### 2) Turning geometry into arithmetic sums
The final closed form for `Q(m,n)` can be written as a [combination](https://ourbigbook.com/codex/combination-combinatorics) of:

- [Binomial coefficients](https://ourbigbook.com/codex/binomial-coefficient) in `P = (m+1)(n+1)`
- A term `S` = **sum of triangle areas** over all [Euclidean lattice](https://ourbigbook.com/codex/euclidean-lattice) [triangles](https://ourbigbook.com/codex/triangle) in the box
- Two “degeneracy correction” terms `L3` and `L4` that count [collinear](https://ourbigbook.com/codex/collinearity) triples/quadruples in a
  weighted way, expressible using `gcd(Δx,Δy)` sums.

All of these can be expressed using sums of the form:

- `∑ x^a y^b gcd(x,y)^c` over rectangular ranges

### 3) Fast evaluation via floor-division grouping + memoization
Naively summing over all `x,y` up to `(12345,6789)` is too slow.

The implementation uses a classic trick for [summatory functions](https://ourbigbook.com/codex/summatory-function):

- Many terms depend on `⌊m/k⌋` and `⌊n/k⌋`, which take only **O(√m)** distinct values.
- We group equal floor-division values into blocks, and use [recursion](https://ourbigbook.com/codex/recursion) + [memoization](https://ourbigbook.com/codex/memoization) (caching) to
  compute weighted **[coprime](https://ourbigbook.com/codex/coprime) sums**:

  `G(u,v,a,b) = ∑_{gcd(x,y)=1, x≤u, y≤v} x^a y^b`

From `G`, we build:

`H(a,b,c) = ∑_{x≤m,y≤n} x^a y^b gcd(x,y)^c`

and then assemble the closed form for `Q(m,n)`.

### 4) Pick’s theorem (conceptually)
[Pick's theorem](https://ourbigbook.com/codex/pick-s-theorem) is used in the underlying derivation to relate [triangle](https://ourbigbook.com/codex/triangle) [area](https://ourbigbook.com/codex/area), boundary [lattice points](https://ourbigbook.com/codex/lattice-point),
and interior [lattice points](https://ourbigbook.com/codex/lattice-point). That’s what allows the “[geometry](https://ourbigbook.com/codex/geometry)” pieces to be rewritten into gcd-based
arithmetic sums.
