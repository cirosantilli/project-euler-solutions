# Project Euler 123 Solution - Prime Square Remainders

<https://projecteuler.net/problem=123>:

* [123.py](123.py)

## Problem Summary

Let $p_n$ be the $n$-th [prime](https://ourbigbook.com/codex/prime-number), and define $r_n$ as the least nonnegative [remainder](https://ourbigbook.com/codex/remainder) of

$$\left((p_n-1)^n+(p_n+1)^n\right)\bmod p_n^2.$$

The task is to find the smallest index $n$ for which $r_n\gt 10^{10}$. At first sight this looks like a large modular-exponentiation problem, but [modulo](https://ourbigbook.com/codex/modulo-operation) $p_n^2$ almost every binomial term disappears. That collapse is the whole reason the problem becomes easy.

## Mathematical Approach

The [remainder](https://ourbigbook.com/codex/remainder) is governed entirely by the first two terms of the binomial expansion. Once that is written out carefully, the problem stops being about huge powers and becomes a search over [prime](https://ourbigbook.com/codex/prime-number) indices.

### Binomial expansion modulo $p_n^2$

Expand both powers around $p_n$:

$$
  (p_n\pm 1)^n=\sum_{k=0}^{n}\binom{n}{k}p_n^k(\pm 1)^{\,n-k}.
  $$

Adding the two expansions gives

$$
  (p_n-1)^n+(p_n+1)^n
  =
  \sum_{k=0}^{n}\binom{n}{k}p_n^k\left((-1)^{n-k}+1\right).
  $$

Any term with $k\ge 2$ is already divisible by $p_n^2$, so [modulo](https://ourbigbook.com/codex/modulo-operation) $p_n^2$ only the cases $k=0$ and $k=1$ can survive. Which of those survives depends only on the [integer parity](https://ourbigbook.com/codex/integer-parity) of $n$.

### Even indices and odd indices behave differently

If $n$ is even, then the [constant terms](https://ourbigbook.com/codex/constant-term) add and the linear terms cancel, so

$$
  r_n\equiv 2 \pmod{p_n^2}.
  $$

Because $0\le 2\lt p_n^2$, the actual [remainder](https://ourbigbook.com/codex/remainder) is simply $r_n=2$. Even indices can therefore never exceed $10^{10}$.

If $n$ is odd, then the [constant terms](https://ourbigbook.com/codex/constant-term) cancel and the linear terms add, giving

$$
  r_n\equiv 2np_n \pmod{p_n^2}.
  $$

So for odd indices the [remainder](https://ourbigbook.com/codex/remainder) is controlled by the single quantity $2np_n$, but at this stage it is still a [integer congruence](https://ourbigbook.com/codex/integer-congruence) rather than an exact equality.

### Why the congruence becomes the exact remainder

The implementations compare $2np_n$ directly against the limit, so we need to know when $2np_n$ is already smaller than $p_n^2$. A simple counting argument is enough. For $n\ge 5$, the [odd numbers](https://ourbigbook.com/codex/odd-number)

$$
  1,3,5,\dots,2n-1
  $$

form a list of exactly $n$ numbers. Among them, both $1$ and $9$ are non-prime, so there are at most $n-2$ [odd primes](https://ourbigbook.com/codex/odd-prime) below $2n$. Including the [prime](https://ourbigbook.com/codex/prime-number) $2$, there are at most $n-1$ [primes](https://ourbigbook.com/codex/prime-number) not exceeding $2n$. Therefore the $n$-th [prime](https://ourbigbook.com/codex/prime-number) must satisfy

$$
  p_n\gt 2n \qquad (n\ge 5).
  $$

For odd $n\ge 5$ this implies

$$
  0\lt 2np_n\lt p_n^2,
  $$

so the [least nonnegative residue](https://ourbigbook.com/codex/least-nonnegative-residue) of $2np_n \pmod{p_n^2}$ is exactly $2np_n$. Hence

$$
  r_n=2np_n.
  $$

The first solution occurs far beyond $n=5$, so this is the formula the code can safely search with.

### Worked example: $n=3$ versus $n=5$

The distinction between [integer congruence](https://ourbigbook.com/codex/integer-congruence) and exact [remainder](https://ourbigbook.com/codex/remainder) matters for tiny odd indices. For $n=3$, we have $p_3=5$, so

$$
  (5-1)^3+(5+1)^3=4^3+6^3=280.
  $$

[Modulo](https://ourbigbook.com/codex/modulo-operation) $25$, this gives $280\bmod 25=5$. The linear formula gives $2np_n=2\cdot 3\cdot 5=30$, and indeed $30\equiv 5\pmod{25}$, but the exact [remainder](https://ourbigbook.com/codex/remainder) is $5$, not $30$.

For $n=5$, however, $p_5=11$ and

$$
  (11-1)^5+(11+1)^5=10^5+12^5=348832.
  $$

Now $348832\bmod 121=110$, and that equals

$$
  2\cdot 5\cdot 11=110.
  $$

Here no wrap-around occurs because $2n\lt p_n$. The target threshold is so large that the first qualifying index lies in this stable regime.

### Estimating the search range

The [prime number theorem](https://ourbigbook.com/codex/prime-number-theorem) gives the rough estimate $p_n\sim n\log n$. Substituting that into the odd-index formula yields

$$
  2n^2\log n \gtrsim 10^{10}.
  $$

This places the crossing a little above $2\times 10^4$. So the program only needs to generate [primes](https://ourbigbook.com/codex/prime-number) up to roughly the corresponding $p_n$, which is on the order of a few hundred thousand. That makes a straightforward [sequential search](https://ourbigbook.com/codex/sequential-search) entirely adequate.

## How the Code Works

### Generate primes in order

The C++, Python, and Java implementations all walk through the [prime](https://ourbigbook.com/codex/prime-number) sequence in increasing order so that the current [prime](https://ourbigbook.com/codex/prime-number) and its index are known simultaneously. The C++ and Java versions keep a growing list of earlier [primes](https://ourbigbook.com/codex/prime-number) and test each new [integer](https://ourbigbook.com/codex/integer) candidate only by those [primes](https://ourbigbook.com/codex/prime-number) up to its [square root](https://ourbigbook.com/codex/square-root). The Python version advances from one [prime](https://ourbigbook.com/codex/prime-number) to the next through a prime-generation routine, but conceptually it performs the same ordered scan.

### Check only odd indices

Each time a new [prime](https://ourbigbook.com/codex/prime-number) $p_n$ is reached, the implementation first checks whether $n$ is odd. Even indices are skipped immediately because their [remainder](https://ourbigbook.com/codex/remainder) is always $2$. For odd indices, it evaluates the simple expression $2np_n$ and stops as soon as this exceeds the limit. None of the implementations ever compute $(p_n-1)^n$ or $(p_n+1)^n$ directly. One implementation also verifies the logic against the smaller threshold $10^9$ before running the full search.

## Complexity Analysis

Let $P$ be the [prime](https://ourbigbook.com/codex/prime-number) where the search stops. After a [prime](https://ourbigbook.com/codex/prime-number) is known, the mathematical test is [constant time](https://ourbigbook.com/codex/constant-time): [integer parity](https://ourbigbook.com/codex/integer-parity) check plus one [multiplication](https://ourbigbook.com/codex/multiplication) and one comparison.

In the C++ and Java implementations, the real cost is [prime](https://ourbigbook.com/codex/prime-number) generation by incremental [trial division](https://ourbigbook.com/codex/trial-division). A candidate $c$ is tested only by previously found [primes](https://ourbigbook.com/codex/prime-number) up to $\sqrt c$, so a standard worst-case estimate is

$$
  O\!\left(\sum_{c=2}^{P}\pi(\sqrt c)\right)=O\!\left(\frac{P^{3/2}}{\log P}\right),
  $$

with memory usage $O(\pi(P))$ for the stored [primes](https://ourbigbook.com/codex/prime-number). For this problem $P$ is only a few $10^5$, so that cost is small in practice. The Python implementation delegates [prime](https://ourbigbook.com/codex/prime-number) stepping to a library routine, but from the problem's point of view it still performs one [constant-time](https://ourbigbook.com/codex/constant-time) [remainder](https://ourbigbook.com/codex/remainder) test per [prime](https://ourbigbook.com/codex/prime-number) index.
