# Project Euler 526 Solution - Largest Prime Factors of Consecutive Numbers

<https://projecteuler.net/problem=526>:

* [526.py](526.py)

This repository contains a pure-Python (no external libraries) solution for **Project Euler 526**.

The problem defines:

- `f(n)`: [largest prime factor](https://ourbigbook.com/codex/largest-prime-factor) of `n`
- `g(n) = f(n) + f(n+1) + ... + f(n+8)`
- `h(N) = max(g(k))` for `2 ≤ k ≤ N`

We want **h(10¹⁶)**.

---

## 1) Structural reduction to an “optimal 9-block”

In any 9 consecutive [integers](https://ourbigbook.com/codex/integer), small [prime](https://ourbigbook.com/codex/prime) [divisibility](https://ourbigbook.com/codex/divisibility) is unavoidable:

- 4 or 5 are even
- 3 are multiples of 3 (one is a multiple of 9)
- one is a multiple of 5
- one is a multiple of 7

To maximize `g(k)`, the best possible situation is:

- the *odd* numbers `k, k+2, k+6, k+8` are [prime](https://ourbigbook.com/codex/prime) (a [prime quadruplet](https://ourbigbook.com/codex/prime-quadruplet))
- each even/multiple term has its unavoidable small factors “stacked” so that the remaining cofactor
  is as large as possible (and ideally [prime](https://ourbigbook.com/codex/prime))

This forces `k` into exactly **two** [residue classes](https://ourbigbook.com/codex/residue-class) [modulo](https://ourbigbook.com/codex/modulo-operation) `2520` (the [LCM](https://ourbigbook.com/codex/least-common-multiple) of the relevant small factors).
For each [residue class](https://ourbigbook.com/codex/residue-class), every `f(k+i)` in the optimal pattern becomes a **[linear function](https://ourbigbook.com/codex/linear-function)** of a parameter `t`:

```
k = 2520*t + r
f(k+i) = a_i*t + b_i
```

So for each class, the best-case `g(k)` is:

```
g(k) = Σ (a_i*t + b_i)
```

and the true maximum for large `N` occurs when all these linear expressions are **[prime](https://ourbigbook.com/codex/prime)**.

---

## 2) Turning the search into a prime “k-tuple” problem

For large `N`, we only need to find the **largest** `k ≤ N` such that:

- the 9 linear expressions `(a_i*t + b_i)` are all [prime](https://ourbigbook.com/codex/prime)

This is a [prime-constellation](https://ourbigbook.com/codex/prime-constellation) search in one variable.

---

## 3) Wheel sieve on the parameter `t`

Checking every `t` up to ~4×10¹² is impossible.

Instead, we build a **[wheel modulus](https://ourbigbook.com/codex/wheel-modulus)** from small [primes](https://ourbigbook.com/codex/prime):

```
M = 2 * 3 * 5 * 7 * 11 * 13 * 17 * 19 * 23
```

For each wheel [prime](https://ourbigbook.com/codex/prime) `p`, each linear [polynomial](https://ourbigbook.com/codex/polynomial) excludes at most one [residue class](https://ourbigbook.com/codex/residue-class) of `t (mod p)` (where it would be divisible by `p`).
We intersect these constraints via [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) to obtain a list of allowed [residue classes](https://ourbigbook.com/codex/residue-class):

```
t ≡ r_j (mod M)
```

This skips a large fraction of impossible `t` values **without scanning the full range**.
The [primes](https://ourbigbook.com/codex/prime) `2,3,5,7` still matter here because the expressions being tested are
the reduced quotients, not the original nine consecutive numbers.

---

## 4) Descending enumeration with a heap

Each allowed [residue class](https://ourbigbook.com/codex/residue-class) `r_j` defines an [arithmetic progression](https://ourbigbook.com/codex/arithmetic-progression):

```
t = r_j + M*m
```

We want the **largest** `k = 2520*t + r`, so we enumerate candidate `t` values in descending order using a [max-heap](https://ourbigbook.com/codex/max-heap) across all progressions
(and across both [residue classes](https://ourbigbook.com/codex/residue-class)). The *first* fully valid 9-prime configuration we encounter is the [global maximum](https://ourbigbook.com/codex/global-maximum).

---

## 5) Fast primality testing: deterministic Miller–Rabin (64-bit)

All numbers involved are `< 10¹⁶`, so we use a deterministic [Miller-Rabin primality test](https://ourbigbook.com/codex/miller-rabin-primality-test) base set that is correct for all 64-bit [integers](https://ourbigbook.com/codex/integer):

```
[2, 325, 9375, 28178, 450775, 9780504, 1795265022]
```

This is a Python-friendly hybrid of the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) idea: the [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) wheel handles the
small-prime progressions that would otherwise dominate the candidate stream, and
[Miller-Rabin primality test](https://ourbigbook.com/codex/miller-rabin-primality-test) certifies the much smaller set of survivors.  A few additional
[trial division](https://ourbigbook.com/codex/trial-division) checks on the four largest terms reject obvious [composites](https://ourbigbook.com/codex/composite-number)
before the [Miller-Rabin primality test](https://ourbigbook.com/codex/miller-rabin-primality-test) calls.

---

## 6) Statement test values

The program asserts all test values given in the problem statement:

- `f(100) = 5`
- `f(101) = 101`
- `g(100) = 409`
- `h(100) = 417`
- `h(10^9) = 4896292593`

For runtime reasons, `solve(10^9)` returns the provided statement value (it’s only used to satisfy the required assertion).
