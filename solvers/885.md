# Project Euler 885 Solution - Sorted Digits

<https://projecteuler.net/problem=885>:

* [885.py](885.py)

## Core idea

We need the sum of `f(d)` over all [positive integers](https://ourbigbook.com/codex/positive-integer) with at most `n` decimal [digits](https://ourbigbook.com/codex/numerical-digit), where `f(d)` is formed by:

1. taking the [digits](https://ourbigbook.com/codex/numerical-digit) of `d`,
2. [sorting](https://ourbigbook.com/codex/sorting) them in nondecreasing order,
3. deleting every `0`.

A useful simplification is to view all numbers with at most `n` [digits](https://ourbigbook.com/codex/numerical-digit) as **all length‑`n` [digit](https://ourbigbook.com/codex/numerical-digit) strings** (allowing leading zeros). This represents the [integers](https://ourbigbook.com/codex/integer) `0..10^n-1`. The special case of the all‑zero string contributes `0` anyway, so it doesn’t change the total.

## Turning the sum into a closed form

Instead of iterating through numbers, we count contributions in bulk.

Consider a fixed [digit](https://ourbigbook.com/codex/numerical-digit) threshold `k` (from `1` to `9`). For any number, let:

- `u` = how many [digits](https://ourbigbook.com/codex/numerical-digit) are `>= k`.

After [sorting](https://ourbigbook.com/codex/sorting) and deleting zeros, the [digits](https://ourbigbook.com/codex/numerical-digit) `>= k` occupy the **last** `u` positions of the sorted string. This observation makes it possible to count, for each `k`, how often each power of `10` is “turned on” by [digits](https://ourbigbook.com/codex/numerical-digit) at least `k`.

When you sum over all length‑`n` [digit](https://ourbigbook.com/codex/numerical-digit) strings, each position independently ranges over `0..9`, so the needed counts reduce to binomial expansions of the form:

- choosing which positions are `>= k`,
- counting assignments of [digits](https://ourbigbook.com/codex/numerical-digit) `< k` and `>= k`.

This collapses into an expression involving powers of a single constant, leading to:

\[
S(n)=\frac{1}{9}\sum_{k=1}^{9}(10+9k)^n - 10^n.
\]

The division by `9` is exact as an [integer](https://ourbigbook.com/codex/integer) identity; for [modular arithmetic](https://ourbigbook.com/codex/modular-arithmetic) we use the [modular inverse](https://ourbigbook.com/codex/modular-inverse) of `9`.

## Implementation technique

- **[Modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation)** (`pow(base, exp, mod)`) computes `(10+9k)^n mod M` quickly.
- **Extended Euclid** computes the [modular inverse](https://ourbigbook.com/codex/modular-inverse) of `9` [modulo](https://ourbigbook.com/codex/modulo-operation) `M` (works whenever `gcd(9, M)=1`).
- The problem’s provided values `S(1)` and `S(5)` are checked with assertions using the same formula evaluated as exact [integers](https://ourbigbook.com/codex/integer).

## Complexity

The computation performs a constant amount of [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation) (9 bases), so it runs in essentially `O(9 log n)` time and `O(1)` memory.
