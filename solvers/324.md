# Project Euler 324 Solution - Building a Tower

<https://projecteuler.net/problem=324>:

* [324.py](324.py)

We want the number of [tilings](https://ourbigbook.com/codex/tessellation) of a **3 × 3 × n** box using **2 × 1 × 1** blocks (dominoes), where dominoes may be oriented along any axis. The answer is required **[modulo](https://ourbigbook.com/codex/modulo)** `100000007`.

## Techniques used

### 1) Profile DP / transfer matrix on slices

Cut the tower perpendicular to its length. Each slice is a **3 × 3** layer with **9 cells**.

A domino can:
- lie **within the current slice** (two adjacent cells in the 3×3 plane), or
- stick **forward into the next slice** (same (x,y) cell, next z).

That means the only information that must cross a slice boundary is which cells in the *current* slice are already occupied by dominoes that started in the previous slice.

Represent that boundary as a **9‑[bit mask](https://ourbigbook.com/codex/bit-mask)** ⇒ **2⁹ = 512 states**.

For each incoming mask we recursively enumerate all ways to finish the slice and count which **next mask** is produced. This gives a sparse transition list:

`mask -> [(next_mask, count), ...]`

Iterating those transitions yields `f(n)` for moderate `n`.

### 2) Even-height reduction

The box has `9n` unit cubes. Since `9` is odd, `9n` is even **iff** `n` is even, so:

- `f(n) = 0` for odd `n`
- define `a(m) = f(2m)` and work only with `a`

### 3) Berlekamp–Massey to find a short recurrence

The [sequence](https://ourbigbook.com/codex/sequence) `a(m) mod MOD` satisfies a [linear recurrence](https://ourbigbook.com/codex/linear-recurrence) with constant [coefficients](https://ourbigbook.com/codex/coefficient).

Using a prefix of values computed by the [transfer DP](https://ourbigbook.com/codex/transfer-dp), **[Berlekamp–Massey](https://ourbigbook.com/codex/berlekamp-massey-algorithm)** finds the *shortest* [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) over the [finite field](https://ourbigbook.com/codex/finite-field) (here `MOD = 100000007` is [prime](https://ourbigbook.com/codex/prime)).

This collapses the problem from a 512‑state [DP](https://ourbigbook.com/codex/dynamic-programming) to a small `k`‑term [recurrence relation](https://ourbigbook.com/codex/recurrence-relation).

### 4) Kitamasa (polynomial exponentiation) for huge indices

To evaluate `a(m)` for a gigantic `m` (here `m = 5·10⁹⁹⁹⁹`), we use **[Kitamasa's algorithm](https://ourbigbook.com/codex/kitamasa-algorithm)**:

- represent `a(m)` as a [linear combination](https://ourbigbook.com/codex/linear-combination) of the first `k` values
- compute the [coefficient](https://ourbigbook.com/codex/coefficient) vector by exponentiating `x^m` **[modulo](https://ourbigbook.com/codex/modulo) the [characteristic polynomial of a linear recurrence](https://ourbigbook.com/codex/characteristic-polynomial-of-a-linear-recurrence)**
- complexity is **O(k² log m)**

This makes `f(10^10000)` feasible.
