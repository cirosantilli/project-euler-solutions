# Project Euler 283 Solution - Integer Sided Triangles with Integral Area/perimeter Ratio

<https://projecteuler.net/problem=283>:

* [283.py](283.py)

## Core Observation (Geometry → Number Theory)

For any [triangle](https://ourbigbook.com/codex/triangle):

- `Area = r * s`, where `r` is the [inradius](https://ourbigbook.com/codex/inradius) and `s` is the [semiperimeter](https://ourbigbook.com/codex/semiperimeter).
- `Perimeter = 2s`

So:

\[
\frac{Area}{Perimeter} = \frac{r s}{2 s} = \frac{r}{2}
\]

Therefore, the condition “[Area](https://ourbigbook.com/codex/area)/[Perimeter](https://ourbigbook.com/codex/perimeter) is an [integer](https://ourbigbook.com/codex/integer) `k`” becomes:

- `r = 2k` is an **[even integer](https://ourbigbook.com/codex/even-integer)**
- and `k ≤ 1000` implies `r ≤ 2000`

So the problem becomes:

> Sum [perimeters](https://ourbigbook.com/codex/perimeter) of all integer-sided [triangles](https://ourbigbook.com/codex/triangle) whose **[inradius](https://ourbigbook.com/codex/inradius)** is an [even integer](https://ourbigbook.com/codex/even-integer) ≤ 2000.

---

## Tangency / Semiperimeter Variables

Define:

\[
x = \frac{a+b-c}{2},\quad
y = \frac{a-b+c}{2},\quad
z = \frac{-a+b+c}{2}
\]

Then:

- `a = x+y`, `b = x+z`, `c = y+z`
- `Perimeter = 2(x+y+z)`

Using [Heron's formula](https://ourbigbook.com/codex/heron-s-formula) + [inradius](https://ourbigbook.com/codex/inradius) identity:

\[
r^2(x+y+z) = xyz
\]

Let `n = r²`. Then:

\[
n(x+y+z)=xyz
\]

---

## Ordering + Critical Bound

Assume canonical ordering:

\[
x \le y \le z
\]

Because `z ≥ x,y` we have:

\[
x+y \le 2z \Rightarrow x+y+z \le 3z
\]

Plugging into `xyz = n(x+y+z)`:

\[
xyz \le 3nz \Rightarrow xy \le 3n
\]

This is the crucial finiteness/efficiency bound:  
**for each `n`, valid pairs satisfy `xy ≤ 3n`.**

Also define:

\[
d = xy-n
\]

Since `xy ≤ 3n`, we get:

\[
d = xy-n \le 2n
\]

So `d` always lies in the small [interval](https://ourbigbook.com/codex/interval) `1..2n`.

---

## Divisibility Trick (Avoid Scanning y)

We use:

\[
z = \frac{n(x+y)}{xy-n} = \frac{n(x+y)}{d}
\]

Thus `d` must divide `n(x+y)`.

Also `d = xy-n`.

A key elimination:

- `d | n(x+y)`  
- `d | (xy-n)`

Combine them to remove `y`, giving:

\[
d \mid n(x^2+n)
\]

So for each `(n,x)`, we enumerate [divisors](https://ourbigbook.com/codex/divisor):

- `d` dividing `n(x²+n)`
- with `d ≤ 2n`

Then recover:

\[
y=\frac{n+d}{x}
\]

and check if `z` is [integral](https://ourbigbook.com/codex/integral) and `z ≥ y`.

This transforms a huge search into manageable [divisor](https://ourbigbook.com/codex/divisor) enumeration.

## Implementation Techniques

✅ **[Smallest Prime Factor Sieve](https://ourbigbook.com/codex/smallest-prime-factor-sieve) ([SPF](https://ourbigbook.com/codex/smallest-prime-factor))**  
Used to factor many values quickly (`≤ 16,000,000`) while looping.

✅ **Prime-factor merge**  
Factor `n` once per [radius](https://ourbigbook.com/codex/radius), factor `x²+n` per `x`, merge [exponents](https://ourbigbook.com/codex/exponent).

✅ **Bounded [divisor](https://ourbigbook.com/codex/divisor) generation**  
Generate [divisors](https://ourbigbook.com/codex/divisor) of `n(x²+n)` only up to `2n`.

✅ **Canonical ordering (x ≤ y ≤ z)**  
Ensures each [triangle](https://ourbigbook.com/codex/triangle) counted once.
