# Project Euler 83 Solution - Path Sum: Four Ways

<https://projecteuler.net/problem=83>:

* [83.py](83.py)
* [83.lean](83.lean)

We need the minimum-cost [graph path](https://ourbigbook.com/codex/graph-path) from the top-left cell to the bottom-right cell in a grid, where moves are allowed in four directions (up/down/left/right). Each cell value is a non-negative cost, and the [graph path](https://ourbigbook.com/codex/graph-path) [sum](https://ourbigbook.com/codex/sum) includes both the starting and ending cells.

### Key insight
This is a shortest-path problem on a [weighted graph](https://ourbigbook.com/codex/weighted-graph):
- Each grid cell is a [graph vertex](https://ourbigbook.com/codex/graph-vertex).
- [Edges](https://ourbigbook.com/codex/edge) connect adjacent cells (4-neighborhood).
- Moving into a neighbor adds the neighbor cell's value to the total cost.
- Start distance is the value of the top-left cell.

Because all [edge](https://ourbigbook.com/codex/edge) weights are non-negative, [Dijkstra's algorithm](https://ourbigbook.com/codex/dijkstra-s-algorithm) finds the optimal [graph path](https://ourbigbook.com/codex/graph-path) efficiently.

### Approach
- Parse the [matrix](https://ourbigbook.com/codex/matrix) (CSV per row).
- Run Dijkstra with a [priority queue](https://ourbigbook.com/codex/priority-queue) (`heapq`) over the `N*M` [graph vertices](https://ourbigbook.com/codex/graph-vertex).
- Maintain a distance [array](https://ourbigbook.com/codex/array) and a visited [array](https://ourbigbook.com/codex/array).
- Stop as soon as the bottom-right [graph vertex](https://ourbigbook.com/codex/graph-vertex) is finalized (popped as the smallest unvisited distance).

### Complexity
For an `80x80` grid (6400 [graph vertices](https://ourbigbook.com/codex/graph-vertex)), Dijkstra runs very fast:
- Time: `O(V log V + E log V)` with `E ≈ 4V`
- Memory: `O(V)`


### Generalized inputs and proof status

The shared input is a rectangular `list[list[int]]` with nonnegative entries. Empty dimensions return zero. Both Python implementations preserve the input, including shared rows. The initial distance bound is the sum of all cell costs plus one, so integer costs have no fixed ceiling.

[The path-bound proof](../ProjectEulerSolutions/Lib/NonnegativeWalkBounds.lean) removes cycles without increasing cost. A simple path visits at most `rows * columns` cells and costs less than the initial bound; this also justifies the reference's finite relaxation count. These are structural proofs, without whole-program computation.

The [reference Python proof](../data/project-euler-statements/data/py/project_euler_statements/p83.py.lean) covers the complete call: input validation, initialization, neighbor filtering, cell relaxation, all iterations, and the final lookup. It proves agreement with the reference Lean model while preserving caller objects and retaining temporary tuple and list allocations. [Lean model equivalence](../ProjectEulerSolutions/Equiv/P83.lean) proves that the scan-based Dijkstra model and the reference return the same value over the full shared domain. The optimized Python priority-queue execution remains unfinished, so the solver's Python proof is not listed as complete.

[The grid minimum proof](../ProjectEulerSolutions/Lib/GridShortestPaths.lean) shows that the reference attains a shortest walk for every rectangular nonnegative matrix. It connects finite grid coordinates, the matrix recurrence, and the input-derived iteration and distance bounds. The [Python composition](../data/project-euler-statements/data/py/project_euler_statements/p83.py.lean.d/ShortestPath.lean) proves that the actual reference call returns that minimum while preserving caller objects.

[Dijkstra selection](../ProjectEulerSolutions/Lib/DijkstraSelection.lean) and the [frontier argument](../ProjectEulerSolutions/Lib/DijkstraFrontier.lean) justify finalizing the least unvisited estimate. The [array invariant](../ProjectEulerSolutions/Lib/DijkstraGridInvariant.lean) preserves path witnesses, settled minima, and crossing-edge bounds. The [traversal proof](../ProjectEulerSolutions/Lib/DijkstraGridTraversal.lean) shows that each active step settles one new cell and that `rows * columns` steps suffice. These proofs use structural induction and the input-derived bounds, without whole-program computation.

The [Python queue contracts](83.py.lean.d/OrderedQueue.lean) prove that push and pop preserve heap order and that pop returns a minimum-distance entry. The [execution proof](83.py.lean.d/HeapOrder.lean) follows both concrete sift phases, including the right-child choice on tied tuple comparisons. Tuple identities and shared references are retained, with no bounds on queue size or integer priorities. The reusable [binary-heap repair invariant](../ProjectEulerSolutions/Lib/BinaryHeapSift.lean) tracks the displaced entry and the ordering between its parent and children.

The [entry proof](83.py.lean.d/Entry.lean) covers the empty-dimension returns and composes positive-dimension initialization with a loop continuation. Its [heap postconditions](83.py.lean.d/InitialState.lean) preserve caller objects, retain all six initial allocations, establish a typed and ordered singleton queue, and identify the distance and visited buffers with the Dijkstra array model.

The [queue coverage invariant](../ProjectEulerSolutions/Lib/LazyDijkstraQueue.lean) retains a current key for every finite unvisited estimate and bounds stale keys below by current distances. A minimum unvisited pop therefore has the current distance. [Concrete tuple coverage](83.py.lean.d/QueueInvariant.lean) preserves these properties through reordering, discarding visited entries, and pushing improvements; [initial coverage](83.py.lean.d/CoverageInitial.lean) establishes them for the singleton queue. The [combined runtime invariant](83.py.lean.d/RuntimeState.lean) connects the mutable matrix, distance and visited buffers, queue coverage, and mathematical shortest-path state. A [fresh iteration](83.py.lean.d/FreshIteration.lean) restores it after the complete Python body; [stale pops](83.py.lean.d/StaleIteration.lean) preserve it. The [loop proof](83.py.lean.d/Loop.lean) follows the actual control flow through to the goal return, proves the shortest-path result, and preserves unrelated heap objects. Its structural measure is five times the number of unvisited cells plus the queue length. Frontier coverage rules out an empty queue before the goal, and each continuing iteration strictly decreases the measure.
