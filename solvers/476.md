# Project Euler 476 Solution - Circle Packing II

<https://projecteuler.net/problem=476>:

* [476.py](476.py)

This repository contains a standalone Python solution (no external libraries) for **[Project Euler](https://ourbigbook.com/codex/project-euler) 476**.

## Key ideas

### 1) Geometry: the optimal 3-circle packing has only two cases
For a [triangle](https://ourbigbook.com/codex/triangle) with [angles](https://ourbigbook.com/codex/angle) ordered **A ≤ B ≤ C**:

- **[Circle](https://ourbigbook.com/codex/circle) 1** (largest) is always the **[incircle](https://ourbigbook.com/codex/incircle)** ([radius](https://ourbigbook.com/codex/radius) `r`).
- **[Circle](https://ourbigbook.com/codex/circle) 2** sits in the smallest corner **A**, tangent to the two sides and to the [incircle](https://ourbigbook.com/codex/incircle).
- **[Circle](https://ourbigbook.com/codex/circle) 3** is one of only two possibilities:
  1. **Corner B**: tangent to the [incircle](https://ourbigbook.com/codex/incircle) in the second-smallest corner.
  2. **Stack in corner A**: tangent to [circle](https://ourbigbook.com/codex/circle) 2 (another [circle](https://ourbigbook.com/codex/circle) in the same corner).

A simple inequality involving half-angles decides which option gives the maximum total [area](https://ourbigbook.com/codex/area):
- if `sin(A/2) ≥ tan(B/4)`, pick **corner B**
- otherwise, pick the **stack in corner A**

This collapses what looks like a continuous [optimization](https://ourbigbook.com/codex/optimization) problem into a fixed formula per [triangle](https://ourbigbook.com/codex/triangle).

### 2) Radii ratios from half-angles
If a [circle](https://ourbigbook.com/codex/circle) of [radius](https://ourbigbook.com/codex/radius) `q` is tangent to both sides of an [angle](https://ourbigbook.com/codex/angle) `θ`, its center lies on the [angle bisector](https://ourbigbook.com/codex/angle-bisector). Using this, the [radius](https://ourbigbook.com/codex/radius) ratio between the [incircle](https://ourbigbook.com/codex/incircle) (`r`) and the corner [circle](https://ourbigbook.com/codex/circle) in [angle](https://ourbigbook.com/codex/angle) `θ` is:

`q = r * (1 - sin(θ/2)) / (1 + sin(θ/2))`

So the [area](https://ourbigbook.com/codex/area) contribution uses only `r²` and `sin(θ/2)`.

### 3) Half-angle formulas from side lengths
With [semiperimeter](https://ourbigbook.com/codex/semiperimeter) `s = (a+b+c)/2`:

- `r² = ((s-a)(s-b)(s-c)) / s`
- `sin(A/2)² = (s-b)(s-c) / (bc)`
- `sin(B/2)² = (s-a)(s-c) / (ac)`

The “case switch” is implemented without computing `tan(B/4)` explicitly by using an equivalent inequality:

`sin(A/2) ≥ tan(B/4)  ⇔  sin(B/2) ≤ 2 sin(A/2) / (1 + sin(A/2)²)`

### 4) Enumeration trick: use `x = a+b-c`
The constraints are:

`1 ≤ a ≤ b ≤ c < a+b ≤ n`

Let:

`x = a+b-c`  (so `c = a+b-x` and `1 ≤ x ≤ a`)

This parameterization makes many repeated expressions simpler and avoids recomputing `c` bounds.

### 5) Performance: keep the numerical loop cache-friendly
The direct formula only needs two [square roots](https://ourbigbook.com/codex/square-root) per [triangle](https://ourbigbook.com/codex/triangle).  A previous version
precomputed `sqrt(i)` and `1/sqrt(i)` tables, but at `n=1803` those tables are
large enough that the scattered lookups cost more than the `sqrt` calls they
replace.  The current solver follows the constant-memory formulation: compute
the two half-angle [sines](https://ourbigbook.com/codex/sine) directly, add the dimensionless [area](https://ourbigbook.com/codex/area) factor, and
multiply by `π` once after the [summation](https://ourbigbook.com/codex/summation).
