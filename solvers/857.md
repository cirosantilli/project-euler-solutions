# Project Euler 857 Solution - Beautiful Graphs

<https://projecteuler.net/problem=857>:

* [857.py](857.py)

This repository contains a standalone Python solution (`main.py`) that prints `G(10^7)` [modulo](https://ourbigbook.com/codex/modulo-operation) `10^9+7`.

## Main techniques used

### 1) Structural reduction to an ordered partition

Call an [graph edge](https://ourbigbook.com/codex/graph-edge) **undirected** if it is green or brown, and a **directed-pair** if it is red/blue (one direction red, the opposite direction blue).

Define a relation on [graph vertices](https://ourbigbook.com/codex/graph-vertex):

- `u ~ v` iff the [graph edge](https://ourbigbook.com/codex/graph-edge) `{u,v}` is undirected.

The “every [directed cycle](https://ourbigbook.com/codex/directed-cycle) contains red iff it contains blue” rule implies:

- If `u ~ v` and `v ~ w`, then `{u,w}` cannot be a directed-pair: otherwise you can go along the red direction of `{u,w}` and return from `w` to `u` using undirected [graph edges](https://ourbigbook.com/codex/graph-edge), producing a [directed cycle](https://ourbigbook.com/codex/directed-cycle) that has red but no blue.

So `~` is transitive and therefore an **[equivalence relation](https://ourbigbook.com/codex/equivalence-relation)**. The [graph vertices](https://ourbigbook.com/codex/graph-vertex) split into blocks ([equivalence classes](https://ourbigbook.com/codex/equivalence-class)) where:

- **inside a block**: every [graph edge](https://ourbigbook.com/codex/graph-edge) is undirected (green/brown)
- **between two different blocks**: every [graph edge](https://ourbigbook.com/codex/graph-edge) must be a directed-pair

Next, between two blocks `A` and `B`, all directed-pair [graph edges](https://ourbigbook.com/codex/graph-edge) must share the same red direction. If not, you can pick `a1,a2 ∈ A` and `b ∈ B` with conflicting red directions and form a [directed cycle](https://ourbigbook.com/codex/directed-cycle) using two red steps and one undirected step inside `A`.

Thus each block-to-block relation is oriented one way, giving a [tournament](https://ourbigbook.com/codex/tournament) on blocks. The same cycle rule forbids a [directed cycle](https://ourbigbook.com/codex/directed-cycle) of red [graph edges](https://ourbigbook.com/codex/graph-edge) among blocks, so the [tournament](https://ourbigbook.com/codex/tournament) is **acyclic**, hence **transitive**, hence the blocks are **totally ordered**.

In short: every beautiful [graph](https://ourbigbook.com/codex/graph) corresponds to an **[ordered set partition](https://ourbigbook.com/codex/ordered-set-partition)** of the [graph vertices](https://ourbigbook.com/codex/graph-vertex) into blocks.

### 2) Ramsey restriction inside blocks

Inside a block, every [graph edge](https://ourbigbook.com/codex/graph-edge) is either green or brown. The second condition (“no all-green or all-brown [triangle](https://ourbigbook.com/codex/triangle)”) means the 2-colouring of the [complete graph](https://ourbigbook.com/codex/complete-graph) on that block has **no monochromatic [triangle](https://ourbigbook.com/codex/triangle)**.

By the classic Ramsey fact `R(3,3)=6`, such a colouring can exist only for block sizes `≤ 5`. Therefore every [ordered set partition](https://ourbigbook.com/codex/ordered-set-partition) uses parts of size at most 5.

For each block size `s ∈ {1,2,3,4,5}`, the solution precomputes `a_s`, the number of valid green/brown colourings of `K_s`, by brute force (at most `2^10 = 1024` colourings).

### 3) Counting via a constant-coefficient recurrence

For an [ordered set partition](https://ourbigbook.com/codex/ordered-set-partition) with block sizes `(s1, s2, ..., sk)`:

- choose which labels go into each block (a multinomial factor)
- multiply by the independent internal counts `a_{si}`
- all [graph edges](https://ourbigbook.com/codex/graph-edge) between blocks are forced by the block order

This yields a simple [recurrence relation](https://ourbigbook.com/codex/recurrence-relation):

- `G(0) = 1`
- `G(n) = Σ_{s=1..5} C(n,s) * a_s * G(n-s)`

For large `n` [modulo](https://ourbigbook.com/codex/modulo-operation) a [prime](https://ourbigbook.com/codex/prime), we convert to a constant-coefficient [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) by dividing by `n!`:

- Let `f_n = G(n) / n!`.
- Then `f_n = Σ_{s=1..5} (a_s / s!) * f_{n-s}`.

Now `f_n` is computed in `O(n)` time using only the last five values (rolling window), while `n! mod MOD` is accumulated in the same loop.

## Complexity

- Precomputation of `a_s`: negligible (≤ 1024 cases).
- Main loop for `n = 10^7`: `O(n)` [arithmetic operations](https://ourbigbook.com/codex/arithmetic-operation).
- Memory: `O(1)` beyond a handful of [integers](https://ourbigbook.com/codex/integer).
