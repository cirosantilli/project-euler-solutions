# Project Euler 858 Solution - LCM

<https://projecteuler.net/problem=858>:

* [858.py](858.py)

We define:

\[
G(N) = \sum_{S \subseteq \{1,\dots,N\}} \mathrm{lcm}(S),
\qquad \mathrm{lcm}(\emptyset)=1
\]

The task is to compute \(G(800) \bmod (10^9+7)\).

---

## Key ideas

### 1) Totient expansion of an integer
A classic identity:

\[
n = \sum_{d \mid n} \varphi(d)
\]

Applying to the subset [LCM](https://ourbigbook.com/codex/least-common-multiple):

\[
\mathrm{lcm}(S) = \sum_{d \mid \mathrm{lcm}(S)} \varphi(d)
\]

Summing over all subsets and swapping sums gives:

\[
G(N) = \sum_{d \mid L} \varphi(d)\cdot \#\{S : d \mid \mathrm{lcm}(S)\}
\]

where \(L = \mathrm{lcm}(1,\dots,N)\).

---

### 2) Inclusion–exclusion on “missing prime-power requirements”
For a fixed [divisor](https://ourbigbook.com/codex/divisor) \(d\), let its prime-power form be:

\[
d = \prod p^{a_p}
\]

Then \(d \mid \mathrm{lcm}(S)\) means:

> For each [prime](https://ourbigbook.com/codex/prime) \(p\) with exponent \(a_p\), the subset contains **at least one**
> number divisible by \(p^{a_p}\).

Counting subsets satisfying “hit every required multiples-set” is done by [inclusion–exclusion](https://ourbigbook.com/codex/inclusion-exclusion-principle)
over which [prime](https://ourbigbook.com/codex/prime) requirements are *missed*.

After regrouping, the problem reduces to summing over sets \(Q\) of **one [prime power](https://ourbigbook.com/codex/prime-power) per [prime](https://ourbigbook.com/codex/prime)**
(e.g. \(Q=\{2^4, 3^1, 11^1\}\)):

\[
G(N) = L \sum_Q (-1)^{|Q|} \cdot 2^{N - F(Q)} \cdot \prod_{p^r \in Q}\frac{\varphi(p^r)}{p^{e_p}}
\]

where:

- \(F(Q)\) is the count of [integers](https://ourbigbook.com/codex/integer) in \([1..N]\) divisible by at least one element of \(Q\)
- \(e_p\) is the maximum exponent of \(p\) in \(L\)

---

### 3) Prime split: small vs large primes
If \(p > \sqrt{N}\), then:

- \(p^2 > N\), so \(e_p = 1\)
- No number \(\le N\) can be divisible by **two** such [primes](https://ourbigbook.com/codex/prime) (product would exceed \(N\))

This makes large [primes](https://ourbigbook.com/codex/prime) essentially independent, once we know which **small multipliers**
are already “covered” by chosen small [prime powers](https://ourbigbook.com/codex/prime-power).

So we:

- brute-force all exponent choices for [primes](https://ourbigbook.com/codex/prime) \(p \le \sqrt{N}\) (few [combinations](https://ourbigbook.com/codex/combination-combinatorics))
- for each choice, compute coverage with a [bitmask](https://ourbigbook.com/codex/bit-mask)
- fold in the large [primes](https://ourbigbook.com/codex/prime) via a product of independent factors

---

### 4) Bitmask coverage + memoisation
Coverage sets are represented as Python [integers](https://ourbigbook.com/codex/integer) ([bitsets](https://ourbigbook.com/codex/bitset)):

- one mask for numbers \(1..N\)
- one smaller mask for multipliers \(1..K_{\max}\) needed to evaluate large [primes](https://ourbigbook.com/codex/prime)

The expensive “large [prime](https://ourbigbook.com/codex/prime) product” depends only on the multiplier-mask, so it is memoised.
This yields a fast runtime.

---

## Complexity
Let \(P_s\) be [primes](https://ourbigbook.com/codex/prime) \(\le \sqrt{N}\).
We enumerate \(\prod_{p \in P_s} (e_p+1)\) [combinations](https://ourbigbook.com/codex/combination-combinatorics) — for \(N=800\), this is only **34,020**.

Each [combination](https://ourbigbook.com/codex/combination-combinatorics) is processed with O(#large [primes](https://ourbigbook.com/codex/prime)) arithmetic,
but memoisation reduces this dramatically in practice.
