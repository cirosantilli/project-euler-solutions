## Game model

A position is a [multiset](https://ourbigbook.com/codex/multiset) of [integer](https://ourbigbook.com/codex/integer) [rectangles](https://ourbigbook.com/codex/rectangle).  
A move chooses one [rectangle](https://ourbigbook.com/codex/rectangle) of size `w×h` and makes **one vertical** and **one horizontal** cut, producing four smaller [rectangles](https://ourbigbook.com/codex/rectangle).  
[Normal play](https://ourbigbook.com/codex/normal-play): a player who cannot move loses.

This is an [impartial game](https://ourbigbook.com/codex/impartial-game), so **[Sprague-Grundy theory](https://ourbigbook.com/codex/sprague-grundy-theory)** applies.

---

## 1) Sprague–Grundy numbers (nimbers)

Let `G(w,h)` be the [nimber](https://ourbigbook.com/codex/nimber) of a single `w×h` [rectangle](https://ourbigbook.com/codex/rectangle) (order doesn’t matter; `G(w,h)=G(h,w)`).

A move splitting at `(x,y)` (with `1≤x<w`, `1≤y<h`) produces [rectangles](https://ourbigbook.com/codex/rectangle):

- `x×y`
- `(w-x)×y`
- `x×(h-y)`
- `(w-x)×(h-y)`

The resulting game is the XOR-sum of those [rectangles](https://ourbigbook.com/codex/rectangle), so the move’s [nimber](https://ourbigbook.com/codex/nimber) is:

G(x,y) [xor](https://ourbigbook.com/codex/xor) G(w-x,y) [xor](https://ourbigbook.com/codex/xor) G(x,h-y) [xor](https://ourbigbook.com/codex/xor) G(w-x,h-y)

## 2) Why nimbers become constant for fixed width

For fixed width `w`, the [sequence](https://ourbigbook.com/codex/sequence) `G(w,1), G(w,2), ...` eventually becomes constant.

Intuition: when the height is very large, every possible horizontal cut leaves at least one side “large enough” that all smaller-width [rectangles](https://ourbigbook.com/codex/rectangle) in that side have already reached their stabilized [nimber](https://ourbigbook.com/codex/nimber) values. This makes the *set of reachable move [nimbers](https://ourbigbook.com/codex/grundy-number)* stop changing, so the `mex` stops changing too.

### Practical certification lemma

A useful rigorous check is:

> If `G(w,h)` is constant for all `h` in the interval `[s, 2s]`, then it stays constant for all `h ≥ s`.

Reason (sketch): when `h > 2s`, any horizontal split `(b, h-b)` has `max(b, h-b) ≥ s`, and for the smaller [rectangles](https://ourbigbook.com/codex/rectangle) created by the move, [nimbers](https://ourbigbook.com/codex/grundy-number) match the already-stabilized values. So the set of reachable [nimbers](https://ourbigbook.com/codex/grundy-number) is the same as at height `2s`, therefore `mex` is identical.

The code finds the last index `s` where a change occurs, and extends the computed range until it can verify constancy over `[s, 2s]`. The constant value is stored as `const[w]`.

## 3) Counting `D(W,H)` without summing `C(w,h)` directly

A **first move** from a `w×h` [rectangle](https://ourbigbook.com/codex/rectangle) is uniquely described by [positive integers](https://ourbigbook.com/codex/positive-integer):

- `i` and `j` with `i+j = w` (left/right widths)
- `k` and `l` with `k+l = h` (top/bottom heights)

So summing all winning moves over all [rectangles](https://ourbigbook.com/codex/rectangle) `w≤W`, `h≤H` is equivalent to counting **all quadruples**:

i,j,k,l ≥ 1
i+j ≤ W
k+l ≤ H

Then for that `(i,j)`, we need the number of ordered `(k,l)` with `k+l≤H` and `t(k)=t(l)`.

Because `G(i,x)` becomes constant for large `x`, `t(x)` also becomes constant beyond a small threshold. This allows `k,l` counting to be done with:
- a histogram on the short “prefix” part, plus
- closed-form formulas for the large “tail” [triangle](https://ourbigbook.com/codex/triangle).

This turns the huge `H=1,234,567` into a computation that mainly depends on the much smaller stabilization thresholds.

## 4) Complexity notes

- The [Grundy number](https://ourbigbook.com/codex/grundy-number) table is computed only up to the heights needed to prove stabilization per width.
- Final `D(W,H)` is computed using per-width-pair histograms over the short prefix (typically a few thousand terms) and O(1) tail formulas.

No external libraries are required, and the program uses a single CPU core.
