# Project Euler 529 Solution - $10$-substrings

<https://projecteuler.net/problem=529>:

* [529.py](529.py)

## Key ideas

- Work with zero-free strings (digits 1–9) first. Any friendly string stays friendly after inserting zeros because zeros do not change sums. This gives a [binomial transform](https://ourbigbook.com/codex/binomial-transform) from zero-free counts to all-length counts.
- For zero-free strings, only the **maximal suffix with sum <= 10** can still participate in a future 10-substring. Older digits must already be covered or the string is invalid.
- Track a [DFA](https://ourbigbook.com/codex/deterministic-finite-automaton) state as:
  - the digits of that maximal suffix (sum <= 10), and
  - how many trailing digits are still uncovered (these always form a suffix).
- Transitions append a digit, drop covered digits while the sum exceeds 10, and mark all digits covered when the [suffix sum](https://ourbigbook.com/codex/suffix-sum) reaches 10.
- The zero-free count [sequence](https://ourbigbook.com/codex/sequence) has a [linear recurrence](https://ourbigbook.com/codex/linear-recurrence) of degree at most the [DFA](https://ourbigbook.com/codex/deterministic-finite-automaton) size. Use [Berlekamp-Massey algorithm](https://ourbigbook.com/codex/berlekamp-massey-algorithm) to recover the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation), then evaluate the [binomial transform](https://ourbigbook.com/codex/binomial-transform) at `n = 10^18` via [polynomial](https://ourbigbook.com/codex/polynomial) [exponentiation](https://ourbigbook.com/codex/exponentiation) in the [quotient ring](https://ourbigbook.com/codex/quotient-ring).

## Complexity notes

- The [DFA](https://ourbigbook.com/codex/deterministic-finite-automaton) has only a few thousand states, so generating the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) terms is fast.
- [Polynomial](https://ourbigbook.com/codex/polynomial) [exponentiation](https://ourbigbook.com/codex/exponentiation) and [convolution](https://ourbigbook.com/codex/convolution) are done with packed big [integers](https://ourbigbook.com/codex/integer) to keep it efficient in Python.
