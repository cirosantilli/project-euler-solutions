# Project Euler 373 Solution - Circumscribed Circles

<https://projecteuler.net/problem=373>:

* [373.py](373.py)

This repo contains a pure-Python solution (no external libraries) for **Project Euler 373**.

## Core idea

Let `N(r)` be the number of integer-sided [triangles](https://ourbigbook.com/codex/triangle) whose **[circumradius](https://ourbigbook.com/codex/circumradius)** is exactly `r`.
Then the asked value is

\[
S(n) = \sum_{r=1}^{n} r\,N(r).
\]

So the problem becomes: **given a [radius](https://ourbigbook.com/codex/radius) `r`, how many integer-sided [triangles](https://ourbigbook.com/codex/triangle) have [circumradius](https://ourbigbook.com/codex/circumradius) `r`?**

## Number theory reduction

A key observation is that [integer](https://ourbigbook.com/codex/integer) chords in a [circle](https://ourbigbook.com/codex/circle) of [radius](https://ourbigbook.com/codex/radius) `r` correspond to **[integer](https://ourbigbook.com/codex/integer) [right triangles](https://ourbigbook.com/codex/right-triangle) with hypotenuse `r`** (via half-chords / perpendiculars). Counting valid [triangles](https://ourbigbook.com/codex/triangle) for a fixed `r` can be reduced to counting suitable combinations of these chords.

This is governed by the classical theorem on representations of an [integer](https://ourbigbook.com/codex/integer) as a **[sum of two squares](https://ourbigbook.com/codex/sum-of-two-squares)**:

- Only [primes](https://ourbigbook.com/codex/prime) `p ≡ 1 (mod 4)` “split” in the [Gaussian integers](https://ourbigbook.com/codex/gaussian-integer) and create non-trivial representations.
- [Primes](https://ourbigbook.com/codex/prime) `p ≡ 3 (mod 4)` and the [prime](https://ourbigbook.com/codex/prime) `2` do not increase the variety in the same way (their contributions are “neutral” for this count).

If

\[
r = \prod p_i^{e_i} \cdot q
\]

where the `p_i` are exactly the [primes](https://ourbigbook.com/codex/prime) with `p_i ≡ 1 (mod 4)` and `e_i` are their [exponents](https://ourbigbook.com/codex/exponent) in `r`, then the number of [integer](https://ourbigbook.com/codex/integer) [triangles](https://ourbigbook.com/codex/triangle) with [circumradius](https://ourbigbook.com/codex/circumradius) `r` is:

\[
N(r)=\frac{1}{6}\left(2\prod(3e_i^2+3e_i+1)-3\prod(2e_i+1)+3\prod(2\lfloor e_i/2\rfloor+1)-2\right).
\]

([Empty products](https://ourbigbook.com/codex/empty-product) are `1`.)

Finally:

\[
S(n)=\sum_{r=1}^{n} r\,N(r).
\]

## Implementation techniques

- **[Linear sieve](https://ourbigbook.com/codex/linear-sieve) for [smallest prime factors](https://ourbigbook.com/codex/smallest-prime-factor) ([SPF](https://ourbigbook.com/codex/smallest-prime-factor)):** builds `spf[x]` for all `x ≤ n` in `O(n)` time.
- **Fast per-integer factorization:** each `r` is factorized by repeatedly dividing by `spf[r]`, extracting [exponents](https://ourbigbook.com/codex/exponent) `e_i`.
- **Only [primes](https://ourbigbook.com/codex/prime) `≡ 1 (mod 4)` matter:** during factorization we multiply three small product terms only for those [primes](https://ourbigbook.com/codex/prime).
- **Low memory:** `spf` is stored as an `array('I')` (4 bytes per entry), ~40 MB for `n = 10^7`.

## Correctness checks

The code includes the problem statement checks:

- `S(100) = 4950`
- `S(1200) = 1653605`

and prints `S(10^7)` when run without arguments.
