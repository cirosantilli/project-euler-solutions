# Project Euler 681 Solution - Maximal Area

<https://projecteuler.net/problem=681>:

* [681.py](681.py)

This solution avoids brute-force enumeration of side lengths by transforming the [geometry](https://ourbigbook.com/codex/geometry) problem into a constrained [integer](https://ourbigbook.com/codex/integer) [integer factorization](https://ourbigbook.com/codex/integer-factorization) problem.

---

## 1) Key Geometry Insight (Brahmagupta)

The maximum area of a [quadrilateral](https://ourbigbook.com/codex/quadrilateral) with sides `a,b,c,d` occurs when it is **cyclic**.
For [cyclic quadrilaterals](https://ourbigbook.com/codex/cyclic-quadrilateral):

\[
A^2 = (s-a)(s-b)(s-c)(s-d)
\]

where:

\[
s = \frac{a+b+c+d}{2}
\]

Define:

- `U = s-a`
- `V = s-b`
- `W = s-c`
- `T = s-d`

Then:

\[
A = \sqrt{U V W T}
\]

---

## 2) Ordering Trick

If `a ≤ b ≤ c ≤ d`, then:

\[
U ≥ V ≥ W ≥ T
\]

Also the perimeter is:

\[
a+b+c+d = 2s = U+V+W+T
\]

So instead of summing over side quadruples, we sum over `(U,V,W,T)`.

---

## 3) Integer Area Condition

We require the maximal area `A` to be an [integer](https://ourbigbook.com/codex/integer) ≤ `n`.

That means:

\[
U V W T = k^2
\]

for some [integer](https://ourbigbook.com/codex/integer) `k ≤ n`.

So the problem becomes:

- For each `k = 1..n`
- Find all `U≥V≥W≥T≥1` with `U·V·W·T = k²`
- Require `U < V+W+T` (positivity of smallest side)
- Require `U+V+W+T` even (ensures sides are [integers](https://ourbigbook.com/codex/integer))
- Sum perimeter `U+V+W+T`

---

## 4) Efficient Enumeration Strategy

For fixed `k`, we enumerate **[divisors](https://ourbigbook.com/codex/divisor) of `k²` that are ≤ k**, since:

- `V ≤ k` must hold (otherwise `U < V`).
- Hence also `W,T ≤ k`.

We choose `T`, then `W`, then `V`, and compute:

\[
U = \frac{k^2}{T W V}
\]

Then we check ordering, [integer parity](https://ourbigbook.com/codex/integer-parity), and the inequality `U < V+W+T`.

The [divisor](https://ourbigbook.com/codex/divisor) list is sorted, so the scan can also stop entire suffixes early:

- If `T^4 > k²`, then even `T,T,T,T` is already too large.
- For fixed `T`, if `W^3 > k²/T`, then no `W,V,U` with `W≤V≤U` can fit.
- After choosing a divisible `W`, if `sqrt(k²/(TW)) < W`, all later `W` values fail the ordering too.

---

## 5) Pruning via a Quadratic Bound

The condition:

\[
U = \frac{k^2}{T W V} < V + W + T
\]

can be rearranged to a [quadratic inequality](https://ourbigbook.com/codex/quadratic-inequality) in `V`, yielding a **tight [lower bound](https://ourbigbook.com/codex/lower-bound)** for feasible `V`.
That massively reduces the number of [divisor](https://ourbigbook.com/codex/divisor) checks per `k`.

---

## 6) Complexity Notes

- [Prime factorization](https://ourbigbook.com/codex/prime-factorization) for all `k ≤ n` is done via a smallest-prime-factor [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve).
- [Divisor](https://ourbigbook.com/codex/divisor) generation per `k` is small because the [divisor](https://ourbigbook.com/codex/divisor) list is restricted to `≤ k`.
- Strong pruning keeps the search practical.
