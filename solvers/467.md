# Project Euler 467 Solution - Superinteger

<https://projecteuler.net/problem=467>:

* [467.py](467.py)

This solution computes:

- `P^D`: the [digital roots](https://ourbigbook.com/codex/digital-root) of the [prime numbers](https://ourbigbook.com/codex/prime-number)
- `C^D`: the [digital roots](https://ourbigbook.com/codex/digital-root) of the [composite numbers](https://ourbigbook.com/codex/composite-number)
- `P_n`, `C_n`: the first `n` [digits](https://ourbigbook.com/codex/numerical-digit) of those [sequences](https://ourbigbook.com/codex/sequence)
- `f(n)`: the **smallest [positive integer](https://ourbigbook.com/codex/positive-integer)** whose [digits](https://ourbigbook.com/codex/numerical-digit) contain both `P_n` and `C_n` as subsequences

The required output is `f(10_000) mod 1_000_000_007`.

## Key idea: smallest common superinteger = lexicographically smallest shortest common supersequence

Treat `P_n` and `C_n` as two strings (here: [digit](https://ourbigbook.com/codex/numerical-digit) [sequences](https://ourbigbook.com/codex/sequence) in `1..9`).

A number `s` is a *common superinteger* iff it is a **[common supersequence](https://ourbigbook.com/codex/common-supersequence)** of both strings.
Among all such `s`, the **smallest [integer](https://ourbigbook.com/codex/integer)** is obtained by:

1. minimizing the length (any shorter [digit](https://ourbigbook.com/codex/numerical-digit) string is always a smaller [positive integer](https://ourbigbook.com/codex/positive-integer)),
2. among equal lengths, taking the **lexicographically smallest** [digit](https://ourbigbook.com/codex/numerical-digit) string.

That is exactly the **lexicographically smallest [shortest common supersequence](https://ourbigbook.com/codex/shortest-common-supersequence) ([SCS](https://ourbigbook.com/codex/shortest-common-supersequence))** problem.

Also, for strings `A`, `B`:

- `|SCS(A,B)| = |A| + |B| - |LCS(A,B)|`

So optimal choices can be guided by **[LCS](https://ourbigbook.com/codex/longest-common-subsequence) lengths** of suffixes.

## Fast LCS lengths with bit-parallel DP

A standard bit-vector ([bit-parallel](https://ourbigbook.com/codex/bit-parallelism)) [LCS](https://ourbigbook.com/codex/longest-common-subsequence)-length [algorithm](https://ourbigbook.com/codex/algorithm) keeps a [bitset](https://ourbigbook.com/codex/bitset) `D` and updates it per character:

- Precompute `matches[d]`: bit `i` is 1 iff `X[i] == d`.
- For each character `ch` of `Y`:

```
U = D | matches[ch]
V = (U - ((D << 1) | 1)) mod 2^n
D = U & ~V
```

After processing a prefix of `Y`, `popcount(D)` equals the [LCS](https://ourbigbook.com/codex/longest-common-subsequence) length against the full `X`.

### Turning suffix queries into prefix queries

The greedy [SCS](https://ourbigbook.com/codex/shortest-common-supersequence) reconstruction needs [LCS](https://ourbigbook.com/codex/longest-common-subsequence) lengths of many suffix pairs `LCS(A[i:], B[j:])`.

Reverse both strings:

- `X = reverse(A)`
- `Y = reverse(B)`

Then:

- `LCS(A[i:], B[j:]) == LCS(X[:n-i], Y[:n-j])`

So we store the [DP](https://ourbigbook.com/codex/dynamic-programming) [bitset](https://ourbigbook.com/codex/bitset) `D` after every prefix of `Y` (an array `rows[b]`).
A prefix-length query is answered by counting set bits in a masked prefix:

- `LCS(X[:a], Y[:b]) = popcount(rows[b] & ((1<<a)-1))`

This makes each [LCS](https://ourbigbook.com/codex/longest-common-subsequence) query **very fast**.

## Greedy construction of the smallest shortest SCS

Let `L(i,j) = LCS(A[i:], B[j:])`. For `A[i] != B[j]`:

- `L(i,j) = max(L(i+1,j), L(i,j+1))`

To keep the [SCS](https://ourbigbook.com/codex/shortest-common-supersequence) as short as possible we choose the branch that keeps the [LCS](https://ourbigbook.com/codex/longest-common-subsequence) maximal:

- if `L(i+1,j) > L(i,j+1)` → take `A[i]`
- if `L(i+1,j) < L(i,j+1)` → take `B[j]`
- if equal → both lengths are optimal, so take the **smaller next [digit](https://ourbigbook.com/codex/numerical-digit)** for [lexicographic](https://ourbigbook.com/codex/lexicographic-order) minimality

If `A[i] == B[j]`, we always take that [digit](https://ourbigbook.com/codex/numerical-digit) and advance both pointers.

While constructing the [digit](https://ourbigbook.com/codex/numerical-digit) string, we update the [modulo](https://ourbigbook.com/codex/modulo-operation) value incrementally:

- `value = (value * 10 + digit) mod M`

## Complexity

For `n = 10_000`:

- Sieve to generate [primes](https://ourbigbook.com/codex/prime) and [composites](https://ourbigbook.com/codex/composite-number): well under a second in Python.
- [Bit-parallel](https://ourbigbook.com/codex/bit-parallelism) [LCS](https://ourbigbook.com/codex/longest-common-subsequence) [DP](https://ourbigbook.com/codex/dynamic-programming): `O(n^2 / word_size)` big-int operations; very fast in practice.
- Greedy [SCS](https://ourbigbook.com/codex/shortest-common-supersequence) reconstruction: `O(|SCS|)` [LCS](https://ourbigbook.com/codex/longest-common-subsequence) queries (≈ up to 20,000), each using a couple of big-int ops.

Memory:

- `rows`: ~10,001 Python [integers](https://ourbigbook.com/codex/integer) holding 10,000-bit [bitsets](https://ourbigbook.com/codex/bitset).
- a small list of prefix masks.
