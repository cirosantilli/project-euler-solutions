# Project Euler 88 Solution - Product-sum Numbers

<https://projecteuler.net/problem=88>:

* [88.py](88.py)
* [88.py.lean](88.py.lean)
* [88.lean](88.lean)

A number `N` is a [product-sum number](https://ourbigbook.com/codex/product-sum-number) for a [multiset](https://ourbigbook.com/codex/multiset) of `k` [natural numbers](https://ourbigbook.com/codex/natural-number) if:
`N = sum(a_i) = product(a_i)`.

Key trick:
- Enumerate only factors `>= 2` (ignore `1`s during search).
- For any factor [multiset](https://ourbigbook.com/codex/multiset) with:
  - [product](https://ourbigbook.com/codex/product) `P`
  - [sum](https://ourbigbook.com/codex/sum) `S`
  - number of factors `t`
- We can add exactly `(P - S)` ones to make the total [sum](https://ourbigbook.com/codex/sum) equal to `P` without changing the [product](https://ourbigbook.com/codex/product).
- That yields an effective [set](https://ourbigbook.com/codex/set) size:
  `k = t + (P - S)`.

So, for each factor [multiset](https://ourbigbook.com/codex/multiset) we compute `k` and update the minimal `P` for that `k`.

### Enumeration
We perform a [DFS](https://ourbigbook.com/codex/depth-first-search) generating factor [multisets](https://ourbigbook.com/codex/multiset) in nondecreasing order to avoid duplicates.
We also use a known safe [upper bound](https://ourbigbook.com/codex/upper-bound): minimal [product-sum numbers](https://ourbigbook.com/codex/product-sum-number) for `k <= K` are `<= 2K`,
so we only explore [products](https://ourbigbook.com/codex/product) up to `2K`.

For each `k >= 2`, the factors `2` and `k`, together with `k-2` ones, have both sum and product `2k`. This witnesses the upper bound. The initial sentinel is `2K + 1`, so it exceeds every possible minimum without imposing a fixed numeric ceiling.

### Result
After filling the minimal value for each `k` in `[2..K]`, we take the [set](https://ourbigbook.com/codex/set) of these minimal values
(duplicates removed) and [sum](https://ourbigbook.com/codex/sum) them.

The code includes asserts for the examples:
- `K=6  -> 30`
- `K=12 -> 61`

Finally it prints the answer for `K=12000`.

### Formalization

[ProductSumNumbers.lean](../ProjectEulerSolutions/Lib/ProductSumNumbers.lean) proves that removing ones preserves every positive product-sum representation, and that padding the remaining factors with ones recovers it. It also proves the `2k` witness and monotonicity of the effective size when a factor is appended.

The [total search model](../ProjectEulerSolutions/Lib/ProductSumSearch.lean) uses the strictly increasing product to prove termination. Its [soundness and completeness proof](../ProjectEulerSolutions/Lib/ProductSumSearchCorrect.lean) covers the nondecreasing factor order and size pruning. [ProductSumMinima.lean](../ProjectEulerSolutions/Lib/ProductSumMinima.lean) proves that each selected value is the least product-sum number for its size, and that increasing `k_max` does not change previously covered minima. [ProductSumTable.lean](../ProjectEulerSolutions/Lib/ProductSumTable.lean) connects guarded table updates to those minima.

The [reference source proof](../data/project-euler-statements/data/py/project_euler_statements/p88.py.lean.d/Search.lean) verifies the complete recursive DFS, including its while loop, pruning, guarded writes, and return of the shared table. Its [setup proof](../data/project-euler-statements/data/py/project_euler_statements/p88.py.lean.d/Preparation.lean) follows sentinel-table allocation and the initial DFS call, producing the exact mathematical minima table. Recursive descent uses the remaining product range; each local loop uses the remaining factor range. Neither measure is a runtime cutoff.

The [complete optimized source proof](88.py.lean) establishes termination and the exact answer for every integer `k_max`. It follows capture-cell allocation, the entire recursive search, the table slice, set construction, and summation under every possible set-iteration order. Each minimum is at most `2*k_max`, so the sentinel is absent from the final slice and needs no filtering. [ProductSumDistinct.lean](../ProjectEulerSolutions/Lib/ProductSumDistinct.lean) proves these facts about the observed table suffix.

The reference's final Boolean-array deduplication and the public equivalence theorem remain unfinished. The older standalone Lean solver is not used by these source proofs.
