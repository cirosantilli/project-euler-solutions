# Project Euler 459 Solution - Flipping Game

<https://projecteuler.net/problem=459>:

* [459.py](459.py)

This repository contains a **pure-Python** solution (no external libraries) for [Project Euler](https://ourbigbook.com/codex/project-euler) 459.

## Key techniques

### 1) Sprague–Grundy theory
The game is an impartial normal-play game (no legal moves = lose). Therefore every position has a **[nimber](https://ourbigbook.com/codex/nimber)** ([Sprague–Grundy value](https://ourbigbook.com/codex/nimber)), and:

- A position is losing iff its [nimber](https://ourbigbook.com/codex/nimber) is `0`.
- A move is winning iff it moves to a position with [nimber](https://ourbigbook.com/codex/nimber) `0`.

### 2) Tartan theorem → reduce the 2D game to two 1D games
The rectangle-flipping rules make this a *tartan game*. Pearson’s “tartan theorem” implies that the [nimber](https://ourbigbook.com/codex/nimber) of a board position factors as a **[nim-product](https://ourbigbook.com/codex/nimber-multiplication)** of two 1D coin-turning games:

- one 1D game where legal strip lengths are **[perfect squares](https://ourbigbook.com/codex/perfect-square)** (width),
- one 1D game where legal strip lengths are **[triangular numbers](https://ourbigbook.com/codex/triangular-number)** (height).

This turns a 2D analysis into two 1D analyses plus nimber arithmetic.

### 3) Prefix-xor recurrence for the 1D coin-turning games
Let `C[k]` be the XOR-prefix of 1D [nimbers](https://ourbigbook.com/codex/nimber) (so the [nimber](https://ourbigbook.com/codex/nimber) of a contiguous strip `[a..b]` is `C[b] XOR C[a-1]`).

Pearson shows an efficient [recurrence relation](https://ourbigbook.com/codex/recurrence-relation):

- `C[k+1] = mex({ C[k] XOR C[k - L] : L in allowed_lengths })`

From `C`, the [nimber](https://ourbigbook.com/codex/nimber) of any allowed strip ending at `x` is simply:

- `strip = C[x] XOR C[x - L]`

### 4) Counting via frequency tables
A first move flips a [rectangle](https://ourbigbook.com/codex/rectangle), whose [nimber](https://ourbigbook.com/codex/nimber) is:

- `rect = strip_width ⊗ strip_height`

The first player has a winning move iff the rectangle’s [nimber](https://ourbigbook.com/codex/nimber) equals the [nimber](https://ourbigbook.com/codex/nimber) of the full board.

So we build two frequency tables:

- `freq_sq[v]` = how many square-length strips have [nimber](https://ourbigbook.com/codex/nimber) `v`,
- `freq_tr[v]` = how many triangular-length strips have [nimber](https://ourbigbook.com/codex/nimber) `v`.

Then the number of winning first moves is the number of pairs `(a,b)` with:

- `a ⊗ b = board_nimber`

### 5) Fast nimber multiplication and inversion
[Nimber multiplication](https://ourbigbook.com/codex/nimber-multiplication) is done with a recursive **Fermat 2-power splitting** [algorithm](https://ourbigbook.com/codex/algorithm) (a Karatsuba-style [recurrence relation](https://ourbigbook.com/codex/recurrence-relation)), based on facts for `F_n = 2^(2^n)`.

To “divide” by a [nimber](https://ourbigbook.com/codex/nimber) we use inverses. For this problem, all strip [nimbers](https://ourbigbook.com/codex/nimber) are `< 2^16`, so inverses can be computed in the [finite field](https://ourbigbook.com/codex/finite-field) of size `2^16` by [exponentiation](https://ourbigbook.com/codex/exponentiation):

- `a^{-1} = a^(2^16 - 2) = a^65534`

This avoids slow brute-force inversion.
