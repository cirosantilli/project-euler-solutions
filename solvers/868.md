# Project Euler 868 Solution - Belfry Maths

<https://projecteuler.net/problem=868>:

* [868.py](868.py)

This solution computes how many **adjacent swaps** are performed by the bell-ringers' [permutation](https://ourbigbook.com/codex/permutation) method before a given target ordering appears.

## Key idea

The described rule generates [permutations](https://ourbigbook.com/codex/permutation) in the **[Steinhaus-Johnson-Trotter](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm) ([SJT](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm))** (also called **[plain changes](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm)**) order:

- Start from the letters sorted alphabetically.
- Each step performs **one [adjacent transposition](https://ourbigbook.com/codex/adjacent-transposition)**.
- Therefore, the number of swaps needed to *reach* a target [permutation](https://ourbigbook.com/codex/permutation) equals its **0-based index** in this [SJT](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm) listing.

## Direct ranking (no simulation)

Simulating the process would require visiting `n!` [permutations](https://ourbigbook.com/codex/permutation), which is infeasible for `n = 18`.
Instead, the solution computes the [SJT](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm) **rank** of the target [permutation](https://ourbigbook.com/codex/permutation).

[SJT](https://ourbigbook.com/codex/steinhaus-johnson-trotter-algorithm) has a convenient recursive structure:

- Build `SJT(n)` from `SJT(n-1)` by inserting the new largest element `n` into each `(n-1)`-permutation.
- The insertion direction alternates with the `(n-1)`-permutation's rank:
  - rank even: insert `n` from **right to left**
  - rank odd: insert `n` from **left to right**

To rank a [permutation](https://ourbigbook.com/codex/permutation) of size `n`:

1. Remove `n` to obtain a [permutation](https://ourbigbook.com/codex/permutation) of size `n-1`.
2. Recursively rank that smaller [permutation](https://ourbigbook.com/codex/permutation) (`i`).
3. Let `p` be the position of `n` in the original [permutation](https://ourbigbook.com/codex/permutation).
4. Convert `p` into the within-block offset `t` depending on the [integer parity](https://ourbigbook.com/codex/integer-parity) of `i`.
5. Combine: `rank = i * n + t`.

## Mapping letters to numbers

Because the method compares letters by alphabetical order, the code maps the letters to `1..n` according to [sorting](https://ourbigbook.com/codex/sorting), then ranks the resulting numeric [permutation](https://ourbigbook.com/codex/permutation).

## Complexity

For `n` letters, the implementation is `O(n^2)` time (due to repeated `index` lookups and list slicing) and `O(n)` space, which is easily fast enough for `n = 18`.
