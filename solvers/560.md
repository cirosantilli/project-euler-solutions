# Project Euler 560 Solution - Coprime Nim

<https://projecteuler.net/problem=560>:

* [560.py](560.py)

This solution computes

\[
L(n,k) = \#\{(a_1,\dots,a_k)\in[1,n-1]^k : \text{starting position is losing}\}
\]

for **[Coprime](https://ourbigbook.com/codex/coprime) Nim**, and prints \(L(10^7,10^7)\bmod 1\,000\,000\,007\).

## 1) Grundy numbers

[Coprime](https://ourbigbook.com/codex/coprime) Nim is an [impartial game](https://ourbigbook.com/codex/impartial-game), so a position with multiple piles is losing iff the [xor](https://ourbigbook.com/codex/bitwise-exclusive-or) of the piles’ **[Grundy numbers](https://ourbigbook.com/codex/grundy-number)** is 0.

A move from a pile of size \(m\) removes \(r\) stones where \(\gcd(r,m)=1\), leaving \(m-r\).

Let \(g(m)\) be the [Grundy number](https://ourbigbook.com/codex/grundy-number) of a single pile of size \(m\).

### Closed form for \(g(m)\)

One can show:

- \(g(0)=0\), \(g(1)=1\)
- if \(m\) is even, then **\(g(m)=0\)**
- if \(m\) is odd and \(m>1\), let \(p=\operatorname{spf}(m)\) be the [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) of \(m\), then

\[
g(m)=\pi(p)
\]

where \(\pi(p)\) is the **[prime index](https://ourbigbook.com/codex/prime-index)**: \(\pi(2)=1,\ \pi(3)=2,\ \pi(5)=3,\dots\).

**Why this works (sketch):**

- If \(m\) is even, every legal removal \(r\) is odd, so every reachable pile size \(m-r\) is odd, and their [Grundy values](https://ourbigbook.com/codex/grundy-number) are \(\ge 1\). Thus 0 is missing and \(\mathrm{mex}=0\).
- If \(m\) is odd with [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) \(p\):
  - There exist legal moves to even pile sizes, so [Grundy number](https://ourbigbook.com/codex/grundy-number) 0 is reachable.
  - For every smaller [prime](https://ourbigbook.com/codex/prime) \(q<p\), \(q\) is [coprime](https://ourbigbook.com/codex/coprime) to \(m\), so removing \(q\) is legal and reaches a position whose [Grundy value](https://ourbigbook.com/codex/grundy-number) is \(\pi(q)\).
  - Any reachable \(m-r\) is [coprime](https://ourbigbook.com/codex/coprime) to \(m\), hence **not divisible by \(p\)**, so its [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) is \(<p\), meaning its [Grundy value](https://ourbigbook.com/codex/grundy-number) is at most \(\pi(p)-1\).
  - Therefore values \(\{0,1,\dots,\pi(p)-1\}\) are reachable while \(\pi(p)\) is not, so \(\mathrm{mex}=\pi(p)\).

So counting losing positions reduces to counting how many pile sizes have each [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor).

## 2) Counting losing k-tuples via XOR convolution + FWHT

Let `c[g]` be the number of pile sizes in \([1,n-1]\) with [Grundy value](https://ourbigbook.com/codex/grundy-number) `g`.

A k-pile starting position is losing iff

\[
g(a_1)\oplus g(a_2)\oplus \cdots \oplus g(a_k)=0.
\]

So \(L(n,k)\) is exactly the k-fold **[XOR convolution](https://ourbigbook.com/codex/xor-convolution)** of `c` evaluated at index 0.

The **[Hadamard transform](https://ourbigbook.com/codex/hadamard-transform) ([FWHT](https://ourbigbook.com/codex/fast-hadamard-transform))** diagonalizes [XOR convolution](https://ourbigbook.com/codex/xor-convolution):

- Let \(C = \mathrm{FWHT}(c)\) (unnormalized).
- The [FWHT](https://ourbigbook.com/codex/fast-hadamard-transform) of the k-fold [XOR convolution](https://ourbigbook.com/codex/xor-convolution) is \(C_i^k\) pointwise.
- The inverse transform at index 0 equals the **average**:

\[
L(n,k) = \frac{1}{M}\sum_{i=0}^{M-1} C_i^k \pmod{10^9+7},
\]

where \(M\) is the transform size (a [power of two](https://ourbigbook.com/codex/power-of-two) large enough to hold all [Grundy values](https://ourbigbook.com/codex/grundy-number)).

## 3) Odd-only sieve for smallest prime factors

To build `c` up to \(n=10^7\):

- Count all even pile sizes directly → contributes to `c[0]`.
- [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) only [odd numbers](https://ourbigbook.com/codex/odd-number) up to \(n-1\), storing `spf` for odds.
- When discovering an [odd prime](https://ourbigbook.com/codex/odd-prime) \(p\), mark each *previously unmarked* odd multiple starting at \(p^2\); each first mark increments the count of numbers whose [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) is \(p\).
- After sieving up to \(\sqrt{n}\), all remaining unmarked odds (excluding 1) are [primes](https://ourbigbook.com/codex/prime) \(>\sqrt{n}\) and each contributes 1.

This yields `c[pi(p)]` for every [odd prime](https://ourbigbook.com/codex/odd-prime) \(p\).

## Complexity

For \(n=10^7\):

- [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve): \(O(n\log\log n)\) time, \(O(n/2)\) memory (odd-only `spf`).
- [FWHT](https://ourbigbook.com/codex/fast-hadamard-transform): \(O(M\log M)\) with \(M\approx 2^{20}\).
- Final sum: \(O(M)\) [modular exponentiations](https://ourbigbook.com/codex/modular-exponentiation) using Python’s built-in `pow`.

The code includes `assert`s for all sample values from the problem statement.
