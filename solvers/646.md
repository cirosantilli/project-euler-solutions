# Project Euler 646 Solution - Bounded Divisors

<https://projecteuler.net/problem=646>:

* [646.py](646.py)

We want

\[
S(n,L,H)=\sum_{\substack{d\mid n\\L\le d\le H}}\lambda(d)\,d
\]

where \(\lambda\) is the [Liouville function](https://ourbigbook.com/codex/liouville-function): \(\lambda(n)=(-1)^{\Omega(n)}\) and \(\Omega(n)\) is the [total number of prime factors](https://ourbigbook.com/codex/total-number-of-prime-factors) with multiplicity.

For the actual problem we need \(S(70!,10^{20},10^{60}) \bmod (10^9+7)\).

---

## 1) Turn the summand into a completely multiplicative function

Define

\[
f(d)=\lambda(d)\,d.
\]

Because \(\lambda\) is [completely multiplicative](https://ourbigbook.com/codex/completely-multiplicative-function), so is \(f\). On [prime powers](https://ourbigbook.com/codex/prime-power):

\[
f(p^k)=(-1)^k\,p^k = (-p)^k.
\]

So any [divisor](https://ourbigbook.com/codex/divisor) \(d=\prod p^{k_p}\) has

\[
f(d)=\prod (-p)^{k_p}.
\]

This is perfect for fast [divisor](https://ourbigbook.com/codex/divisor) enumeration: we can build both the [divisor](https://ourbigbook.com/codex/divisor) value \(d\) and its contribution \(f(d)\) by multiplying precomputed power tables.

---

## 2) Reduce a bounded sum to prefix sums

Let

\[
F(x)=\sum_{\substack{d\mid n\\ d\le x}} f(d).
\]

Then

\[
S(n,L,H)=F(H)-F(L-1).
\]

So we only need the ability to compute \(F(x)\) quickly.

---

## 3) Meet-in-the-middle over the prime factors of \(n!\)

For \(n=70\), \(70!\) has only 19 [primes](https://ourbigbook.com/codex/prime) in its [integer factorization](https://ourbigbook.com/codex/integer-factorization), but the [number of divisors](https://ourbigbook.com/codex/divisor-function) is enormous.

Split the [primes](https://ourbigbook.com/codex/prime) into two [disjoint sets](https://ourbigbook.com/codex/disjoint-sets):

- **STORE** [primes](https://ourbigbook.com/codex/prime) → [divisors](https://ourbigbook.com/codex/divisor) \(b\)
- **ITER** [primes](https://ourbigbook.com/codex/prime) → [divisors](https://ourbigbook.com/codex/divisor) \(a\)

Every [divisor](https://ourbigbook.com/codex/divisor) \(d\mid n!\) can be written uniquely as \(d=a\cdot b\), and by [multiplicativity](https://ourbigbook.com/codex/multiplicativity)

\[
f(d)=f(a)\,f(b).
\]

For a prefix bound \(x\):

\[
F(x)=\sum_{a} f(a)\sum_{\substack{b\\ b\le x/a}} f(b).
\]

### Implementation detail

1. Enumerate all STORE [divisors](https://ourbigbook.com/codex/divisor) \(b\), sort them by value, and build a prefix array of \(\sum f(b)\).
2. For each ITER [divisor](https://ourbigbook.com/codex/divisor) \(a\), compute `limit = x // a`, [binary-search](https://ourbigbook.com/codex/binary-search) the largest `b <= limit`, and fetch the inner sum in **O(log |B|)**.

The code chooses STORE so that the number of STORE [divisors](https://ourbigbook.com/codex/divisor) stays below a fixed memory cap (about 1.2 million) but is still reasonably close to \(\sqrt{\tau(n!)}\) to balance work.

---

## 4) Speed trick: loop/base split on the iterated side

Enumerating all ITER [divisors](https://ourbigbook.com/codex/divisor) can still be millions of combinations. To reduce Python overhead:

- Move the few [primes](https://ourbigbook.com/codex/prime) with the largest \((e_p+1)\) factors into a small set of **loop [primes](https://ourbigbook.com/codex/prime)**.
- Enumerate the remaining **base [primes](https://ourbigbook.com/codex/prime)** into a small list.
- Combine them with nested loops.

This keeps the “stored base list” small (e.g., tens of thousands) while still visiting all ITER [divisors](https://ourbigbook.com/codex/divisor) exactly once.

---

## 5) Modulo arithmetic

For the final answer, all coefficients are kept [modulo](https://ourbigbook.com/codex/modulo) \(10^9+7\) during enumeration, which avoids huge intermediate [integers](https://ourbigbook.com/codex/integer).

The example values from the problem statement are asserted using exact [integer arithmetic](https://ourbigbook.com/codex/integer-arithmetic).

---

## Complexity (rough)

Let \(|B|\) be the number of STORE [divisors](https://ourbigbook.com/codex/divisor) and \(|A|\) the number of ITER [divisors](https://ourbigbook.com/codex/divisor).

- Precomputation: \(O(|B|\log |B|)\) for [sorting](https://ourbigbook.com/codex/sorting).
- Querying: \(O(|A|\log |B|)\) via [binary search](https://ourbigbook.com/codex/binary-search).

With \(n=70\) and the chosen split, this comfortably fits in time without any external libraries.
