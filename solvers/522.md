# Project Euler 522 Solution - Hilbert's Blackout

<https://projecteuler.net/problem=522>:

* [522.py](522.py)

We are given `n` floors. Each floor sends power to **exactly one other floor** (no [self-loops](https://ourbigbook.com/codex/loop-graph-theory)).
So each arrangement is a **loopless [functional digraph](https://ourbigbook.com/codex/functional-graph)** on `n` labeled [vertices](https://ourbigbook.com/codex/vertex-of-a-graph): [outdegree](https://ourbigbook.com/codex/outdegree) = 1,
and cycles have length ≥ 2.

Hilbert may **rewire** floors (change a vertex’s outgoing [edge](https://ourbigbook.com/codex/edge-of-a-graph)). The arrangement is **safe** iff
starting from **any** floor, power eventually reaches *all* floors — which is only possible when
the [digraph](https://ourbigbook.com/codex/directed-graph) is a **single directed `n`-cycle**.

The task is to compute:

- `F(n)` = sum, over all `(n-1)^n` loopless arrangements, of the **minimum number of rewires** needed,
- and output `F(12344321) mod 135707531`.

The problem statement gives sample values: `F(3)=6`, `F(8)=16276736`,
and `F(100) mod 135707531 = 84326147`. citeturn0search0turn0search2turn0search4

## 1) Graph decomposition

A [functional digraph](https://ourbigbook.com/codex/functional-graph) decomposes into components, each containing exactly one [directed cycle](https://ourbigbook.com/codex/directed-cycle) with
(in-arborescence) [trees](https://ourbigbook.com/codex/tree-graph-theory) feeding into the cycle.

Define:

- `z` = number of [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) with [indegree](https://ourbigbook.com/codex/indegree) 0 (nobody points to them),
- `c` = number of components (cycles),
- `p` = number of **pure** components: components that are *only* a [directed cycle](https://ourbigbook.com/codex/directed-cycle) (no [trees](https://ourbigbook.com/codex/tree-graph-theory) attached).

In a loopless [functional digraph](https://ourbigbook.com/codex/functional-graph):

- every **cycle [vertex](https://ourbigbook.com/codex/vertex-of-a-graph)** has [indegree](https://ourbigbook.com/codex/indegree) ≥ 1 (its predecessor on the cycle),
- every nontrivial attached [tree](https://ourbigbook.com/codex/tree-graph-theory) contains at least one [tree leaf](https://ourbigbook.com/codex/leaf-of-a-tree) (indegree-0 [vertex](https://ourbigbook.com/codex/vertex-of-a-graph)),
  and each **impure** component contains ≥ 1 such [tree leaf](https://ourbigbook.com/codex/leaf-of-a-tree).

Let `q = c - p` be the number of impure components. Then `z ≥ q`, so:

`z + p ≥ (c - p) + p = c`.

So `max(c, z+p) = z+p` always.

---

## 2) Minimal rewires simplify to `z + p` (with one exception)

Project Euler 522’s minimal-rewire value can be expressed (and brute-checked for small `n`) as:

- If the [graph](https://ourbigbook.com/codex/graph) is already a single `n`-cycle: **0** rewires.
- Otherwise: **`z + p`** rewires.

Since an `n`-cycle has `z=0` and `p=1`, we can write:

**minimum rewires = `z + p - I[n-cycle]`**.

Summing over all arrangements:

`F(n) = (sum z) + (sum p) - (# directed n-cycles)`.

The number of directed `n`-cycles on labeled [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) is `(n-1)!`.

---

## 3) Counting `sum z` by linearity of expectation

Fix a [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) `v`. For any other [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) `u≠v`, the [probability](https://ourbigbook.com/codex/probability) `u` points to `v` is `1/(n-1)`,
so the [probability](https://ourbigbook.com/codex/probability) `u` does **not** point to `v` is `(n-2)/(n-1)`.

Thus:

`P(indegree(v)=0) = ((n-2)/(n-1))^(n-1)`,

and by linearity:

`E[z] = n * ((n-2)/(n-1))^(n-1)`.

Multiply by the total number of arrangements `(n-1)^n`:

**`sum z = n*(n-1)*(n-2)^(n-1)`**.

---

## 4) Counting `sum p` by counting pure cycle components

A **pure component** is a [directed cycle](https://ourbigbook.com/codex/directed-cycle) (length ≥ 2) with **no incoming [edges](https://ourbigbook.com/codex/edge-of-a-graph)** from outside.

Fix a [directed cycle](https://ourbigbook.com/codex/directed-cycle) on `k` chosen [vertices](https://ourbigbook.com/codex/vertex-of-a-graph). Let `m = n-k` be outside [vertices](https://ourbigbook.com/codex/vertex-of-a-graph).

For the cycle to be a pure component, every outside [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) must point to another outside [vertex](https://ourbigbook.com/codex/vertex-of-a-graph)
(not itself). Each outside [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) then has `(m-1)` choices, giving `(m-1)^m` outside mappings.

Number of directed `k`-cycles on labeled [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) is `C(n,k)*(k-1)! = n!/(k*(n-k)!)`.

So:

`sum p = (n-1)! + n! * Σ_{m=2..n-2} (m-1)^m / ((n-m)*m!)`.

Finally, since `F(n)` subtracts `(n-1)!`, those cancel and we only need:

**`F(n) = n*(n-1)*(n-2)^(n-1) + n! * Σ_{m=2..n-2} (m-1)^m / ((n-m)*m!)`  (mod M)**

with `M = 135707531`.

`M` is [prime](https://ourbigbook.com/codex/prime) (it appears as a proven [prime](https://ourbigbook.com/codex/prime) in [prime](https://ourbigbook.com/codex/prime) lists). citeturn1search1turn1search5  
Also `n=12344321 < M`, so all [integers](https://ourbigbook.com/codex/integer) `1..n` are invertible mod `M`.

## 5) Implementation techniques (what `main.py` does)

- Uses the closed-form `sum z`.
- Computes `n! mod M`.
- Uses **O(n)** precomputation of [modular inverses](https://ourbigbook.com/codex/modular-inverse):

  `inv[i] = M - (M//i) * inv[M%i] (mod M)`  (valid for [prime](https://ourbigbook.com/codex/prime) `M`, `i<M`)

- Streams `inv_fact = 1/m!` incrementally using `inv[m]`.
- Accumulates the [summation](https://ourbigbook.com/codex/summation) in one pass.

Memory: stores only `inv[0..n]` using `array('I')` (~4 bytes per entry), about 50 MB for `n≈12.3M`.  
Time: linear passes plus [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation) (`pow(base, exp, M)`) per `m`.
