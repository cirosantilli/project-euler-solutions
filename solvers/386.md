# Project Euler 386 Solution - Maximum Length of an Antichain

<https://projecteuler.net/problem=386>:

* [386.py](386.py)

We want:

\[
\sum_{1 \le n \le 10^8} N(n)
\]

where \(N(n)\) is the maximum size of an *[antichain](https://ourbigbook.com/codex/antichain)* in the [divisor](https://ourbigbook.com/codex/divisor) set \(S(n)\) under [divisibility](https://ourbigbook.com/codex/divisibility).

## 1) Divisors form a product-of-chains poset

If

\[
n=\prod_{i=1}^r p_i^{a_i},
\]

then each [divisor](https://ourbigbook.com/codex/divisor) corresponds to a [vector](https://ourbigbook.com/codex/vector) \((e_1,\dots,e_r)\) with \(0\le e_i\le a_i\), ordered componentwise.
So the [divisor](https://ourbigbook.com/codex/divisor) [poset](https://ourbigbook.com/codex/partially-ordered-set) is a direct product of [chains](https://ourbigbook.com/codex/chain-in-a-partial-order) of lengths \((a_i+1)\).

A classic fact (Sperner-type results for products of [chains](https://ourbigbook.com/codex/chain-in-a-partial-order)) implies the [poset](https://ourbigbook.com/codex/partially-ordered-set) is **Sperner**: the largest [antichain](https://ourbigbook.com/codex/antichain)
is attained by a single rank level.

The natural [poset rank](https://ourbigbook.com/codex/rank-function-of-a-partially-ordered-set) is the total [exponent](https://ourbigbook.com/codex/exponent) sum:

\[
\text{rank}(e_1,\dots,e_r)=e_1+\cdots+e_r.
\]

## 2) Reduce \(N(n)\) to a tiny generating-function DP

The number of [divisors](https://ourbigbook.com/codex/divisor) of [poset rank](https://ourbigbook.com/codex/rank-function-of-a-partially-ordered-set) \(k\) is the [coefficient](https://ourbigbook.com/codex/coefficient) of \(x^k\) in:

\[
\prod_{i=1}^r (1+x+\cdots+x^{a_i}).
\]

Therefore:

*Compute all [coefficients](https://ourbigbook.com/codex/coefficient) (degree \(\sum a_i\)), then take the maximum.*

Since \(n\le 10^8\) implies \(\sum a_i\) is small (at most 26 for \(2^{26}\)), this [DP](https://ourbigbook.com/codex/dynamic-programming) is extremely fast.

## 3) Group by exponent multisets

The value \(N(n)\) depends only on the [multiset](https://ourbigbook.com/codex/multiset) \(\{a_1,\dots,a_r\}\), not on which [primes](https://ourbigbook.com/codex/prime) appear.

So we:

1. Enumerate all feasible exponent multisets for \(n \le 10^8\) (there are few, because at most 9 distinct [primes](https://ourbigbook.com/codex/prime) fit).
2. For each [multiset](https://ourbigbook.com/codex/multiset):
   - compute its [antichain](https://ourbigbook.com/codex/antichain) width \(N(\cdot)\) via the [DP](https://ourbigbook.com/codex/dynamic-programming) above,
   - count how many [integers](https://ourbigbook.com/codex/integer) \(n\le 10^8\) have exactly that [multiset](https://ourbigbook.com/codex/multiset),
   - add `count * width` to the final sum.

## 4) Counting how many numbers realize a given multiset

For a [multiset](https://ourbigbook.com/codex/multiset) of [exponents](https://ourbigbook.com/codex/exponent) sorted non-increasing, we assign distinct [primes](https://ourbigbook.com/codex/prime) to those [exponents](https://ourbigbook.com/codex/exponent).
To avoid overcounting when some [exponents](https://ourbigbook.com/codex/exponent) are equal, we impose an ordering only *within equal-exponent groups*
([primes](https://ourbigbook.com/codex/prime) [strictly increasing](https://ourbigbook.com/codex/strictly-increasing) there).

The counting itself is done with a short [recursion](https://ourbigbook.com/codex/recursion) over [prime](https://ourbigbook.com/codex/prime) choices, using strong numeric bounds so that only
small [primes](https://ourbigbook.com/codex/prime) are explicitly iterated.

When the [recursion](https://ourbigbook.com/codex/recursion) reaches the last [prime](https://ourbigbook.com/codex/prime), the remaining count is obtained via a fast [prime-counting function](https://ourbigbook.com/codex/prime-counting-function) \(\pi(x)\).

## 5) Fast \(\pi(x)\) with Lehmer prime counting

Direct sieving to \(10^8\) in pure Python is memory/time heavy.
Instead, the solution uses a standard **[Meissel–Lehmer](https://ourbigbook.com/codex/lehmer-prime-counting-algorithm)** [prime counting](https://ourbigbook.com/codex/prime-counting) implementation:

- sieve [primes](https://ourbigbook.com/codex/prime) up to \(10^6\),
- use the Lehmer formula plus a cached `phi(x, s)` to compute \(\pi(x)\) for \(x \le 10^8\) quickly,
- cache \(\pi(x)\) values across calls (the [recursion](https://ourbigbook.com/codex/recursion) asks for many repeats).

This makes the overall approach feasible without iterating over all \(n \le 10^8\).
