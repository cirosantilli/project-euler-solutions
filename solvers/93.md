# Project Euler 93 Solution - Arithmetic Expressions

<https://projecteuler.net/problem=93>:

* [93.py](93.py)
* [93.lean](93.lean)

Choose four distinct [digits](https://ourbigbook.com/codex/numerical-digit) and use each exactly once with addition, subtraction, multiplication, division, and arbitrary parentheses. The objective is the longest consecutive run of positive integer results starting at one. Concatenation is not allowed.

Both Python implementations generalize this to four distinct nonnegative integer operands at most `max_digit`, which may exceed nine. They return an increasing tuple, choosing the lexicographically first tuple on ties, or the empty tuple when fewer than four operands are available. The default bound is nine; the script prints `1258`, whose run reaches 51.

## Exact arithmetic

A [rational number](https://ourbigbook.com/codex/rational-number) is represented by its integer numerator and positive denominator. The optimized implementation divides both by their [greatest common divisor](https://ourbigbook.com/codex/greatest-common-divisor), giving each value a unique tuple representation. It tests integrality by checking whether the denominator is one. The reference retains unreduced pairs and tests exact divisibility instead. Both omit division by zero and retain fractional intermediate values.

## Optimized search

Start with the four rational operands. Repeatedly choose any pair of current expression fragments and replace it by each permitted arithmetic result. Include both orders for subtraction and division. Every [binary expression tree](https://ourbigbook.com/codex/binary-expression-tree) can be constructed this way.

Sort each state of normalized pairs to obtain a canonical [multiset](https://ourbigbook.com/codex/multiset) key. A [memoization](https://ourbigbook.com/codex/memoization) dictionary avoids recomputing equal states, and sets deduplicate their resulting values. Tuple sorting only orders the cache key; it need not compare the represented rational values numerically.

## Exhaustive reference

For each operand permutation, split the sequence at every interior position. Recursively enumerate the left and right expressions and combine them with each operation. This includes all five parenthesizations for four operands, including balanced trees such as `(a + b) * (c + d)`. The reference keeps duplicate results and scans for the first missing positive integer without an iteration cutoff.

## Proof status

The [rational-pair lemmas](../ProjectEulerSolutions/Lib/RationalPair.lean) prove that normalization gives Lean's exact canonical rational numerator and denominator for every integer numerator and nonzero integer denominator. Equal rational values therefore yield identical tuple keys. The [Python helper proof](93.py.lean.d/Rational.lean) follows sign normalization, the gcd call, division, and tuple allocation, preserving caller heap objects. Its [source contracts](93.py.lean) prove termination and the exact result using only standard Lean axioms.

The [reference operation proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Operations.lean) executes the arithmetic, divisor-sign branches, tuple allocations, and result-list appends. It preserves all caller objects, including shared operand tuples. The [unreduced-pair model](../ProjectEulerSolutions/Lib/RationalEnumeration.lean) proves that every recursive result retains a positive denominator and that the complete value list agrees with ordered expression enumeration. The [reference collection proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Outer.lean) follows both nested loops through every operand pair, preserving result order, duplicates, and shared tuples. Empty and singleton inputs and the tuple slices are also proved.

The [recursive source proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Enumeration.lean) connects the complete `all_results` traversal to that ordered expression model for every integer tuple. Induction on operand count covers both recursive calls and every interior split, while preserving caller objects. The [consecutive scan proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Consecutive.lean) proves termination and the least missing positive integer for every integer list. Its reusable [positive-run lemmas](../ProjectEulerSolutions/Lib/PositiveRun.lean) show that the result depends only on positive-integer membership, regardless of duplicates or ordering. These proofs use only standard Lean axioms and do not evaluate either complete program.

The [integer-extraction lemmas](../ProjectEulerSolutions/Lib/RationalIntegers.lean) prove that positive numerators with exact divisibility represent precisely the positive integer results. The [complete reference helper proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Digits.lean) follows every positional permutation, recursive result call, tuple unpack, divisibility test, integer append, and consecutive scan. Its membership theorem connects the returned run to all expression trees over every operand permutation, including repeated, negative, and empty input tuples.

The [reference search proof](../data/project-euler-statements/data/py/project_euler_statements/p93.py.lean.d/Search.lean) covers every signed `max_digit`, the complete combination pool, all candidate score calls, and strict best-score updates. The result is the standard first-on-tie `List.argmax`, with an empty tuple for an empty candidate list. The default call reuses the generalized proof. Caller objects remain unchanged; private tuple, list, and recursive-result allocations are tracked explicitly.

The [expression-tree proof](../ProjectEulerSolutions/Lib/ArithmeticExpressions.lean) establishes completeness of every recursive split and operand permutation. The [pair-reduction proof](../ProjectEulerSolutions/Lib/ArithmeticReduction.lean) proves that replacing arbitrary pairs produces exactly those same values: sibling contraction gives completeness, and substituting expression fragments gives soundness, including repeated operands. Connecting the optimized pair operations, memo table, integer-result set, and best-operand search to this equivalence remains pending.

The [regression tests](../tests/test_p93_expressions.py) compare both algorithms across all decimal operand sets and check an independent `fractions.Fraction` oracle for every four-leaf tree shape, including zero, repeated, negative, and larger operands. The separate handwritten Lean models still need reconciliation with the generalized Python contract.
