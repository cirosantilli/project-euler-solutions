# Project Euler 502 Solution - Counting Castles

<https://projecteuler.net/problem=502>:

* [502.py](502.py)

This solver uses **[generating functions](https://ourbigbook.com/codex/generating-function)**, **[integer parity](https://ourbigbook.com/codex/integer-parity) filtering**, and **fast [coefficient extraction](https://ourbigbook.com/codex/coefficient-extraction)** to count valid castles efficiently for enormous widths/heights.

---

## 1. Structural Decomposition → Generating Function

A castle is built from horizontal blocks (height 1, [integer](https://ourbigbook.com/codex/integer) length) stacked on a width `w` base block.

Key observation:
- The configuration above any block depends only on what happens inside its horizontal span.
- Row blocks must be separated by ≥1 space.

This leads to a [rational generating function](https://ourbigbook.com/codex/rational-generating-function) [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) for castles of height ≤h.

Let:

- `C_h(x, y)` = [generating function](https://ourbigbook.com/codex/generating-function) where:
  - `x` marks width,
  - `y` marks number of blocks.

Base:
```
C_1 = y * x/(1-x)
```

[Recurrence relation](https://ourbigbook.com/codex/recurrence-relation):
```
C_h = y * ( x + (1+x) C_{h-1} ) / ( 1 - x(1 + C_{h-1}) )
```

---

## 2. Even-Block Constraint via Parity Evaluation

We need castles with an **[even number](https://ourbigbook.com/codex/even-number) of blocks**.

Standard trick:
- Evaluate at `y = 1` → counts all castles
- Evaluate at `y = -1` → counts castles weighted by (-1)^(#blocks)

Then:

```
E = (C(1) + C(-1)) / 2
```

This isolates even block counts.

---

## 3. Exact Height Constraint

The problem requires **max height exactly h**, not ≤h.

So:

```
F(w,h) = E≤h(w) - E≤(h-1)(w)
```

---

## 4. Coefficient Extraction

We must extract `[x^w] C_h(x, y)` for different regimes:

### A) Moderate `w` (≤ 10000), moderate `h` (≤ 10000)
- Build [numerator](https://ourbigbook.com/codex/numerator)/[denominator](https://ourbigbook.com/codex/denominator) [polynomials](https://ourbigbook.com/codex/polynomial) `P_h, Q_h`.
- Compute series [coefficient](https://ourbigbook.com/codex/coefficient) of `P_h / Q_h`.

For large `w`, this uses **[Newton series inversion](https://ourbigbook.com/codex/newton-iteration-for-power-series-inversion)** accelerated by fast [polynomial multiplication](https://ourbigbook.com/codex/polynomial-multiplication).

### B) Huge width (`w = 10^12`), small height (`h ≤ 100`)
- Series becomes a [linear recurrence](https://ourbigbook.com/codex/linear-recurrence) of order `h`.
- Use **[Kitamasa algorithm](https://ourbigbook.com/codex/kitamasa-algorithm)** (O(h² log w)) to compute [coefficient](https://ourbigbook.com/codex/coefficient) `x^w`.

### C) Huge height (`h = 10^12`), small width (`w ≤ 100`)
- Work [modulo](https://ourbigbook.com/codex/modulo-operation) `x^(w+1)`.
- Use **2×2 [matrix exponentiation](https://ourbigbook.com/codex/matrix-exponentiation)** on truncated [polynomials](https://ourbigbook.com/codex/polynomial).

---

## 5. Fast Polynomial Multiplication (NTT + CRT)

Since modulus `1e9+7` is not NTT-friendly, we perform [NTT](https://ourbigbook.com/codex/number-theoretic-transform) under three [primes](https://ourbigbook.com/codex/prime):

- 998244353
- 1004535809
- 469762049

Then reconstruct exact [integer](https://ourbigbook.com/codex/integer) [coefficients](https://ourbigbook.com/codex/coefficient) via [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) (product is > max [coefficient](https://ourbigbook.com/codex/coefficient) bound),
finally reduce mod `1e9+7`.
