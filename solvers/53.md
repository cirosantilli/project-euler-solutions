# Project Euler 53 Solution - Combinatoric Selections

<https://projecteuler.net/problem=53>:

* [53.py](53.py)
* [Python source proof](53.py.lean)
* [53.lean](53.lean)

We must count how many [binomial coefficients](https://ourbigbook.com/codex/binomial-coefficient) `C(n, r)` with `1 ≤ n ≤ 100` exceed `1,000,000` (counting pairs `(n,r)`, not distinct values).

## Key insights
- Use the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) to compute [binomial coefficients](https://ourbigbook.com/codex/binomial-coefficient) efficiently without [factorials](https://ourbigbook.com/codex/factorial):
  - `C(n, 0) = 1`
  - `C(n, r) = C(n, r-1) * (n-r+1) / r` (always an [integer](https://ourbigbook.com/codex/integer))
- For fixed `n`, the sequence `C(n, r)` increases up to `r = floor(n/2)` and is symmetric:
  - `C(n, r) = C(n, n-r)`
- Therefore, once we find the smallest `r` (with `r ≤ n/2`) such that `C(n, r) > 1,000,000`,
  then **all** `r` in the range `[r, n-r]` exceed the threshold.
  The count contributed by this `n` is `n - 2r + 1`.

The solver also handles other integer bounds and thresholds. Nonpositive bounds give zero. If the threshold is less than one, every coefficient qualifies, including both endpoints: for a positive bound `N`, the count is `N(N+3)/2`. The Python source proof covers these cases and the early-break search.

## Complexity
For each `n` we scan `r` only up to `n/2` and often stop early, so this runs extremely fast for `n ≤ 100`.

The final answer printed is `4075`.
