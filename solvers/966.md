# Project Euler 966 Solution - Triangle Circle Intersection

<https://projecteuler.net/problem=966>:

* [966.py](966.py)

This repo contains a single-file solution (`main.py`) that computes

\[
\sum I(a,b,c)\quad\text{for integer triangles }1\le a\le b\le c < a+b,\ a+b+c\le 200,
\]

where **\(I(a,b,c)\)** is the **maximum possible [area](https://ourbigbook.com/codex/area) of intersection** between:

- a [triangle](https://ourbigbook.com/codex/triangle) with side lengths \(a,b,c\), and
- a [circle](https://ourbigbook.com/codex/circle) whose [area](https://ourbigbook.com/codex/area) equals the triangle’s [area](https://ourbigbook.com/codex/area),

allowing the [circle](https://ourbigbook.com/codex/circle) to be translated freely in the plane.

## Main techniques used

### 1) Deterministic coordinate placement
For side lengths \(a,b,c\), the [triangle](https://ourbigbook.com/codex/triangle) is placed as:

- \(A=(0,0)\)
- \(B=(c,0)\)
- \(C=(x,y)\) from the [law of cosines](https://ourbigbook.com/codex/law-of-cosines) so that \(|AC|=b\) and \(|BC|=a\)

This removes irrelevant [rigid motions](https://ourbigbook.com/codex/rigid-motion).

### 2) Equal-area circle radius
If the [triangle](https://ourbigbook.com/codex/triangle) has [area](https://ourbigbook.com/codex/area) \(T\), the [circle](https://ourbigbook.com/codex/circle) satisfies \(\pi r^2 = T\), hence
\[
r=\sqrt{T/\pi}.
\]

### 3) Triangle–circle intersection via per-edge triangle/sector contributions
To evaluate overlap for a fixed [circle](https://ourbigbook.com/codex/circle) center:

- translate so the [circle](https://ourbigbook.com/codex/circle) is centered at the origin
- for each oriented edge \(P\to Q\), compute its signed contribution:
  - split the segment at its intersection point(s) with the [circle](https://ourbigbook.com/codex/circle)
  - **classify each resulting subsegment using its endpoints**
    (inside/on [circle](https://ourbigbook.com/codex/circle) → [triangle](https://ourbigbook.com/codex/triangle) [area](https://ourbigbook.com/codex/area); otherwise → sector [area](https://ourbigbook.com/codex/area))
  - project computed intersection points back onto the [circle](https://ourbigbook.com/codex/circle) to reduce drift

Summing the three edge contributions (and taking [absolute value](https://ourbigbook.com/codex/absolute-value)) yields the
[triangle](https://ourbigbook.com/codex/triangle)–[circle](https://ourbigbook.com/codex/circle) intersection [area](https://ourbigbook.com/codex/area).

### 4) Maximization by pattern search
To compute \(I(a,b,c)\), the code maximizes the overlap over the [circle](https://ourbigbook.com/codex/circle) center
using a deterministic, derivative-free search:

- try several geometric start points (centroid, [incenter](https://ourbigbook.com/codex/incenter), [circumcenter](https://ourbigbook.com/codex/circumcenter), vertices, midpoints)
- perform an 8-direction pattern search (axes + diagonals)
- at each [step size](https://ourbigbook.com/codex/step-size), “keep walking” while improvements exist, then halve the step

### 5) Similarity scaling speedup (group by gcd)
If \((a,b,c)=g(a',b',c')\), scaling scales all areas by \(g^2\), so
\[
I(ga',gb',gc') = g^2 I(a',b',c').
\]
The program groups [triangles](https://ourbigbook.com/codex/triangle) by their gcd-reduced shape and accumulates the
needed \(g^2\) weights so each shape is optimized only once.

### 6) Independent worker chunks
The optimized shapes are independent. For the full perimeter-200 run, the solver
splits the shape list into worker chunks, computes a compensated [partial sum](https://ourbigbook.com/codex/partial-sum) in
each worker, and then combines the [partial sums](https://ourbigbook.com/codex/partial-sum) with another compensated
reduction. If multiprocessing is unavailable, the same chunk routine is used in
one process.
