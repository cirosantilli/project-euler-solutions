# Project Euler 788 Solution - Dominating Numbers

<https://projecteuler.net/problem=788>:

* [788.py](788.py)

## Problem Summary

Let $D(n)$ denote the number of [positive integers](https://ourbigbook.com/codex/positive-integer) $x<10^n$ whose usual [decimal representation](https://ourbigbook.com/codex/decimal-representation) has a [digit](https://ourbigbook.com/codex/numerical-digit) appearing in more than half of its positions. Such a [digit](https://ourbigbook.com/codex/numerical-digit) is called dominating. The goal is to compute $D(2022)$ [modulo](https://ourbigbook.com/codex/modulo-operation) $10^9+7$.

A direct scan over all numbers below $10^{2022}$ is hopeless. The key simplification is to count valid numbers by decimal length and by the exact number of times the dominating [digit](https://ourbigbook.com/codex/numerical-digit) appears.

## Mathematical Approach

For each length $\ell$, let $A(\ell)$ be the number of dominating $\ell$-digit numbers. Then

$$D(n)=\sum_{\ell=1}^{n} A(\ell).$$

The remaining task is to derive a closed formula for $A(\ell)$.

### Step 1: Fix the length and the exact dominating multiplicity

Assume a length-$\ell$ number has a dominating [digit](https://ourbigbook.com/codex/numerical-digit) occurring exactly $k$ times. By definition, domination means

$$k>\frac{\ell}{2}.$$

This strict inequality is important: two different [digits](https://ourbigbook.com/codex/numerical-digit) cannot both appear more than half the time. So every dominating number has a unique dominating [digit](https://ourbigbook.com/codex/numerical-digit) and contributes to exactly one value of $k$.

Therefore, for fixed $\ell$, the valid [multiplicities](https://ourbigbook.com/codex/multiplicity) are

$$k=\left\lfloor\frac{\ell}{2}\right\rfloor+1,\ \left\lfloor\frac{\ell}{2}\right\rfloor+2,\ \dots,\ \ell.$$

If $N(\ell,k)$ denotes the number of $\ell$-digit numbers whose dominating [digit](https://ourbigbook.com/codex/numerical-digit) appears exactly $k$ times, then

$$A(\ell)=\sum_{k=\lfloor \ell/2\rfloor+1}^{\ell} N(\ell,k).$$

### Step 2: Choose the positions occupied by the dominating digit

Fix $\ell$ and $k$. First choose which $k$ positions contain the dominating [digit](https://ourbigbook.com/codex/numerical-digit). There are

$$\binom{\ell}{k}$$

such position sets.

Once those positions are chosen, the remaining $\ell-k$ positions must use [digits](https://ourbigbook.com/codex/numerical-digit) different from the dominating [digit](https://ourbigbook.com/codex/numerical-digit). No extra condition is needed to stop another [digit](https://ourbigbook.com/codex/numerical-digit) from also dominating, because the non-dominating positions are too few:

$$\ell-k<k.$$

So the [combinatorics](https://ourbigbook.com/codex/combinatorics) reduces to counting how many assignments are possible for one fixed choice of the $k$ dominant positions.

### Step 3: Handle the leading-digit restriction carefully

The first [digit](https://ourbigbook.com/codex/numerical-digit) of an $\ell$-digit number cannot be $0$, so the count is not just $10\cdot 9^{\ell-k}$. The implementations implicitly resolve this by splitting into two cases for a fixed set of dominant positions.

If the first position is one of the $k$ dominant positions, then the dominating [digit](https://ourbigbook.com/codex/numerical-digit) itself must be nonzero. There are $9$ choices for that [digit](https://ourbigbook.com/codex/numerical-digit), and every remaining non-dominant position has $9$ choices because it may use any [digit](https://ourbigbook.com/codex/numerical-digit) except the dominating one. This case contributes

$$9\cdot 9^{\ell-k}=9^{\ell-k+1}.$$

If the first position is not dominant, then the dominating [digit](https://ourbigbook.com/codex/numerical-digit) may be zero or nonzero. Summing those possibilities gives

$$9\cdot 8 + 1\cdot 9 = 81 = 9^2$$

choices for the pair consisting of the dominating [digit](https://ourbigbook.com/codex/numerical-digit) and the first [digit](https://ourbigbook.com/codex/numerical-digit): $9$ nonzero dominant [digits](https://ourbigbook.com/codex/numerical-digit) with $8$ legal first [digits](https://ourbigbook.com/codex/numerical-digit) each, or the dominant [digit](https://ourbigbook.com/codex/numerical-digit) $0$ with $9$ legal first [digits](https://ourbigbook.com/codex/numerical-digit). The other $\ell-k-1$ non-dominant positions again have $9$ choices each, so this case contributes

$$81\cdot 9^{\ell-k-1}=9^{\ell-k+1}.$$

Both cases give the same value. That is why every chosen position set contributes exactly $9^{\ell-k+1}$.

### Step 4: Derive the closed count for one pair $(\ell,k)$

Multiplying the number of position sets by the number of valid assignments for each set gives

$$N(\ell,k)=\binom{\ell}{k}9^{\ell-k+1}.$$

Hence the number of dominating numbers of length $\ell$ is

$$A(\ell)=\sum_{k=\lfloor \ell/2\rfloor+1}^{\ell}\binom{\ell}{k}9^{\ell-k+1}.$$

### Step 5: Sum over all decimal lengths

Adding the contributions of all lengths from $1$ to $n$ yields the final formula

$$\boxed{D(n)=\sum_{\ell=1}^{n}\sum_{k=\lfloor \ell/2\rfloor+1}^{\ell}\binom{\ell}{k}9^{\ell-k+1}\pmod{10^9+7}.}$$

This is the exact quantity accumulated by the C++, Python, and Java implementations.

### Worked Example: $D(4)=603$

For $n=4$, compute the contribution of each length separately.

For $\ell=1$, only $k=1$ is possible:

$$\binom{1}{1}9^1=9.$$

For $\ell=2$, only $k=2$ is allowed:

$$\binom{2}{2}9^1=9.$$

For $\ell=3$, the allowed values are $k=2$ and $k=3$:

$$\binom{3}{2}9^2+\binom{3}{3}9^1=3\cdot81+9=252.$$

For $\ell=4$, the allowed values are $k=3$ and $k=4$:

$$\binom{4}{3}9^2+\binom{4}{4}9^1=4\cdot81+9=333.$$

Therefore

$$D(4)=9+9+252+333=603,$$

which matches the small checkpoint used by the implementations.

## How the Code Works

The implementations all follow the same numerical strategy. They precompute [factorials](https://ourbigbook.com/codex/factorial), inverse [factorials](https://ourbigbook.com/codex/factorial), and powers of $9$ up to the requested limit $n$. Because the modulus

$$M=10^9+7$$

is [prime](https://ourbigbook.com/codex/prime), inverse [factorials](https://ourbigbook.com/codex/factorial) can be obtained using [Fermat's little theorem](https://ourbigbook.com/codex/fermat-s-little-theorem):

$$a^{M-1}\equiv 1 \pmod{M}\qquad\Longrightarrow\qquad a^{-1}\equiv a^{M-2}\pmod{M}.$$

After that precomputation, every [binomial coefficient](https://ourbigbook.com/codex/binomial-coefficient) $\binom{\ell}{k}$ is available in constant time. The implementation then loops over all lengths $\ell=1,\dots,n$, loops over all valid dominating [multiplicities](https://ourbigbook.com/codex/multiplicity) $k>\ell/2$, evaluates the term $\binom{\ell}{k}9^{\ell-k+1}$ [modulo](https://ourbigbook.com/codex/modulo-operation) $M$, and accumulates the result.

## Complexity Analysis

Building the [factorial](https://ourbigbook.com/codex/factorial), inverse-factorial, and power tables costs $O(n)$ time and $O(n)$ memory. The main computation is a double sum over all pairs $(\ell,k)$ with $1\le \ell\le n$ and $k>\ell/2$, which performs

$$\sum_{\ell=1}^{n}\left(\ell-\left\lfloor\frac{\ell}{2}\right\rfloor\right)=O(n^2)$$

constant-time updates. Therefore the total running time is $O(n^2)$ and the memory usage is $O(n)$.
