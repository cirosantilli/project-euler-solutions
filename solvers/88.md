# Project Euler 88 Solution - Product-sum Numbers

<https://projecteuler.net/problem=88>:

* [88.py](88.py)
* [88.lean](88.lean)

A number `N` is a [product-sum number](https://ourbigbook.com/codex/product-sum-number) for a [multiset](https://ourbigbook.com/codex/multiset) of `k` [natural numbers](https://ourbigbook.com/codex/natural-number) if:
`N = sum(a_i) = product(a_i)`.

Key trick:
- Enumerate only factors `>= 2` (ignore `1`s during search).
- For any factor [multiset](https://ourbigbook.com/codex/multiset) with:
  - [product](https://ourbigbook.com/codex/product) `P`
  - [sum](https://ourbigbook.com/codex/sum) `S`
  - number of factors `t`
- We can add exactly `(P - S)` ones to make the total [sum](https://ourbigbook.com/codex/sum) equal to `P` without changing the [product](https://ourbigbook.com/codex/product).
- That yields an effective [set](https://ourbigbook.com/codex/set) size:
  `k = t + (P - S)`.

So, for each factor [multiset](https://ourbigbook.com/codex/multiset) we compute `k` and update the minimal `P` for that `k`.

### Enumeration
We perform a [DFS](https://ourbigbook.com/codex/depth-first-search) generating factor [multisets](https://ourbigbook.com/codex/multiset) in nondecreasing order to avoid duplicates.
We also use a known safe [upper bound](https://ourbigbook.com/codex/upper-bound): minimal [product-sum numbers](https://ourbigbook.com/codex/product-sum-number) for `k <= K` are `<= 2K`,
so we only explore [products](https://ourbigbook.com/codex/product) up to `2K`.

### Result
After filling the minimal value for each `k` in `[2..K]`, we take the [set](https://ourbigbook.com/codex/set) of these minimal values
(duplicates removed) and [sum](https://ourbigbook.com/codex/sum) them.

The code includes asserts for the examples:
- `K=6  -> 30`
- `K=12 -> 61`

Finally it prints the answer for `K=12000`.
