# Tennis Leaderboard Overtakes

This solution counts the possible overtake-count [vectors](https://ourbigbook.com/codex/vector) without simulating match [sequences](https://ourbigbook.com/codex/sequence).

## Main ideas

1. **Ignore non-overtake matches.**
   A non-overtake match leaves both the ranking and all counts unchanged. Therefore only the overtakes matter, and the number of overtakes must be even when the ranking returns to the identity. If `T = k // 2`, the task is to count valid [vectors](https://ourbigbook.com/codex/vector) with total count at most `2T`.

2. **Characterize valid [vectors](https://ourbigbook.com/codex/vector) by positive blocks.**
   Split an overtake-count [vector](https://ourbigbook.com/codex/vector) into maximal contiguous blocks of positive entries, separated by zeros. A block with entries `x_1, ..., x_l` is valid exactly when:

   - its sum is even, say `2t`, and
   - every entry is at most `t`.

   A one-entry positive block is therefore impossible. Multiple blocks are independent because a zero gap means no player ever needs to cross that gap.

3. **Count one block with [inclusion-exclusion](https://ourbigbook.com/codex/inclusion-exclusion-principle).**
   For a block of length `l` and cost `t`, the number of [positive integer](https://ourbigbook.com/codex/positive-integer) [vectors](https://ourbigbook.com/codex/vector) with sum `2t` and all entries at most `t` is

   ```text
   A(l, t) = C(2t - 1, l - 1) - l * C(t - 1, l - 1),
   ```

   where the second binomial term is treated as zero if `t < l`. At most one entry can exceed `t`, so only one subtraction term is needed.

4. **Use [generating functions](https://ourbigbook.com/codex/generating-function).**
   For each block length `l`, the series `sum_t A(l,t) q^t` has [denominator](https://ourbigbook.com/codex/denominator) `(1-q)^l`. The program stores only its [numerator](https://ourbigbook.com/codex/numerator). A [dynamic program](https://ourbigbook.com/codex/dynamic-program) scans positions and appends either:

   - a zero, or
   - a whole positive block starting after a zero or at the beginning.

   For a prefix of length `i`, its [generating function](https://ourbigbook.com/codex/generating-function) is stored as a [numerator](https://ourbigbook.com/codex/numerator) over `(1-q)^i`, so appending a zero multiplies the [numerator](https://ourbigbook.com/codex/numerator) by `(1-q)`, while appending a block multiplies by that block's [numerator](https://ourbigbook.com/codex/numerator).

5. **Convert exact-cost counts to cumulative counts.**
   At the end,

   ```text
   H_n(q) = N_n(q) / (1-q)^n
   ```

   counts exact costs. Summing all costs up to `T` is the [coefficient](https://ourbigbook.com/codex/coefficient) of `q^T` in

   ```text
   N_n(q) / (1-q)^(n+1).
   ```

   This is evaluated with [binomial coefficients](https://ourbigbook.com/codex/binomial-coefficient). The final target is computed [modulo](https://ourbigbook.com/codex/modulo-operation) `1234567891`.
