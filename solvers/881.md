# Project Euler 881 Solution - Divisor Graph Width

<https://projecteuler.net/problem=881>:

* [881.py](881.py)

This repository contains a pure-Python solution (no third‑party libraries) for **[Project Euler](https://ourbigbook.com/codex/project-euler) 881: [Divisor](https://ourbigbook.com/codex/divisor) [Graph](https://ourbigbook.com/codex/graph) Width**.

## Key ideas

### 1) Divisor graph as an exponent lattice
Write

\[
 n = \prod_{i=1}^m p_i^{e_i}.
\]

Every [divisor](https://ourbigbook.com/codex/divisor) corresponds to an [exponent vector](https://ourbigbook.com/codex/exponent-vector) \((f_1,\dots,f_m)\) with \(0\le f_i\le e_i\). An edge connects two [divisors](https://ourbigbook.com/codex/divisor) when their quotient is [prime](https://ourbigbook.com/codex/prime), i.e. when you multiply/divide by exactly one [prime](https://ourbigbook.com/codex/prime) once. In the exponent-vector view, each edge changes exactly **one coordinate by \(\pm 1\)**.

Starting from \(n\) (the vector \((e_1,\dots,e_m)\)), reaching a [divisor](https://ourbigbook.com/codex/divisor) \((f_1,\dots,f_m)\) requires decreasing coordinates; the shortest [path length](https://ourbigbook.com/codex/path-length) is the **[Manhattan distance](https://ourbigbook.com/codex/manhattan-distance)**:

\[
\text{dist}(n, d) = \sum_i (e_i - f_i).
\]

So “level \(k\)” consists of all [divisors](https://ourbigbook.com/codex/divisor) whose total exponent *deficit* equals \(k\).

### 2) Level sizes via generating functions
For each [prime](https://ourbigbook.com/codex/prime) \(p_i^{e_i}\), the deficit in that coordinate can be any [integer](https://ourbigbook.com/codex/integer) from \(0\) to \(e_i\). The number of [divisors](https://ourbigbook.com/codex/divisor) at level \(k\) is therefore the coefficient of \(x^k\) in

\[
P(x) = \prod_{i=1}^m (1 + x + \cdots + x^{e_i}).
\]

The required quantity is

\[
 g(n) = \max_k [x^k]P(x).
\]

### 3) Fast multiplication by \(1+x+\cdots+x^e\)
Each factor \(1+x+\cdots+x^e\) has all coefficients equal to 1, so multiplying a coefficient array by this factor is a **sliding-window sum**:

\[
\text{new}[j] = \sum_{t=j-e}^{j} \text{old}[t]
\]

(with indices clamped to valid ranges). Using [prefix sums](https://ourbigbook.com/codex/prefix-sum), each multiplication runs in linear time in the [polynomial](https://ourbigbook.com/codex/polynomial) length.

### 4) Searching for the smallest \(n\)
The width \(g(n)\) depends only on the exponent [multiset](https://ourbigbook.com/codex/multiset) \(\{e_i\}\), while the numeric value of \(n\) is minimized by assigning **larger exponents to smaller [primes](https://ourbigbook.com/codex/prime)**. Thus we search over exponent sequences constrained to be **non-increasing**:

\[
 e_1 \ge e_2 \ge \cdots \ge e_m \ge 1.
\]

A [branch-and-bound](https://ourbigbook.com/codex/branch-and-bound) [DFS](https://ourbigbook.com/codex/depth-first-search) builds exponents prime-by-prime:

- maintain the current [polynomial](https://ourbigbook.com/codex/polynomial) coefficients and its current maximum coefficient (the current best possible level width),
- maintain the current numeric value of \(n\),
- prune any branch where \(n\) already exceeds the best solution found so far.

An initial (easy) [upper bound](https://ourbigbook.com/codex/upper-bound) is obtained by using only exponent 1 (distinct [primes](https://ourbigbook.com/codex/prime)), i.e. \((1+x)^m\), increasing \(m\) until the peak coefficient reaches the target.
