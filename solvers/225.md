# Project Euler 225 Solution - Tribonacci Non-divisors

<https://projecteuler.net/problem=225>:

* [225.py](225.py)

## Problem Summary

The [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) sequence is defined by $T_1=T_2=T_3=1$ and

$$T_{k+3}=T_{k+2}+T_{k+1}+T_k.$$

For an [odd integer](https://ourbigbook.com/codex/odd-integer) $n$, we ask whether at least one [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) term is divisible by $n$. The task is to scan the [odd integers](https://ourbigbook.com/codex/odd-integer) and find the 124th one for which this never happens.

Trying to generate huge [Tribonacci numbers](https://ourbigbook.com/codex/tribonacci-number) directly is the wrong viewpoint. [Divisibility](https://ourbigbook.com/codex/divisibility) by $n$ depends only on [remainders](https://ourbigbook.com/codex/remainder) [modulo](https://ourbigbook.com/codex/modulo-operation) $n$, so the real problem is to understand the orbit of a [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) on [remainder](https://ourbigbook.com/codex/remainder) triples.

## Mathematical Approach

### Tribonacci as a modular state machine

For a fixed candidate $n$, group three consecutive terms into one state:

$$S_k=(T_k,T_{k+1},T_{k+2})\bmod n.$$

The [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) then becomes the deterministic transition

$$F_n(a,b,c)=(b,c,(a+b+c)\bmod n),$$

so that $S_{k+1}=F_n(S_k)$ with starting state $S_1=(1,1,1)\bmod n$. This is the natural [state space](https://ourbigbook.com/codex/state-space) for the problem because the next term depends on exactly the previous three terms and on nothing else.

### When does $n$ divide a Tribonacci term?

For every $m\ge 3$, the term $T_m$ appears as the third coordinate of a state:

$$S_{m-2}=(T_{m-2},T_{m-1},T_m)\bmod n.$$

Therefore

$$n\mid T_m \quad \Longleftrightarrow \quad \text{the orbit of } S_1 \text{ contains a state with third coordinate } 0.$$

This is why the implementations only inspect the newest [remainder](https://ourbigbook.com/codex/remainder) in each triple. A zero in the first or second coordinate would simply be a third coordinate from one or two steps earlier, and the initial state $(1,1,1)$ clearly contains no zero for the odd candidates being tested.

### Why each candidate can be decided by a finite search

[Modulo](https://ourbigbook.com/codex/modulo-operation) $n$, there are only $n^3$ possible [remainder](https://ourbigbook.com/codex/remainder) triples. Since the transition $F_n$ is deterministic, once a state repeats, the entire future orbit repeats as well. That means the [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) sequence [modulo](https://ourbigbook.com/codex/modulo-operation) $n$ is periodic at the level of triples, and each odd candidate can be classified after exploring only a finite orbit.

If a zero third coordinate appears before the orbit closes, then $n$ divides some [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) term. If the orbit closes first and no third coordinate was zero anywhere on that [closed walk](https://ourbigbook.com/codex/closed-walk), then zero will never appear later either, so $n$ is a [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) non-divisor.

### Worked example: one divisor and one non-divisor

The state model makes small examples transparent. For $n=9$, the first few states are

$$
    (1,1,1)\to(1,1,3)\to(1,3,5)\to(3,5,0).
  $$

The third coordinate becomes 0 in the state $(T_4,T_5,T_6)\bmod 9$, so $9\mid T_6$. Thus 9 is rejected immediately.

For $n=27$, the orbit begins

$$
    (1,1,1)\to(1,1,3)\to(1,3,5)\to(3,5,9)\to(5,9,17)\to(9,17,4)\to\cdots
  $$

and the full modular orbit eventually returns to an earlier state without ever producing a third coordinate 0. So 27 is accepted. In fact, it is the first [odd integer](https://ourbigbook.com/codex/odd-integer) with the required non-divisibility property.

### Why Floyd's cycle detection is the right tool

The orbit is generated by repeatedly applying the same transition $F_n$, so it is exactly the setting for Floyd's [Floyd's cycle-finding algorithm](https://ourbigbook.com/codex/floyd-s-cycle-finding-algorithm). One pointer advances by one state and the other by two. This finds a repeated state using constant memory instead of storing every triple encountered so far.

At the same time, the implementations watch the third coordinate of the visited states. If either pointer reaches a triple whose newest [remainder](https://ourbigbook.com/codex/remainder) is 0, the candidate is immediately known to divide a [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) term. If the two pointers meet first, the code has found a cycle and then checks that cycle once to confirm that no state on it has third coordinate 0.

## How the Code Works

### Testing one odd candidate

The C++, Python, and Java implementations all test a single odd $n$ in the same way. They represent the current [remainder](https://ourbigbook.com/codex/remainder) triple $(a,b,c)$, advance it by the modular [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) transition, and initialize Floyd's slow and fast pointers from the start state $(1,1,1)\bmod n$.

After initialization, the implementation loops until one of two events occurs. If the newest [remainder](https://ourbigbook.com/codex/remainder) becomes 0, the candidate is classified as a [divisor](https://ourbigbook.com/codex/divisor) and the test stops immediately. Otherwise the slow and fast pointers eventually meet, which proves that the orbit has entered a cycle. The code then walks once around that cycle, checking every state's third coordinate before declaring the candidate a non-divisor.

That second pass is important. The meeting point only tells us that a cycle exists; it does not by itself guarantee that every state on the cycle has been inspected for a zero [remainder](https://ourbigbook.com/codex/remainder). The implementations therefore verify the entire loop explicitly.

### Searching for the target odd non-divisor

Outside the single-candidate test, the [algorithm](https://ourbigbook.com/codex/algorithm) simply scans the [odd integers](https://ourbigbook.com/codex/odd-integer)

$$3,5,7,9,\dots$$

because the problem asks specifically for odd $n$. Each [odd number](https://ourbigbook.com/codex/odd-number) is tested independently. Whenever the [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) orbit [modulo](https://ourbigbook.com/codex/modulo-operation) that $n$ closes without hitting a third coordinate 0, the counter of successful candidates is increased by one.

The search ends as soon as the required count is reached. The three language versions differ only in syntax; they implement the same state transition, the same [cycle detection](https://ourbigbook.com/codex/cycle-detection), and the same outer scan over odd candidates.

## Complexity Analysis

For one fixed $n$, the [state space](https://ourbigbook.com/codex/state-space) has at most $n^3$ triples. Let $p_n$ be the number of transitions examined before the orbit repeats. Then $p_n\le n^3$, and [Floyd's cycle-finding algorithm](https://ourbigbook.com/codex/floyd-s-cycle-finding-algorithm) uses $O(p_n)$ state updates plus one additional traversal of the detected cycle. The worst-case time for one candidate is therefore $O(n^3)$.

The [memory usage](https://ourbigbook.com/codex/memory-usage) is $O(1)$: only a handful of [remainder](https://ourbigbook.com/codex/remainder) triples and counters are stored. If $A_t$ denotes the $t$-th odd [Tribonacci](https://ourbigbook.com/codex/tribonacci-number) non-divisor, the total work of finding it is

$$
    O\!\left(\sum_{\substack{3\le n\le A_t\\2\nmid n}} p_n\right),
  $$

with the crude [upper bound](https://ourbigbook.com/codex/upper-bound) $O(A_t^4)$ coming from $p_n\le n^3$. In practice the periods are much shorter than the full state-space bound, so the search is easily feasible for the required target.
