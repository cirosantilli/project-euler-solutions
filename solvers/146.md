# Project Euler 146 Solution - Investigating a Prime Pattern

<https://projecteuler.net/problem=146>:

* [146.py](146.py)

## Problem Summary

We seek the sum of all [integers](https://ourbigbook.com/codex/integer) $n < 150{,}000{,}000$ for which the six values $$n^2+1,\ n^2+3,\ n^2+7,\ n^2+9,\ n^2+13,\ n^2+27$$ are [prime](https://ourbigbook.com/codex/prime), while the odd values between them, $$n^2+5,\ n^2+11,\ n^2+15,\ n^2+17,\ n^2+19,\ n^2+21,\ n^2+23,\ n^2+25,$$ are [composite](https://ourbigbook.com/codex/composite-number). Because the [primes](https://ourbigbook.com/codex/prime) must be consecutive inside that window, those eight exclusions are part of the definition of a valid $n$, not an optional afterthought.

A [brute-force search](https://ourbigbook.com/codex/brute-force-search) would examine far too many large numbers near $2.25\times 10^{16}$. The successful strategy is to force $n$ into a tiny set of [residue classes](https://ourbigbook.com/codex/residue-class), precompute modular obstructions for many small [primes](https://ourbigbook.com/codex/prime), and reserve exact [primality testing](https://ourbigbook.com/codex/primality-testing) for the few candidates that survive all cheap filters.

## Mathematical Approach

Let $$G=\{1,3,7,9,13,27\},\qquad C=\{5,11,15,17,19,21,23,25\}.$$ Then $n$ is a solution exactly when $n^2+g$ is [prime](https://ourbigbook.com/codex/prime) for every $g\in G$ and $n^2+c$ is [composite](https://ourbigbook.com/codex/composite-number) for every $c\in C$.

### The required and forbidden offsets

If $n$ is even, then $n^2$ is even, so every even offset produces an [even number](https://ourbigbook.com/codex/even-number) greater than 2 and is automatically [composite](https://ourbigbook.com/codex/composite-number). That is why only the odd offsets matter. The implementation therefore tracks two explicit sets: the six offsets that must produce [primes](https://ourbigbook.com/codex/prime) and the eight odd offsets in the same interval that must not.

### Congruence restrictions from small primes

Several modular arguments remove almost all [integers](https://ourbigbook.com/codex/integer) before any [primality test](https://ourbigbook.com/codex/primality-test) is attempted.

If $n$ were odd, then $n^2+1$ would be even and larger than 2, so $n$ must be even.

[Modulo](https://ourbigbook.com/codex/modulo-operation) 5, the [quadratic residues](https://ourbigbook.com/codex/quadratic-residue) are $0,1,4$. If $n^2\equiv 1\pmod 5$, then $n^2+9\equiv 0\pmod 5$. If $n^2\equiv 4\pmod 5$, then $n^2+1\equiv 0\pmod 5$. Therefore the only surviving case is $n^2\equiv 0\pmod 5$, which forces $5\mid n$.

[Modulo](https://ourbigbook.com/codex/modulo-operation) 3, a multiple of 3 would make $n^2+3$, $n^2+9$, and $n^2+27$ divisible by 3, so $3\nmid n$.

The strongest restriction comes from [modulo](https://ourbigbook.com/codex/modulo-operation) 7. The [quadratic residues](https://ourbigbook.com/codex/quadratic-residue) mod 7 are $0,1,2,4$. If $n^2\equiv 0\pmod 7$, then $n^2+7$ is divisible by 7. If $n^2\equiv 1\pmod 7$, then $n^2+13\equiv 0\pmod 7$. If $n^2\equiv 4\pmod 7$, then $n^2+3\equiv 0\pmod 7$. Only $n^2\equiv 2\pmod 7$ survives, which is equivalent to $n\equiv \pm 3\pmod 7$.

Combining $2\mid n$, $5\mid n$, and $n\equiv \pm 3\pmod 7$ leaves exactly two [arithmetic progressions](https://ourbigbook.com/codex/arithmetic-progression): $$n\equiv 10 \pmod{70}\qquad\text{or}\qquad n\equiv 60 \pmod{70}.$$ The same mod-7 argument automatically makes $n^2+5$ and $n^2+19$ divisible by 7, so two forbidden offsets are eliminated for free.

### Worked example: $n=10$

The smallest candidate already exhibits the full pattern. For $n=10$, we have $n^2=100$, so the required values are $$101,\ 103,\ 107,\ 109,\ 113,\ 127,$$ and each of them is [prime](https://ourbigbook.com/codex/prime). The forbidden odd offsets give $$105,\ 111,\ 115,\ 117,\ 119,\ 121,\ 123,\ 125,$$ and each of those is [composite](https://ourbigbook.com/codex/composite-number). So $10$ is a genuine solution and a concrete illustration of the exact condition being tested.

### A residue sieve for many small primes

The fixed mod-70 reduction is only the first layer. For each small [prime](https://ourbigbook.com/codex/prime) $p$ up to 2000, the implementations precompute the bad [remainder](https://ourbigbook.com/codex/remainder) set $$R_p=\{r\in\{0,\dots,p-1\}: r^2+g\equiv 0\pmod p\text{ for some }g\in G\}.$$ If $n\bmod p\in R_p$, then at least one required value is divisible by $p$, so the candidate can be discarded immediately.

[Primes](https://ourbigbook.com/codex/prime) 2 and 5 are omitted from this table because [divisibility](https://ourbigbook.com/codex/divisibility) by them has already been absorbed into the forced form $n\equiv 0\pmod{10}$. For very small $n$, an [integer congruence](https://ourbigbook.com/codex/integer-congruence) $n^2+g\equiv 0\pmod p$ could still mean $n^2+g=p$, which is [prime](https://ourbigbook.com/codex/prime) rather than [composite](https://ourbigbook.com/codex/composite-number). The implementations avoid that edge case by activating these precomputed tables only once $n\ge 1000$, a conservative threshold well above $\sqrt{2000}$.

### Exact verification after filtering

After the modular screens, the surviving candidates are rare. Each survivor is then checked exactly: the six values $n^2+g$ must be [prime](https://ourbigbook.com/codex/prime) and the eight values $n^2+c$ must be [composite](https://ourbigbook.com/codex/composite-number). Since $$n^2+27 < (150{,}000{,}000)^2+27 < 2.25\times 10^{16},$$ every tested [integer](https://ourbigbook.com/codex/integer) fits comfortably in 64-bit arithmetic, so fast [Miller-Rabin](https://ourbigbook.com/codex/miller-rabin-primality-test) based certification is practical for the last stage.

## How the Code Works

### Scanning only the two valid progressions

The C++, Python, and Java implementations iterate only over the sequences $70m+10$ and $70m+60$. This is the direct payoff of the [integer congruence](https://ourbigbook.com/codex/integer-congruence) analysis: instead of checking all [integers](https://ourbigbook.com/codex/integer), the search immediately keeps only about one out of every 35 candidates.

### Maintaining squares and modular states incrementally

Inside one progression, the [common difference](https://ourbigbook.com/codex/common-difference) is always 70, so the square is updated by the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) $$ (n+70)^2=n^2+140n+4900.$$ That avoids recomputing $n^2$ from scratch. The same incremental idea is used for every small-prime filter: if the current [remainder](https://ourbigbook.com/codex/remainder) [modulo](https://ourbigbook.com/codex/modulo-operation) $p$ is known, the next one is obtained by adding $70\bmod p$. The [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) phase therefore becomes a sequence of cheap table lookups instead of repeated modular squaring.

### The decision pipeline and parallel search

Each candidate passes through a short pipeline: inexpensive [divisibility](https://ourbigbook.com/codex/divisibility) checks for 3 and 13, lookup in the precomputed bad-residue tables, exact [primality tests](https://ourbigbook.com/codex/primality-test) on the six required offsets, and exact compositeness checks on the eight forbidden offsets. When every condition succeeds, the candidate $n$ is added to the running sum.

The interval splits naturally into independent chunks. The C++ and Java implementations parallelize those chunks directly, and the Python implementation can also distribute chunks across worker processes. The mathematics is identical in all three languages; only the execution strategy changes.

## Complexity Analysis

Let $L$ be the search limit and $B$ the [upper bound](https://ourbigbook.com/codex/upper-bound) for the small-prime [remainder](https://ourbigbook.com/codex/remainder) tables. Building the tables costs $O(B\log\log B+\sum_{p\le B} p)$ time and $O(\sum_{p\le B} p)$ memory, because each [prime](https://ourbigbook.com/codex/prime) $p$ stores a boolean array of length $p$.

The main scan visits only about $L/35$ [integers](https://ourbigbook.com/codex/integer) because it uses two [residue classes](https://ourbigbook.com/codex/residue-class) [modulo](https://ourbigbook.com/codex/modulo-operation) 70. For each candidate it performs constant-time arithmetic plus one [remainder](https://ourbigbook.com/codex/remainder) update per [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) [prime](https://ourbigbook.com/codex/prime), and only a tiny fraction survive to the [primality](https://ourbigbook.com/codex/primality) stage. With the fixed choice $B=2000$ used by the implementations, [memory usage](https://ourbigbook.com/codex/memory-usage) stays small and the [running time](https://ourbigbook.com/codex/running-time) is effectively linear in the search limit.
