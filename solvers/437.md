# Project Euler 437 Solution - Fibonacci Primitive Roots

<https://projecteuler.net/problem=437>:

* [437.py](437.py)

A number `g` is a **[Fibonacci primitive root](https://ourbigbook.com/codex/fibonacci-primitive-root)** [modulo](https://ourbigbook.com/codex/modulo-operation) a [prime](https://ourbigbook.com/codex/prime) `p` if:

1. `g` is a [primitive root](https://ourbigbook.com/codex/primitive-root) mod `p` (its [multiplicative order](https://ourbigbook.com/codex/multiplicative-order) is `p−1`), and
2. the powers of `g` satisfy Fibonacci’s [recurrence relation](https://ourbigbook.com/codex/recurrence-relation), which is equivalent to  
   `g² ≡ g + 1 (mod p)`.

The task is to compute the sum of all [primes](https://ourbigbook.com/codex/prime) `p < 100,000,000` that have **at least one** [Fibonacci primitive root](https://ourbigbook.com/codex/fibonacci-primitive-root).

## Key techniques used

### 1) Reduce the “Fibonacci” condition to a quadratic congruence
From `g² ≡ g + 1 (mod p)`, multiplying by `gⁿ` yields `gⁿ + gⁿ⁺¹ ≡ gⁿ⁺²`, so it’s enough to solve:

- `g² − g − 1 ≡ 0 (mod p)`

Thus any [Fibonacci primitive root](https://ourbigbook.com/codex/fibonacci-primitive-root) must be one of the two roots of this quadratic (when roots exist).

### 2) Use quadratic reciprocity to pre-filter primes
The quadratic has solutions iff its [discriminant](https://ourbigbook.com/codex/discriminant) is a [quadratic residue](https://ourbigbook.com/codex/quadratic-residue):

- [Discriminant](https://ourbigbook.com/codex/discriminant) = `5`
- Since `5 ≡ 1 (mod 4)`, we have `(5/p) = (p/5)`
- [Quadratic residues](https://ourbigbook.com/codex/quadratic-residue) mod `5` are `1` and `4`

So for `p ≠ 5`, solutions exist only when:

- `p ≡ 1 or 4 (mod 5)`  

This eliminates about half of all [primes](https://ourbigbook.com/codex/prime) immediately.

### 3) Modular square roots with Tonelli–Shanks
For [primes](https://ourbigbook.com/codex/prime) with `p ≡ 1 (mod 4)`, computing `√5 (mod p)` uses the **[Tonelli–Shanks](https://ourbigbook.com/codex/tonelli-shanks-algorithm)** [algorithm](https://ourbigbook.com/codex/algorithm).
For `p ≡ 3 (mod 4)`, a shortcut exists:

- `√5 ≡ 5^((p+1)/4) (mod p)`

The two roots are then:

- `(1 ± √5) / 2 (mod p)` (using `inv2 = (p+1)/2` for [division](https://ourbigbook.com/codex/division) by 2)

### 4) Primitive root test via factorization of `p−1`
An element `g` is a [primitive root](https://ourbigbook.com/codex/primitive-root) iff for every [prime](https://ourbigbook.com/codex/prime) [divisor](https://ourbigbook.com/codex/divisor) `q` of `p−1`:

- `g^((p−1)/q) ≠ 1 (mod p)`

So the [algorithm](https://ourbigbook.com/codex/algorithm) factors `p−1` into distinct [prime factors](https://ourbigbook.com/codex/prime-factor) and performs these [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation) checks for each of the (at most) two quadratic roots.

To keep factorization fast, the code:
- strips small [primes](https://ourbigbook.com/codex/prime) quickly, then
- uses a deterministic 32-bit [Miller–Rabin test](https://ourbigbook.com/codex/miller-rabin-primality-test) to stop early when the remaining cofactor is already [prime](https://ourbigbook.com/codex/prime).

### 5) Segmented sieve for primes up to `1e8`
Generating [primes](https://ourbigbook.com/codex/prime) up to `100,000,000` is done with a **[segmented sieve of Eratosthenes](https://ourbigbook.com/codex/segmented-sieve)** over [odd numbers](https://ourbigbook.com/codex/odd-number) only. This keeps memory usage manageable while still being fast.

## Built-in checks from the statement

The solution asserts the two values given in the problem statement:

- `8` is a [Fibonacci primitive root](https://ourbigbook.com/codex/fibonacci-primitive-root) of `11`
- There are `323` such [primes](https://ourbigbook.com/codex/prime) below `10,000` and their sum is `1,480,491`

