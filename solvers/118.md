# Project Euler 118 Solution - Pandigital Prime Sets

<https://projecteuler.net/problem=118>:

* [118.py](118.py)

## Problem Summary

We must use the [digits](https://ourbigbook.com/codex/numerical-digit) $1,2,\dots,9$ exactly once in total, split them into several [decimal](https://ourbigbook.com/codex/decimal) [integers](https://ourbigbook.com/codex/integer), and require every resulting [integer](https://ourbigbook.com/codex/integer) to be [prime](https://ourbigbook.com/codex/prime-number). The goal is to count how many *[sets](https://ourbigbook.com/codex/set)* of [primes](https://ourbigbook.com/codex/prime-number) are possible, so the collection $\{23,461,5879\}$ is the same [set](https://ourbigbook.com/codex/set) regardless of the order in which its members are discovered.

The brute-force view is enormous: every ordered [string](https://ourbigbook.com/codex/string) of distinct [digits](https://ourbigbook.com/codex/numerical-digit) might be one block in the [set partition](https://ourbigbook.com/codex/set-partition), and a full solution must somehow organize all compatible [prime](https://ourbigbook.com/codex/prime-number) blocks into unordered covers of $\{1,\dots,9\}$. The implementations solve this by separating the problem into two layers: first generate every [prime](https://ourbigbook.com/codex/prime-number) whose [digits](https://ourbigbook.com/codex/numerical-digit) are distinct and taken from $1$ through $9$, then count [exact covers](https://ourbigbook.com/codex/exact-cover) of the [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set) with a memoized [recurrence relation](https://ourbigbook.com/codex/recurrence-relation).

## Mathematical Approach

The decisive mathematical objects are the family of admissible [prime](https://ourbigbook.com/codex/prime-number) blocks and a [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) on the remaining [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set). Once those are identified, the whole problem becomes a small [exact-cover](https://ourbigbook.com/codex/exact-cover) [dynamic program](https://ourbigbook.com/codex/dynamic-program) on $2^9$ [bit masks](https://ourbigbook.com/codex/bit-mask).

### The Candidate Prime Family

Let $\mathcal{P}$ be the [set](https://ourbigbook.com/codex/set) of all [primes](https://ourbigbook.com/codex/prime-number) whose [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) uses distinct [digits](https://ourbigbook.com/codex/numerical-digit) drawn from $\{1,\dots,9\}$. For each $p\in\mathcal{P}$, let $D(p)\subseteq\{1,\dots,9\}$ be the [set](https://ourbigbook.com/codex/set) of [digits](https://ourbigbook.com/codex/numerical-digit) appearing in $p$.

Every valid [pandigital prime](https://ourbigbook.com/codex/pandigital-prime) [set](https://ourbigbook.com/codex/set) is therefore a collection $\{p_1,\dots,p_r\}\subseteq\mathcal{P}$ such that

$$D(p_1)\sqcup D(p_2)\sqcup\cdots\sqcup D(p_r)=\{1,\dots,9\},$$

where $\sqcup$ denotes [disjoint union](https://ourbigbook.com/codex/disjoint-union). So the original problem is equivalent to counting all [exact covers](https://ourbigbook.com/codex/exact-cover) of the [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set) by digit-disjoint members of $\mathcal{P}$.

The recursive generator used in the implementations produces $\mathcal{P}$ directly: start from the [empty string](https://ourbigbook.com/codex/empty-string), append one unused [digit](https://ourbigbook.com/codex/numerical-digit) at a time, and whenever the current prefix is [prime](https://ourbigbook.com/codex/prime-number), store it as an admissible block. Because every ordered sequence of distinct [digits](https://ourbigbook.com/codex/numerical-digit) is reached exactly once, every possible [prime](https://ourbigbook.com/codex/prime-number) block appears exactly once in this [search tree](https://ourbigbook.com/codex/search-tree).

### The Set-Counting Recurrence

For any [subset](https://ourbigbook.com/codex/subset) $S\subseteq\{1,\dots,9\}$, define $F(S)$ to be the number of [pandigital prime](https://ourbigbook.com/codex/pandigital-prime) [sets](https://ourbigbook.com/codex/set) that use exactly the [digits](https://ourbigbook.com/codex/numerical-digit) in $S$. The target is $F(\{1,\dots,9\})$, and the [empty set](https://ourbigbook.com/codex/empty-set) has the natural base value

$$F(\varnothing)=1,$$

because there is exactly one way to cover no [digits](https://ourbigbook.com/codex/numerical-digit): choose no more [primes](https://ourbigbook.com/codex/prime-number).

Now let $m(S)=\min S$, the smallest remaining [digit](https://ourbigbook.com/codex/numerical-digit). In any valid [set partition](https://ourbigbook.com/codex/set-partition) of $S$, exactly one [prime](https://ourbigbook.com/codex/prime-number) block contains that [digit](https://ourbigbook.com/codex/numerical-digit). This gives the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation)

$$F(S)=\sum_{\substack{p\in\mathcal{P}\\ D(p)\subseteq S\\ m(S)\in D(p)}} F\bigl(S\setminus D(p)\bigr).$$

This is the key [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics) behind the code. It removes duplicate counting without imposing any ordering on [prime](https://ourbigbook.com/codex/prime-number) values: every unordered [prime](https://ourbigbook.com/codex/prime-number) [set](https://ourbigbook.com/codex/set) has a unique first step, namely the block that contains the smallest still-uncovered [digit](https://ourbigbook.com/codex/numerical-digit). The implementations realize the same idea with a [bitmask](https://ourbigbook.com/codex/bit-mask) and its least significant set bit.

### Why This Counts Sets Rather Than Sequences

Suppose a valid solution is the [set](https://ourbigbook.com/codex/set) $\{p_1,\dots,p_r\}$. If we tried to build it by freely choosing the next block, the same [set](https://ourbigbook.com/codex/set) would appear in $r!$ different orders. The anchor rule avoids that completely. At the top level, the chosen block must be the unique one containing [digit](https://ourbigbook.com/codex/numerical-digit) $1$. After removing that block, the next chosen block must be the unique one containing the smallest [digit](https://ourbigbook.com/codex/numerical-digit) not yet used, and so on.

So every valid [set](https://ourbigbook.com/codex/set) determines exactly one [graph path](https://ourbigbook.com/codex/graph-path) through the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation), and every [graph path](https://ourbigbook.com/codex/graph-path) clearly reconstructs a valid [set](https://ourbigbook.com/codex/set) of digit-disjoint [primes](https://ourbigbook.com/codex/prime-number). That proves a [bijection](https://ourbigbook.com/codex/bijection) between solutions and [recursion](https://ourbigbook.com/codex/recursion) [graph paths](https://ourbigbook.com/codex/graph-path).

### The Search Space Is Large but Fixed

The [prime](https://ourbigbook.com/codex/prime-number) generator explores every non-empty ordered [string](https://ourbigbook.com/codex/string) of distinct [digits](https://ourbigbook.com/codex/numerical-digit) from $1$ through $9$. The exact number of such prefixes is

$$\sum_{k=1}^{9} P(9,k)=\sum_{k=1}^{9}\frac{9!}{(9-k)!}=986409.$$

Only a small [fraction](https://ourbigbook.com/codex/fraction) survive the [primality test](https://ourbigbook.com/codex/primality-test); for the full problem the candidate list contains 43089 admissible [primes](https://ourbigbook.com/codex/prime-number). Also, no 9-digit candidate can survive, because every [permutation](https://ourbigbook.com/codex/permutation) of $1,\dots,9$ has [digit sum](https://ourbigbook.com/codex/digit-sum) $45$ and is therefore divisible by $9$. Once the candidate list is known, the counting phase has only $2^9=512$ remaining-digit states.

### Worked Example: Digits $1,2,3,4$

The smaller instance on [digits](https://ourbigbook.com/codex/numerical-digit) $\{1,2,3,4\}$ is useful because the same [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) already shows the whole mechanism. Here the smallest remaining [digit](https://ourbigbook.com/codex/numerical-digit) is always the anchor [digit](https://ourbigbook.com/codex/numerical-digit) $1$ at the top level. The admissible [prime](https://ourbigbook.com/codex/prime-number) blocks containing $1$ are

$$13,\ 31,\ 41,\ 241,\ 421,\ 431,\ 1423,\ 2143,\ 2341,\ 4231.$$

The first two leave the [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set) $\{2,4\}$, which has no [prime](https://ourbigbook.com/codex/prime-number) cover, so those branches contribute $0$. The others give

$$\begin{aligned}
F(\{1,2,3,4\})={}&F(\{2,3\})+F(\{3\})+F(\{3\})+F(\{2\}) \\
&+F(\varnothing)+F(\varnothing)+F(\varnothing)+F(\varnothing).
\end{aligned}$$

Now $F(\{3\})=1$ because $\{3\}$ itself is [prime](https://ourbigbook.com/codex/prime-number), $F(\{2\})=1$, and

$$F(\{2,3\})=F(\{3\})+F(\varnothing)=2,$$

coming from the covers $\{2,3\}$ and $\{23\}$. Therefore

$$F(\{1,2,3,4\})=2+1+1+1+1+1+1+1=9.$$

The nine corresponding [sets](https://ourbigbook.com/codex/set) are $\{2,3,41\}$, $\{23,41\}$, $\{3,241\}$, $\{3,421\}$, $\{2,431\}$, $\{1423\}$, $\{2143\}$, $\{2341\}$, and $\{4231\}$. This is exactly the checkpoint used by the parameterized implementation before it runs the full $1$ through $9$ case.

## How the Code Works

### Generating the Prime Blocks

The C++, Python, and Java implementations first enumerate [digit](https://ourbigbook.com/codex/numerical-digit) [strings](https://ourbigbook.com/codex/string) recursively. Starting from value $0$ and an empty used-digit [bit mask](https://ourbigbook.com/codex/bit-mask), they append one unused [digit](https://ourbigbook.com/codex/numerical-digit) to the right, forming a new [decimal](https://ourbigbook.com/codex/decimal) prefix. Whenever that prefix is [prime](https://ourbigbook.com/codex/prime-number), the implementation stores the pair consisting of the [prime](https://ourbigbook.com/codex/prime-number) value and the [bit mask](https://ourbigbook.com/codex/bit-mask) of [digits](https://ourbigbook.com/codex/numerical-digit) used by that value. The [recursion](https://ourbigbook.com/codex/recursion) then continues, because a [prime](https://ourbigbook.com/codex/prime-number) prefix can still be extended into a longer [prime](https://ourbigbook.com/codex/prime-number) built from additional unused [digits](https://ourbigbook.com/codex/numerical-digit).

After generation, the candidate list is normalized to unique pairs before the counting stage. Conceptually, this list is just the [finite set](https://ourbigbook.com/codex/finite-set) $\mathcal{P}$ together with the [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set) $D(p)$ attached to each member.

### Memoized Counting on Masks

The second phase replaces [digit](https://ourbigbook.com/codex/numerical-digit) [subsets](https://ourbigbook.com/codex/subset) by 9-bit [bit masks](https://ourbigbook.com/codex/bit-mask). A [bit mask](https://ourbigbook.com/codex/bit-mask) represents the [digits](https://ourbigbook.com/codex/numerical-digit) that still need to be covered. The empty [bit mask](https://ourbigbook.com/codex/bit-mask) returns $1$. For any non-empty [bit mask](https://ourbigbook.com/codex/bit-mask), the implementation extracts its least significant set bit, which is the smallest remaining [digit](https://ourbigbook.com/codex/numerical-digit), and scans the stored [prime](https://ourbigbook.com/codex/prime-number) blocks. A block contributes only if its digit [bit mask](https://ourbigbook.com/codex/bit-mask) is a [subset](https://ourbigbook.com/codex/subset) of the remaining [bit mask](https://ourbigbook.com/codex/bit-mask) and also contains the anchor bit.

Whenever those two conditions hold, the code removes that block's [digits](https://ourbigbook.com/codex/numerical-digit) from the remaining [bit mask](https://ourbigbook.com/codex/bit-mask) and recurses. The result is memoized by [bit mask](https://ourbigbook.com/codex/bit-mask), so each remaining-digit state is solved once. This is a direct bit-level implementation of the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) for $F(S)$ above.

### Primality Testing in the Three Languages

The C++ and Java implementations use straightforward [trial division](https://ourbigbook.com/codex/trial-division) up to $\sqrt{n}$. That is sufficient here because every candidate is less than $10^9$, so $\sqrt{n}\lt 31623$. The Python implementation uses a library [primality](https://ourbigbook.com/codex/primality) routine, but the surrounding [combinatorics](https://ourbigbook.com/codex/combinatorics) and the [bit mask](https://ourbigbook.com/codex/bit-mask) [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) are the same in all three languages.

## Complexity Analysis

Candidate generation visits exactly 986409 non-empty [digit](https://ourbigbook.com/codex/numerical-digit) prefixes. If we write $T_{\mathrm{prime}}(x)$ for the cost of one [primality test](https://ourbigbook.com/codex/primality-test) at magnitude $x$, the generation phase is

$$O\!\left(\sum_{k=1}^{9} P(9,k)\cdot T_{\mathrm{prime}}(10^k)\right).$$

In the concrete implementations, [trial division](https://ourbigbook.com/codex/trial-division) makes $T_{\mathrm{prime}}(10^k)=O(10^{k/2})$ in C++ and Java, while Python delegates this step to its [primality](https://ourbigbook.com/codex/primality) library.

After that, the [dynamic program](https://ourbigbook.com/codex/dynamic-program) has only 512 memo states. The stored candidate list has 43089 [prime](https://ourbigbook.com/codex/prime-number) blocks, and each state performs a linear scan through that list with [constant-time](https://ourbigbook.com/codex/constant-time) [bit mask](https://ourbigbook.com/codex/bit-mask) tests. So the counting phase is $O(512\cdot 43089)$ simple compatibility checks for the full problem, with memory $O(512+43089)$.

More generally, if the [digit](https://ourbigbook.com/codex/numerical-digit) [set](https://ourbigbook.com/codex/set) were $\{1,\dots,n\}$, the same method would use $2^n$ memo states and enumerate $\sum_{k=1}^{n} P(n,k)$ candidate prefixes. For $n=9$, that fixed search space is small enough that this [exact-cover](https://ourbigbook.com/codex/exact-cover) approach is entirely practical.
