# Bitwise meta-problem solution

Run:

```bash
python3 main.py
```

The script uses no external libraries. It checks every numerical example supplied in the statement with `assert` and prints only the requested meta-problem result.

## Main techniques

### 1. Max And: optimize one bit at a time

The contribution of bit `b` depends only on how many numbers carrying that bit are placed in each group. If `count` numbers in `1..n` contain the bit, the largest possible contribution is obtained by splitting those numbers as evenly as possible:

```text
(1 << b) * floor(count / 2) * ceil(count / 2)
```

These per-bit [upper bounds](https://ourbigbook.com/codex/upper-bound) can all be attained simultaneously: partition the [integers](https://ourbigbook.com/codex/integer) by the [integer parity](https://ourbigbook.com/codex/integer-parity) of their [population count](https://ourbigbook.com/codex/hamming-weight). For any fixed bit, pairing values by a different toggled bit balances the two population-count [integer parities](https://ourbigbook.com/codex/integer-parity), with at most one unpaired value. Therefore `max_and` sums the independent per-bit maxima.

### 2. Max Xor Sum: longest increasing walk in a weighted graph

Treat each [integer](https://ourbigbook.com/codex/integer) as a [graph vertex](https://ourbigbook.com/codex/graph-vertex). The undirected [edge](https://ourbigbook.com/codex/edge-of-a-graph) between `x` and `y` has weight:

```text
(x * x) XOR (y * y)
```

A valid [sequence](https://ourbigbook.com/codex/sequence) is a walk whose [edge](https://ourbigbook.com/codex/edge-of-a-graph) weights strictly increase. Sort all [edges](https://ourbigbook.com/codex/edge-of-a-graph) by weight and apply [dynamic programming](https://ourbigbook.com/codex/dynamic-programming):

```text
best[v] = largest sum of an increasing walk ending at vertex v
```

For an [edge](https://ourbigbook.com/codex/edge-of-a-graph) `(u, v)` of weight `w`, possible updates are `best[u] + w` into `v` and `best[v] + w` into `u`. All [edges](https://ourbigbook.com/codex/edge-of-a-graph) with the same weight are staged before committing updates, because equal-weight [edges](https://ourbigbook.com/codex/edge-of-a-graph) may not be chained. [Edges](https://ourbigbook.com/codex/edge-of-a-graph) are packed into [integers](https://ourbigbook.com/codex/integer) before [sorting](https://ourbigbook.com/codex/sorting) to reduce [memory usage](https://ourbigbook.com/codex/memory-usage).

### 3. Unreachable Nim: highest-XOR-bit characterization plus digit DP

Let:

```text
x = a XOR b XOR c
```

A nonzero-XOR position can be reached from a zero-XOR predecessor exactly when one pile could have been reduced from the matching pairwise [XOR](https://ourbigbook.com/codex/xor). It is unreachable precisely when:

```text
a >= (b XOR c)
b >= (a XOR c)
c >= (a XOR b)
```

Since `b XOR c = a XOR x`, compare each pile with itself [XOR](https://ourbigbook.com/codex/xor) `x`. At the highest set bit of `x`, the comparison succeeds exactly when that pile has a `1`. Thus an unreachable triple has:

- even [XOR](https://ourbigbook.com/codex/xor) [integer parity](https://ourbigbook.com/codex/integer-parity) in every bit above the highest set bit of `x`;
- the pattern `111` at that highest set bit;
- arbitrary lower bits.

A small [binary digit DP](https://ourbigbook.com/codex/binary-digit-dp) counts bounded triples for every possible highest [XOR](https://ourbigbook.com/codex/xor) bit while tracking which pile prefixes are still equal to the [upper bound](https://ourbigbook.com/codex/upper-bound).

### 4. Meta recurrence: reduce after every multiplication

After computing the three starting values, the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) is evaluated iteratively. Each product is reduced [modulo](https://ourbigbook.com/codex/modulo-operation) `1_000_000_007`, keeping the [integers](https://ourbigbook.com/codex/integer) small while preserving the required result.
