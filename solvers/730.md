# Project Euler 730 Solution - Shifted Pythagorean Triples

<https://projecteuler.net/problem=730>:

* [730.py](730.py)

This solution counts *primitive* [integer](https://ourbigbook.com/codex/integer) triples \((p,q,r)\) with:

- \(p^2 + q^2 + k = r^2\)
- \(1 \le p \le q \le r\)
- \(p + q + r \le n\)
- \(\gcd(p,q,r)=1\)

Define \(P_k(n)\) as the number of such triples for a fixed \(k\), and
\(S(m,n)=\sum_{k=0}^{m} P_k(n)\).

The program computes \(S(100, 10^8)\) and prints the result.

## Main ideas

### 1) Invariant-preserving 3×3 matrix generators

There are three [integer matrices](https://ourbigbook.com/codex/integer-matrix) that preserve the [quadratic form](https://ourbigbook.com/codex/quadratic-form):

\[
p^2 + q^2 - r^2
\]

That means if a triple satisfies \(p^2 + q^2 + k = r^2\), then applying any of these [matrices](https://ourbigbook.com/codex/matrix)
produces another triple with the *same* \(k\).

So for each \(k\), the primitive solutions form a [forest](https://ourbigbook.com/codex/forest) of trees:
start from a set of *[tree roots](https://ourbigbook.com/codex/root-of-a-tree)* (seed triples), then repeatedly apply the three transforms to generate
all descendants.

### 2) Root detection using inverse transforms

To avoid duplicates (and to ensure the [forest](https://ourbigbook.com/codex/forest) covers everything exactly once), we need the correct [tree roots](https://ourbigbook.com/codex/root-of-a-tree).

A triple is treated as a [root of a tree](https://ourbigbook.com/codex/root-of-a-tree) if none of the three [inverse matrices](https://ourbigbook.com/codex/inverse-matrix) maps it back to a
strictly-positive ordered triple \((p,q,r)\) with \(p \le q \le r\).
Because the transforms are [unimodular matrices](https://ourbigbook.com/codex/unimodular-matrix) ([determinant](https://ourbigbook.com/codex/determinant) \(\pm 1\)), primitiveness is preserved along the tree.

### 3) Bounded enumeration of candidate roots

For \(k \le 100\), [tree roots](https://ourbigbook.com/codex/root-of-a-tree) only occur with relatively small \(r\).
That allows generating all candidate triples in a small range of \((p,q,r)\), filtering by:

- the defining equation (via \(k = r^2 - p^2 - q^2\)),
- \(\gcd(p,q,r)=1\),
- and the "no positive parent" root test.

This finds all [tree roots](https://ourbigbook.com/codex/root-of-a-tree) needed for \(k=0..100\) efficiently.

### 4) Depth-first traversal with pruning

For each [root of a tree](https://ourbigbook.com/codex/root-of-a-tree), the code performs an explicit stack-based [depth-first traversal](https://ourbigbook.com/codex/depth-first-search):

- Count the node if its perimeter \(p+q+r \le n\).
- Generate its children.
- Skip children whose perimeter already exceeds \(n\).

Perimeters of children are computed as fixed [linear forms](https://ourbigbook.com/codex/linear-form) in \((p,q,r)\) to reduce overhead.
