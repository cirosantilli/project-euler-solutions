# Project Euler 395 Solution - Pythagorean Tree

<https://projecteuler.net/problem=395>:

* [395.py](395.py)

This solution computes the **axis-aligned bounding rectangle** (parallel to the initial [unit square](https://ourbigbook.com/codex/unit-square)) that contains the entire *infinite* 3–4–5 [Pythagorean tree](https://ourbigbook.com/codex/pythagoras-tree).

The program prints the [area](https://ourbigbook.com/codex/area), rounded to **10 decimal places**.

## Key techniques

### 1) Similarity-based square representation
Each [square](https://ourbigbook.com/codex/square) is represented by:

- `p`: the **base-left** corner (origin)
- `u`: the **base** side [vector](https://ourbigbook.com/codex/vector)
- `v`: the **outward** side [vector](https://ourbigbook.com/codex/vector) (same length as `u`, 90° CCW [rotation](https://ourbigbook.com/codex/rotation))

So the four corners are:

- `p`
- `p + u`
- `p + u + v`
- `p + v`

This handles all [rotations](https://ourbigbook.com/codex/rotation) and scales without trig.

### 2) Exact local construction for the 3–4–5 step
For a parent [square](https://ourbigbook.com/codex/square) of side length `s`, the [triangle](https://ourbigbook.com/codex/triangle) is attached to the **top** [side](https://ourbigbook.com/codex/side-of-a-polygon) with:

- [hypotenuse](https://ourbigbook.com/codex/hypotenuse) length `s`
- legs `4s/5` and `3s/5`
- *smaller leg on the right* (as required by the statement)

In the square’s local [basis](https://ourbigbook.com/codex/basis) `(u, v)` the right-angle [polygon vertex](https://ourbigbook.com/codex/vertex-of-a-polygon) is:

- `C = A + (16/25) u + (12/25) v`

where `A` is the **top-left** corner of the [square](https://ourbigbook.com/codex/square).

Two child [squares](https://ourbigbook.com/codex/square) are built on legs `A–C` and `B–C`, and oriented so they lie **outside** the [triangle](https://ourbigbook.com/codex/triangle).

### 3) Branch-and-bound pruning with a rigorous disk bound
A naive breadth-first generation grows as `2^n`. To avoid that, we prune subtrees that cannot affect the final [bounding box](https://ourbigbook.com/codex/bounding-box).

We compute a safe constant `R` such that the entire unit tree lies inside a [disk](https://ourbigbook.com/codex/disk-mathematics) of [radius](https://ourbigbook.com/codex/radius) `R` around the **root square’s center**. Using the fixed distances from parent-center to child-centers:

- `d_left  = sqrt(13/10)` (child scaled by `4/5`)
- `d_right = sqrt(29)/5`  (child scaled by `3/5`)

The [radius](https://ourbigbook.com/codex/radius) must satisfy:

- `R >= sqrt(2)/2` (covers the root [square](https://ourbigbook.com/codex/square))
- `R >= d_left  + (4/5) R`
- `R >= d_right + (3/5) R`

Solving gives:

- `R = 5 * sqrt(13/10)`

For any node [square](https://ourbigbook.com/codex/square) of side `s`, its entire infinite subtree lies inside a [disk](https://ourbigbook.com/codex/disk-mathematics) of [radius](https://ourbigbook.com/codex/radius) `s * R` around that square’s center.  
If that [disk](https://ourbigbook.com/codex/disk-mathematics) is fully inside the current global bounds (with a tiny epsilon), that node **cannot** improve `xmin/xmax/ymin/ymax`, so we skip expanding it.

### 4) Priority-driven expansion
[Squares](https://ourbigbook.com/codex/square) are expanded in **decreasing side length** order (a [max-heap](https://ourbigbook.com/codex/max-heap)), so the global bounds tighten quickly and pruning becomes effective.

## Output
Running `python3 main.py` prints the [area](https://ourbigbook.com/codex/area) to 10 decimal places.
