# Project Euler 417 Solution - Reciprocal Cycles II

<https://projecteuler.net/problem=417>:

* [417.py](417.py)

This solution computes:

\[
\sum_{3 \le n \le 100\,000\,000} L(n)
\]

where **L(n)** is the length of the [recurring cycle](https://ourbigbook.com/codex/repeating-decimal) of the [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) of **1/n**, and **L(n)=0**
when `n` has no [prime factors](https://ourbigbook.com/codex/prime-factor) other than `2` and/or `5`.

---

## Key Techniques Used

### 1) Reduce to Multiplicative Order
Write:

\[
n = 2^a 5^b m \quad \text{with } \gcd(m,10)=1
\]

Then the [decimal recurring cycle](https://ourbigbook.com/codex/repeating-decimal) length is:

\[
L(n)=\operatorname{ord}_m(10)
\]

So only the “reduced [denominator](https://ourbigbook.com/codex/denominator)” `m` ([coprime](https://ourbigbook.com/codex/coprime) to 10) matters; factors of 2 and 5 only affect the
terminating prefix.

---

### 2) Count Multiples by `2^a * 5^b`
For each reduced [denominator](https://ourbigbook.com/codex/denominator) `m`, it contributes the same cycle length to every number:

\[
m \cdot 2^a \cdot 5^b \le N
\]

So we weight each `ord_m(10)` by:

\[
g\left(\left\lfloor \frac{N}{m} \right\rfloor\right)
\]

where `g(x)` counts how many values of `2^a*5^b` are ≤ x.
All such products are precomputed (only a few hundred values), and `g(x)` is computed via [binary search](https://ourbigbook.com/codex/binary-search).

---

### 3) Smallest Prime Factor Sieve (Odd Only)
Because all reduced [denominators](https://ourbigbook.com/codex/denominator) `m` are **odd and not divisible by 5**, we only sieve **[odd numbers](https://ourbigbook.com/codex/odd-number)**,
halving memory.

We build an [SPF](https://ourbigbook.com/codex/smallest-prime-factor) table:

- `spf[i] = smallest prime factor of (2*i+1)`
- `spf[i] = 0` means `(2*i+1)` is [prime](https://ourbigbook.com/codex/prime)

---

### 4) Fast Orders for Composite Numbers via LCM
For a [composite](https://ourbigbook.com/codex/composite-number) reduced [denominator](https://ourbigbook.com/codex/denominator):

\[
m = p^e \cdot r
\]

we use:

\[
\operatorname{ord}_m(10) = \mathrm{lcm}(\operatorname{ord}_{p^e}(10), \operatorname{ord}_r(10))
\]

[Multiplicative orders](https://ourbigbook.com/codex/multiplicative-order) are computed in increasing `m`, so `ord_r(10)` is already known.

---

### 5) Prime Orders via Factorization of `p-1`
For [prime](https://ourbigbook.com/codex/prime) `p`, the [multiplicative order](https://ourbigbook.com/codex/multiplicative-order) divides `p-1`.
We factor `p-1` quickly using the [SPF](https://ourbigbook.com/codex/smallest-prime-factor) table, then shrink the candidate [multiplicative order](https://ourbigbook.com/codex/multiplicative-order) by testing:

\[
10^{k/q} \equiv 1 \pmod p
\]

for each [prime](https://ourbigbook.com/codex/prime) [divisor](https://ourbigbook.com/codex/divisor) `q` of `p-1`.

---

### 6) Prime Powers via Lifting
For powers `p^e`, the [multiplicative order](https://ourbigbook.com/codex/multiplicative-order) can only stay the same or multiply by `p` when going from `p^{e-1}` to `p^e`.
We build these values once per small [prime](https://ourbigbook.com/codex/prime) and cache them.

---

## Correctness Check (from statement)
The code asserts the given checksum:

\[
\sum_{3\le n\le 1,000,000} L(n) = 55535191115
\]

and also asserts the example cycle lengths:
- `L(6)=1`, `L(7)=6`, terminating examples yield `0`.

---

## Complexity Notes
- Memory: ~400MB (two `array('I')` tables of size ~50 million)
- Time: dominated by one pass over ~40 million reduced [denominators](https://ourbigbook.com/codex/denominator) plus prime-order computations.

---

## Final Output
Running `python3 main.py` prints the required sum for `N=100,000,000`.
