# Project Euler 428 Solution - Necklace of Circles

<https://projecteuler.net/problem=428>:

* [428.py](428.py)

This solution solves [Project Euler](https://ourbigbook.com/codex/project-euler) 428 efficiently in pure Python (no external libraries)
and avoids brute force for `T(10^9)`.

---

## 1) Geometry → Arithmetic (Steiner Necklace Criterion)

The problem asks when a triple `(a,b,c)` forms a valid **[Steiner necklace](https://ourbigbook.com/codex/steiner-chain)** between
two [circles](https://ourbigbook.com/codex/circle) determined by [collinear](https://ourbigbook.com/codex/collinearity) points. A classical result gives that
`(a,b,c)` is a necklace iff:

\[
\frac{b(a+b+c)-ac}{b(a+b+c)+ac} \in \left\{-1,-\frac12,0,\frac12,1\right\}.
\]

The cases `±1` are impossible with [positive integers](https://ourbigbook.com/codex/positive-integer), leaving only:

- `0`
- `-1/2`
- `+1/2`

Each produces a [Diophantine equation](https://ourbigbook.com/codex/diophantine-equation) that factors neatly.

---

## 2) Three Factorisation Cases

For fixed `b`, each allowable value yields:

### Case 1: ratio = 0
\[
(a-b)(c-b)=2b^2
\]
Number of ordered solutions: `τ(2b²)`.

### Case 2: ratio = −1/2
\[
(a-3b)(c-3b)=12b^2
\]
Number of ordered solutions: `τ(12b²)`.

### Case 3: ratio = +1/2
\[
(3a-b)(3c-b)=4b^2
\]
Solutions depend on `b mod 3`.

- If `3 | b`, only [divisors](https://ourbigbook.com/codex/divisor) with a **3-adic [exponent](https://ourbigbook.com/codex/exponent) strictly between**
  `1` and `2v3(b)-1` are valid.
- If `3 ∤ b`, solutions correspond to [divisors](https://ourbigbook.com/codex/divisor) of `4b²` in one [residue class](https://ourbigbook.com/codex/residue-class) mod 3,
  handled via a [Dirichlet character](https://ourbigbook.com/codex/dirichlet-character).

This introduces a mod-3 character `χ` and [divisor sum](https://ourbigbook.com/codex/divisor-sum)
\[
S(n)=\sum_{d|n}\chi(d).
\]

---

## 3) Reducing to Two Summatory Functions

Write:

\[
b = 2^i 3^j m,\quad (m,6)=1.
\]

All contributions become weighted sums of `τ(m²)` and `χ(m)S(m²)`.

Define:

- **F(x)**  
  \[
  F(x)=\sum_{m\le x,\ (m,6)=1}\tau(m^2)
  \]

- **G(x)**  
  \[
  G(x)=\sum_{m\le x,\ (m,6)=1}\chi(m)S(m^2)
  \]

Then `T(n)` is expressed as a short double sum over [exponents](https://ourbigbook.com/codex/exponent) `i,j`
(only ~600 terms for `n=10^9`), provided we can evaluate `F` and `G` quickly.

---

## 4) Fast Evaluation of F and G (Min_25-Style Sieve)

The core bottleneck is computing `F(x)` and `G(x)` for large `x`.

Both functions are **[multiplicative](https://ourbigbook.com/codex/multiplicative-function)** with simple prime-power rules
(depending only on the [exponent](https://ourbigbook.com/codex/exponent) and `p mod 3`), so we compute [prefix sums](https://ourbigbook.com/codex/prefix-sum) via:

1. **[Prime](https://ourbigbook.com/codex/prime) block tables** ([Min_25](https://ourbigbook.com/codex/min-25-sieve) / Legendre-style):
   - `π(x)` for block values
   - `Σ_{p≤x} χ(p)` for block values

2. A **recursive [multiplicative](https://ourbigbook.com/codex/multiplicative-function) summatory** over [primes](https://ourbigbook.com/codex/prime):
   - enumerating [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor)
   - memoizing `(n, idx)` states

This runs in about `O(n^(2/3))` preprocessing and a small [recursion](https://ourbigbook.com/codex/recursion) tree.

---

## 5) Final Assembly

Once `F(x)` and `G(x)` are available, we evaluate:

- `Σ τ(2b²)`
- `Σ τ(12b²)`
- `Σ` of the `+1/2` case (split by `v3(b)=0` vs `≥1`)

using the decomposition `b = 2^i 3^j m`.
