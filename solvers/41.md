# Project Euler 41 Solution - Pandigital Prime

<https://projecteuler.net/problem=41>:

* [41.py](41.py)
* [41.lean](41.lean)

## Key insight
An `n`-[digit](https://ourbigbook.com/codex/numerical-digit) [pandigital number](https://ourbigbook.com/codex/pandigital-number) uses [digits](https://ourbigbook.com/codex/numerical-digit) `1..n` exactly once, so the sum of its digits is fixed:
\[
1 + 2 + \dots + n = \frac{n(n+1)}{2}
\]
If this [sum](https://ourbigbook.com/codex/sum) is divisible by `3`, then **every** such [pandigital number](https://ourbigbook.com/codex/pandigital-number) is divisible by `3` and therefore not [prime](https://ourbigbook.com/codex/prime-number) (except `3`, which is not pandigital here).

This eliminates `n = 9` and `n = 8` immediately:
- `1..9` [sum](https://ourbigbook.com/codex/sum) is `45` (divisible by 3)
- `1..8` [sum](https://ourbigbook.com/codex/sum) is `36` (divisible by 3)

The largest possible [pandigital prime](https://ourbigbook.com/codex/pandigital-prime) must therefore have `n = 7` or `n = 4` (since `1..7` [sum](https://ourbigbook.com/codex/sum) is 28, `1..4` [sum](https://ourbigbook.com/codex/sum) is 10).

## Algorithm
1. Loop `n` from 9 down to 1.
2. Skip `n` if `n(n+1)/2` is divisible by 3.
3. Generate all [permutations](https://ourbigbook.com/codex/permutation) of [digits](https://ourbigbook.com/codex/numerical-digit) `1..n`.
4. Apply quick last-digit filters (cannot end in an even digit or 5).
5. Test [primality](https://ourbigbook.com/codex/primality) by [trial division](https://ourbigbook.com/codex/trial-division) up to `sqrt(n)` using a `6k ± 1` loop.
6. Track the maximum [prime](https://ourbigbook.com/codex/prime-number) found and return it.

For `n = 7`, there are only `7! = 5040` [permutations](https://ourbigbook.com/codex/permutation), so this runs quickly.
