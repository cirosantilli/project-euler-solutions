# Project Euler 444 Solution - The Roundtable Lottery

<https://projecteuler.net/problem=444>:

* [444.py](444.py)

This solution relies on two closed-form observations.

## 1) Game analysis: `E(p) = H_p`

Under optimal play, the end-of-game players correspond exactly to the **[record highs](https://ourbigbook.com/codex/record-value)** (“[left-to-right maxima](https://ourbigbook.com/codex/record-value)”) in the order that ticket values are revealed.

- When a new **highest so far** value appears, it is always optimal for the current player (and any future player) to prefer that known best ticket over any smaller known ticket.
- Any player facing only non-record tickets can do better (in [expectation](https://ourbigbook.com/codex/expectation)) by continuing, so non-record tickets are “discarded” via trades.
- Therefore, the number of players left equals the number of [record highs](https://ourbigbook.com/codex/record-value) in a random [permutation](https://ourbigbook.com/codex/permutation) of `1..p`.

A standard fact: the expected number of [record highs](https://ourbigbook.com/codex/record-value) in a random [permutation](https://ourbigbook.com/codex/permutation) of length `p` is the [harmonic number](https://ourbigbook.com/codex/harmonic-number)

\[
H_p = \sum_{i=1}^{p} \frac{1}{i}.
\]

So `E(p) = H_p`.

## 2) Iterated summation: `S_k(N)` collapses neatly

The problem defines:

- `S_1(N) = sum_{p=1..N} E(p)`
- `S_k(N) = sum_{p=1..N} S_{k-1}(p)` for `k>1`

With `E(p)=H_p`, the k-fold [summation](https://ourbigbook.com/codex/summation) has a compact closed form:

\[
S_k(N) = \binom{N+k}{k}\left(H_{N+k} - H_k\right).
\]

This can be proven by [induction](https://ourbigbook.com/codex/induction) using the identity

\[
\binom{N+k}{k} = \binom{N+k-1}{k} + \binom{N+k-1}{k-1}
\]

and the telescoping behavior of [harmonic numbers](https://ourbigbook.com/codex/harmonic-number).

## 3) Numerical computation

For `N=10^14, k=20`:

- `binom(N+k, k)` is computed **exactly** as a Python big [integer](https://ourbigbook.com/codex/integer) (`math.comb`).
- `H_{N+k}` is computed using an **[Euler–Maclaurin](https://ourbigbook.com/codex/euler-maclaurin-formula)** expansion:

\[
H_n = \ln(n) + \gamma + \frac{1}{2n} - \frac{1}{12n^2} + \frac{1}{120n^4} - \cdots
\]

This is extremely accurate for such large `n`.
- `decimal.Decimal` is used to keep plenty of guard [digits](https://ourbigbook.com/codex/numerical-digit) and to ensure correct [rounding](https://ourbigbook.com/codex/rounding) to **10 significant [digits](https://ourbigbook.com/codex/numerical-digit)** in the final [scientific-notation](https://ourbigbook.com/codex/scientific-notation) output.
