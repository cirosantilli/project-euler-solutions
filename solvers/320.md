# Project Euler 320 Solution - Factorials Divisible by a Huge Integer

<https://projecteuler.net/problem=320>:

* [320.py](320.py)

## Problem Summary

Define $N(i)$ as the smallest [integer](https://ourbigbook.com/codex/integer) $n$ such that

$$n! \text{ is divisible by } (i!)^{1234567890}.$$

Then

$$S(u)=\sum_{i=10}^{u}N(i).$$

We are given

$$S(1000)=614538266565663,$$

and must compute

$$S(1000000)\bmod 10^{18}.$$

## Mathematical Approach

**1) [Divisibility](https://ourbigbook.com/codex/divisibility) of [factorials](https://ourbigbook.com/codex/factorial) is a prime-valuation problem.**

Write

$$i!=\prod_{p\le i}p^{e_{i,p}},\qquad e_{i,p}=v_p(i!).$$

Then

$$(i!)^K=\prod_{p\le i}p^{K e_{i,p}},\qquad K=1234567890.$$

Therefore

$$(i!)^K\mid n!\iff v_p(n!)\ge K e_{i,p}\quad\text{for every prime }p\le i.$$

So the whole problem reduces to matching required [prime exponents](https://ourbigbook.com/codex/prime-exponent) inside $n!$.

**2) [Legendre's formula](https://ourbigbook.com/codex/legendre-s-formula) tells us the [exponent](https://ourbigbook.com/codex/exponent) of one [prime](https://ourbigbook.com/codex/prime) in $n!$.**

For a fixed [prime](https://ourbigbook.com/codex/prime) $p$,

$$v_p(n!)=\sum_{j\ge1}\left\lfloor\frac{n}{p^j}\right\rfloor.$$

This function is [monotone](https://ourbigbook.com/codex/monotonicity) increasing in $n$. So if we want the smallest $n$ satisfying

$$v_p(n!)\ge t,$$

we can find it by [binary search](https://ourbigbook.com/codex/binary-search).

**3) Per-prime bottlenecks.**

For each [prime](https://ourbigbook.com/codex/prime) $p$, define the current target

$$t_p=K\,v_p(i!).$$

Let $n_p$ be the smallest [integer](https://ourbigbook.com/codex/integer) with

$$v_p(n_p!)\ge t_p.$$

Then the smallest $n$ satisfying *all* [prime](https://ourbigbook.com/codex/prime) conditions simultaneously is simply

$$N(i)=\max_{p\le i} n_p.$$

The largest per-prime obstruction determines the answer.

**4) Incremental update from $i-1$ to $i$.**

This is the key [optimization](https://ourbigbook.com/codex/optimization). Suppose

$$i=\prod p^{\alpha_p}.$$

Then

$$v_p(i!)=v_p((i-1)!)+\alpha_p,$$

so the required target updates only for [primes](https://ourbigbook.com/codex/prime) dividing $i$:

$$t_p\leftarrow t_p+K\alpha_p.$$

All other [primes](https://ourbigbook.com/codex/prime) keep exactly the same target. Therefore, when we move from $i-1$ to $i$, we only need to recompute the [primes](https://ourbigbook.com/codex/prime) appearing in the factorization of $i$.

**5) Why the [global maximum](https://ourbigbook.com/codex/global-maximum) never decreases.**

Every target $t_p$ is [nondecreasing](https://ourbigbook.com/codex/nondecreasing-function) as $i$ grows. Hence every minimal witness $n_p$ is also [nondecreasing](https://ourbigbook.com/codex/nondecreasing-function). So

$$N(i)=\max_p n_p$$

can never go down. This is why the code stores a single running value `current_max` and only raises it when a changed [prime](https://ourbigbook.com/codex/prime) produces a larger $n_p$.

**6) [Lower bound](https://ourbigbook.com/codex/lower-bound) for [binary search](https://ourbigbook.com/codex/binary-search).**

[Legendre's formula](https://ourbigbook.com/codex/legendre-s-formula) implies

$$v_p(n!)\le \frac{n}{p-1}.$$

So any $n$ meeting $v_p(n!)\ge t_p$ must satisfy

$$n\ge t_p(p-1).$$

The implementation uses this as a cheap [lower bound](https://ourbigbook.com/codex/lower-bound), and it also keeps the previous solution for that [prime](https://ourbigbook.com/codex/prime) as another [lower bound](https://ourbigbook.com/codex/lower-bound) because $n_p$ never decreases.

**7) Example of the incremental logic.**

When we move from $i=9$ to $i=10$, only the [prime factors](https://ourbigbook.com/codex/prime-factor) of $10$ matter:

$$10=2\cdot 5.$$

So the required [exponents](https://ourbigbook.com/codex/exponent) update as

$$t_2\leftarrow t_2+K,\qquad t_5\leftarrow t_5+K,$$

while the targets for $3,7,\dots$ stay unchanged. Therefore we recompute only $n_2$ and $n_5$, and then compare them to the existing [global maximum](https://ourbigbook.com/codex/global-maximum).

**8) Fast factorization of every $i$.**

To make the incremental update cheap, the program precomputes the [smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) ([SPF](https://ourbigbook.com/codex/smallest-prime-factor)) of every number up to $10^6$. Then each $i$ is factorized in essentially logarithmic time by repeatedly dividing by its [SPF](https://ourbigbook.com/codex/smallest-prime-factor).

## Algorithm

**1)** Build an [SPF sieve](https://ourbigbook.com/codex/smallest-prime-factor-sieve) up to $u$.

**2)** Maintain, for every [prime](https://ourbigbook.com/codex/prime) $p$, the required target $t_p$ and its minimal witness $n_p$.

**3)** For each $i=2,3,\dots,u$, factorize $i$.

**4)** For each [prime](https://ourbigbook.com/codex/prime) $p^{\alpha_p}$ in $i$, update

$$t_p\leftarrow t_p+K\alpha_p,$$

then recompute $n_p$ by [binary search](https://ourbigbook.com/codex/binary-search) on [Legendre's formula](https://ourbigbook.com/codex/legendre-s-formula).

The implementation first checks the current [global maximum](https://ourbigbook.com/codex/global-maximum) against the updated target. If that value already has enough factors of `p`, the exact new `n_p` cannot affect `N(i)`, so the [binary search](https://ourbigbook.com/codex/binary-search) is skipped.

**5)** Update the running maximum $N(i)$.

**6)** Add $N(i)$ to the sum whenever $i\ge10$.

## Complexity Analysis

The [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) costs roughly linear time in $u$. Each $i$ changes only the [primes](https://ourbigbook.com/codex/prime) in its factorization, which is very small on average. Each changed [prime](https://ourbigbook.com/codex/prime) needs a [binary search](https://ourbigbook.com/codex/binary-search), and each midpoint evaluation computes

$$v_p(n!)=\sum_{j\ge1}\left\lfloor\frac{n}{p^j}\right\rfloor$$

in $O(\log_p n)$. This is vastly faster than recomputing all [prime](https://ourbigbook.com/codex/prime) constraints from scratch for every $i$.

## Checks And Final Result

The source checks

$$S(1000)=614538266565663.$$

For the full problem, it computes

$$S(1000000)\bmod 10^{18}=278157919195482643.$$
