# Project Euler 781 Solution - Feynman Diagrams

<https://projecteuler.net/problem=781>:

* [781.py](781.py)

We need **F(n)**: the number of **connected** [graphs](https://ourbigbook.com/codex/graph) built from:

- 2 degree‑1 [graph vertices](https://ourbigbook.com/codex/graph-vertex) (one has a single outgoing blue [graph edge](https://ourbigbook.com/codex/graph-edge), one has a single incoming blue [graph edge](https://ourbigbook.com/codex/graph-edge))
- `n` degree‑3 [graph vertices](https://ourbigbook.com/codex/graph-vertex), each with:
  - one incoming blue [graph edge](https://ourbigbook.com/codex/graph-edge),
  - a *different* outgoing blue [graph edge](https://ourbigbook.com/codex/graph-edge) (so **no blue self‑loops**),
  - one red (undirected) edge-end.

Because every degree‑3 [graph vertex](https://ourbigbook.com/codex/graph-vertex) contributes exactly one red edge-end, the red [graph edges](https://ourbigbook.com/codex/graph-edge) form a [perfect matching](https://ourbigbook.com/codex/perfect-matching), so `n` must be even.

The problem gives test values:

- `F(4) = 5`
- `F(8) = 319`

Both are asserted in `main.py`.

---

## 1) Turning the count into power series

Let `n = 2m`. The red [graph matching](https://ourbigbook.com/codex/matching-graph-theory) contributes the Gaussian moment factor:

- number of pairings of `2m` items is `(2m-1)!!`.

The “blue part” is a directed [bijection](https://ourbigbook.com/codex/bijection) of outgoing blue stubs to incoming blue stubs, with the constraint that a degree‑3 [graph vertex](https://ourbigbook.com/codex/graph-vertex)’s incoming and outgoing blue [graph edges](https://ourbigbook.com/codex/graph-edge) must be **different**, which corresponds to excluding [fixed points](https://ourbigbook.com/codex/fixed-point) (derangement-style [inclusion–exclusion](https://ourbigbook.com/codex/inclusion-exclusion-principle)). This leads to truncated sums of `(-1)^k/k!`.

A convenient way to package the Burnside / [inclusion–exclusion](https://ourbigbook.com/codex/inclusion-exclusion-principle) bookkeeping is via two [formal power series](https://ourbigbook.com/codex/formal-power-series) in `h`:

- `A(h)` uses coefficients of `e^{-x}/(1-x)`
- `B(h)` uses coefficients of `e^{-x}/(1-x)^2`

Concretely, for `m >= 0`:

- `A_m = (2m-1)!! * [x^(2m)] (e^{-x}/(1-x))`
- `B_m = (2m-1)!! * [x^(2m)] (e^{-x}/(1-x)^2)`

The required connected count appears as the quotient series:

- `G(h) = B(h) / A(h)`
- then `F(2m) ≡ [h^m] G(h) (mod 1e9+7)`.

So the task reduces to extracting one coefficient from a **[formal power series division](https://ourbigbook.com/codex/formal-power-series-division)**.

---

## 2) Fast power series division via Newton inversion

To compute `G = B / A` up to degree `M = 25_000`, we compute the [formal power series reciprocal](https://ourbigbook.com/codex/formal-power-series-reciprocal) `A^{-1}` using [Newton inversion of a formal power series](https://ourbigbook.com/codex/newton-inversion-of-a-formal-power-series):

- start with `inv = 1/A[0]`
- repeatedly double the precision:
  - `inv <- inv * (2 - A*inv)  (mod x^k)`

Finally:

- `G = B * A^{-1}  (mod x^(M+1))`.

This needs fast [polynomial multiplication](https://ourbigbook.com/codex/polynomial-multiplication).

## 3) Fast multiplication mod 1e9+7 (NTT + CRT)

`1_000_000_007` is not an NTT-friendly [prime](https://ourbigbook.com/codex/prime), so multiplication is done by:

1. Performing 3 [NTT](https://ourbigbook.com/codex/number-theoretic-transform) [convolutions](https://ourbigbook.com/codex/convolution) under these [primes](https://ourbigbook.com/codex/prime):

   - `998244353`
   - `1004535809`
   - `469762049`

2. Reconstructing each coefficient with [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) directly into `mod 1e9+7`.

This is fully deterministic (no floating-point rounding issues) and uses only Python built-ins.
