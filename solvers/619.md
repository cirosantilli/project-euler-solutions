# Project Euler 619 Solution - Square Subsets

<https://projecteuler.net/problem=619>:

* [619.py](619.py)

## Idea
For each [integer](https://ourbigbook.com/codex/integer) `n`, write its [prime](https://ourbigbook.com/codex/prime) [integer factorization](https://ourbigbook.com/codex/integer-factorization)

- `n = ∏ p^{e_p}`

Only the [integer parity](https://ourbigbook.com/codex/integer-parity) of each exponent matters when asking if a product is a [perfect square](https://ourbigbook.com/codex/perfect-square).
Define the **[squarefree part](https://ourbigbook.com/codex/squarefree-part)**

- `k(n) = ∏ p` over [primes](https://ourbigbook.com/codex/prime) where `e_p` is odd.

A [subset](https://ourbigbook.com/codex/subset) product is a square **iff** the [XOR](https://ourbigbook.com/codex/bitwise-exclusive-or) (mod 2) of all parity-vectors is the [zero vector](https://ourbigbook.com/codex/zero-vector).

So if we have `m = b-a+1` [vectors](https://ourbigbook.com/codex/vector) and their [matrix rank](https://ourbigbook.com/codex/rank-of-a-matrix) over **[GF(2)](https://ourbigbook.com/codex/field-with-two-elements)** is `r`, the [linear map](https://ourbigbook.com/codex/linear-map)

- choose [subset](https://ourbigbook.com/codex/subset) → XOR-sum

has [kernel](https://ourbigbook.com/codex/kernel-of-a-linear-map) size `2^{m-r}`. That is exactly the number of [subsets](https://ourbigbook.com/codex/subset) whose product is a square, including the empty [subset](https://ourbigbook.com/codex/subset).
Therefore

- `C(a,b) = 2^{m-r} - 1`.

The whole problem becomes: **compute the [matrix rank](https://ourbigbook.com/codex/rank-of-a-matrix)** of the squarefree-kernel vectors.

## Key optimisation: split primes into “small” and “big”
Let `T = ⌊√b⌋`.

- **Small [primes](https://ourbigbook.com/codex/prime)**: `p ≤ T` (there are only ~200 of these for `b ≈ 1.2e6`)
- **Big [primes](https://ourbigbook.com/codex/prime)**: `p > T`

For any `n ≤ b`, its [squarefree part](https://ourbigbook.com/codex/squarefree-part) contains **at most one** big [prime](https://ourbigbook.com/codex/prime):
if two factors were both `> T`, their product would be `≥ (T+1)^2 > b`.

So every [vector](https://ourbigbook.com/codex/vector) looks like:

- just a **small-bitmask**, or
- `e_p + small_bitmask` for a single big [prime](https://ourbigbook.com/codex/prime) `p`.

This special structure makes the [matrix rank](https://ourbigbook.com/codex/rank-of-a-matrix) computation cheap.

## Rank computation strategy
1. **Pivot on big [primes](https://ourbigbook.com/codex/prime) first**: every distinct big [prime](https://ourbigbook.com/codex/prime) `p` that appears contributes `+1` to the [matrix rank](https://ourbigbook.com/codex/rank-of-a-matrix), because it is a unique column that no other big [prime](https://ourbigbook.com/codex/prime) touches.
2. Extra occurrences with the same big [prime](https://ourbigbook.com/codex/prime) `p` can be XORed to cancel `e_p`:

   - `(e_p + s1) XOR (e_p + s2) = s1 XOR s2` (a purely-small [vector](https://ourbigbook.com/codex/vector))

   These differences are added into the small [linear subspace](https://ourbigbook.com/codex/linear-subspace).
3. The **small [linear subspace](https://ourbigbook.com/codex/linear-subspace) [matrix rank](https://ourbigbook.com/codex/rank-of-a-matrix)** is computed with standard incremental [Gaussian elimination](https://ourbigbook.com/codex/gaussian-elimination) over [GF(2)](https://ourbigbook.com/codex/field-with-two-elements), but with an [integer](https://ourbigbook.com/codex/integer) [bitmask](https://ourbigbook.com/codex/bit-mask) (fast [XOR](https://ourbigbook.com/codex/bitwise-exclusive-or)), and the basis size is ≤ `π(T)` (~200).

Overall:

- `rank = (#distinct big primes) + rank_small`.

## Implementation notes
- A linear-time **[smallest prime factor](https://ourbigbook.com/codex/smallest-prime-factor) (SPF)** [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) factors all numbers quickly.
- Small [primes](https://ourbigbook.com/codex/prime) are mapped to bit positions in an [integer](https://ourbigbook.com/codex/integer) mask.
- The [algorithm](https://ourbigbook.com/codex/algorithm) streams through `n=a..b` once, and maintains only:
  - a dictionary of first-seen small masks per big [prime](https://ourbigbook.com/codex/prime)
  - a tiny [GF(2)](https://ourbigbook.com/codex/field-with-two-elements) basis for small masks

This runs comfortably fast for the target range.
