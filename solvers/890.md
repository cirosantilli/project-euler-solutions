# Project Euler 890 Solution - Binary Partitions

<https://projecteuler.net/problem=890>:

* [890.py](890.py)

## 1. Mathematical Reformulation

Let `p(n)` be the number of unordered representations of `n` as a sum of [powers of two](https://ourbigbook.com/codex/powers-of-two).

A standard [generating function](https://ourbigbook.com/codex/generating-function) is:

\[
P(x)=\prod_{k\ge 0}\frac{1}{1-x^{2^k}}
\]

A known [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) implies:

\[
p(2m)=p(2m+1)=S(m), \quad S(m)=\sum_{i=0}^m p(i)
\]

So computing `p(n)` reduces to computing `S(n//2)`.

Define:

\[
A(x)=\sum_{m\ge 0} S(m)x^m
\]

Then:

\[
A(x)=\frac{P(x)}{1-x}
\]

Using the identity:

\[
\frac{1}{1-t}=\prod_{j\ge 0}\left(1+t^{2^j}\right)
\]

one can rewrite:

\[
A(x)=\prod_{k\ge 0}(1+x^{2^k})^{k+2}
\]

Thus:

- `S(m)` is exactly the [coefficient](https://ourbigbook.com/codex/coefficient) `[x^m] A(x)`
- `p(n) = [x^{n//2}] A(x)`

## 2. Carry-Based Dynamic Programming in Base 2

Each factor:

\[
(1+x^{2^k})^{k+2}=\sum_{j=0}^{k+2}\binom{k+2}{j}x^{j2^k}
\]

Selecting terms is equivalent to choosing `j` items of weight `2^k` from `k+2` copies.

When summing weights in binary, each bit position has a [carry](https://ourbigbook.com/codex/carry-arithmetic).
We run [DP](https://ourbigbook.com/codex/dynamic-programming) over bit positions:

- State: `dp[c]` = number of ways to match processed bits with [carry](https://ourbigbook.com/codex/carry-arithmetic) `c`
- Transition: convolve `dp` with binomial row `C(k+2, j)` then pick [coefficients](https://ourbigbook.com/codex/coefficient)
  of the correct [integer parity](https://ourbigbook.com/codex/integer-parity) (matching the target bit)

---

## 3. Fast Convolution via Big-Integer Packing

A naive [convolution](https://ourbigbook.com/codex/convolution) per bit would be too slow.

To accelerate, [coefficients](https://ourbigbook.com/codex/coefficient) are packed into a large-base [integer](https://ourbigbook.com/codex/integer):

- Choose base \(B=2^{80}\) (large enough to prevent [carry](https://ourbigbook.com/codex/carry-arithmetic) overlap)
- Encode a [coefficient](https://ourbigbook.com/codex/coefficient) list `[a0, a1, ...]` as:

\[
A = a_0 + a_1B + a_2B^2 + \cdots
\]

Then ordinary [integer](https://ourbigbook.com/codex/integer) [multiplication](https://ourbigbook.com/codex/multiplication) `A * B` produces exact [convolution](https://ourbigbook.com/codex/convolution)
[coefficients](https://ourbigbook.com/codex/coefficient) in base \(2^{80}\).

Python’s [big integers](https://ourbigbook.com/codex/big-integer) use efficient [algorithms](https://ourbigbook.com/codex/algorithm) in optimized C, so this becomes fast.

After [multiplication](https://ourbigbook.com/codex/multiplication), we unpack only the needed [digits](https://ourbigbook.com/codex/digit) (every second [coefficient](https://ourbigbook.com/codex/coefficient)),
reducing overhead further.

---

## 4. Complexity

Let `L = bit_length(m)` where `m = n//2`.

- `L ≈ 2181` for the target input
- [DP](https://ourbigbook.com/codex/dynamic-programming) runs for `L` steps
- Each step uses one [big-integer multiplication](https://ourbigbook.com/codex/big-integer-multiplication) with ~O(L) [digits](https://ourbigbook.com/codex/digit)

This is practical in pure Python without external libraries.
