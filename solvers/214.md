# Project Euler 214 Solution - Totient Chains

<https://projecteuler.net/problem=214>:

* [214.py](214.py)

## Problem Summary

For the [Project Euler](https://ourbigbook.com/codex/project-euler) parameters $N=40{,}000{,}000$ and $T=25$, define the [totient chain](https://ourbigbook.com/codex/totient-chain) of a [positive integer](https://ourbigbook.com/codex/positive-integer) by repeatedly applying [Euler's totient function](https://ourbigbook.com/codex/euler-s-totient-function) until the value reaches $1$:

$$n \to \varphi(n) \to \varphi(\varphi(n)) \to \cdots \to 1.$$

The problem asks for the sum of all [primes](https://ourbigbook.com/codex/prime) $p < N$ whose chain has length exactly $T$. If we denote the chain length by $\ell(n)$, then the target quantity is

$$S(N,T)=\sum_{\substack{p < N\\ \ell(p)=T}} p,$$

where the sum runs over [primes](https://ourbigbook.com/codex/prime). A naive prime-by-prime search would recompute the same [totient](https://ourbigbook.com/codex/euler-s-totient-function) values again and again. The implementations avoid that duplication by building one global table of $\varphi(n)$ and one global table of chain lengths.

## Mathematical Approach

The key object is the directed map $n \mapsto \varphi(n)$. For Problem 214, every useful fact comes from understanding how this map behaves on all [integers](https://ourbigbook.com/codex/integer) up to the bound, not just on the [primes](https://ourbigbook.com/codex/prime) that appear in the final sum.

### The totient map always moves downward

For every [integer](https://ourbigbook.com/codex/integer) $n > 1$, Euler's [totient](https://ourbigbook.com/codex/euler-s-totient-function) satisfies $\varphi(n) < n$. Therefore repeated iteration cannot cycle above $1$; it must eventually terminate at $1$. This makes the chain length well defined for every [positive integer](https://ourbigbook.com/codex/positive-integer).

The natural [base case](https://ourbigbook.com/codex/base-case) is

$$\ell(1)=1,$$

because the chain starting at $1$ already consists of a single term. For $n \ge 2$, one step of the chain removes the first term and leaves the chain starting at $\varphi(n)$, so

$$\ell(n)=1+\ell(\varphi(n)).$$

This is the central [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) in all three implementations. Because $\varphi(n)$ is strictly smaller than $n$, the values form a dependency [graph](https://ourbigbook.com/codex/graph) that is automatically topologically ordered by the ordinary numeric order $1,2,3,\dots,N$.

### Primes enter through the identity $\varphi(p)=p-1$

If $p$ is [prime](https://ourbigbook.com/codex/prime), then every number $1 \le a \lt p$ is [coprime](https://ourbigbook.com/codex/coprime) to $p$, so

$$\varphi(p)=p-1.$$

Hence every candidate [prime](https://ourbigbook.com/codex/prime) immediately reduces to a [composite](https://ourbigbook.com/codex/composite-number) [even number](https://ourbigbook.com/codex/even-number):

$$\ell(p)=1+\ell(p-1).$$

This does *not* mean we can skip the [composite numbers](https://ourbigbook.com/codex/composite-number); on the contrary, the [prime](https://ourbigbook.com/codex/prime) case depends on them directly. Problem 214 is solved only after the chain length has been computed for every [integer](https://ourbigbook.com/codex/integer) up to the bound.

### Why the linear sieve gives every totient value in one pass

The implementations compute all totients with a [linear sieve](https://ourbigbook.com/codex/linear-sieve). Maintain a growing list of discovered [primes](https://ourbigbook.com/codex/prime). When an [integer](https://ourbigbook.com/codex/integer) $i$ has not been marked [composite](https://ourbigbook.com/codex/composite-number), it is [prime](https://ourbigbook.com/codex/prime), so its [totient](https://ourbigbook.com/codex/euler-s-totient-function) is known immediately:

$$\varphi(i)=i-1.$$

Then combine $i$ with each known [prime](https://ourbigbook.com/codex/prime) $q$ to form $v=i q$. Two cases determine $\varphi(v)$:

$$\varphi(iq)=
  \begin{cases}
  \varphi(i)\,q, & q \mid i,\\
  \varphi(i)\,(q-1), & q \nmid i.
  \end{cases}$$

The second line is just [multiplicativity](https://ourbigbook.com/codex/multiplicativity) for [coprime](https://ourbigbook.com/codex/coprime) factors: if $\gcd(i,q)=1$, then $\varphi(iq)=\varphi(i)\varphi(q)=\varphi(i)(q-1)$. The first line follows from writing $i=q^a m$ with $q \nmid m$: then

$$\varphi(i)=q^{a-1}(q-1)\varphi(m),\qquad \varphi(iq)=q^a(q-1)\varphi(m)=q\,\varphi(i).$$

The [linear sieve](https://ourbigbook.com/codex/linear-sieve) stops the inner generation as soon as it uses the smallest [prime](https://ourbigbook.com/codex/prime) [divisor](https://ourbigbook.com/codex/divisor) of $i$. That [invariant](https://ourbigbook.com/codex/invariant-mathematics) ensures each [composite](https://ourbigbook.com/codex/composite-number) is produced exactly once, so the [totient](https://ourbigbook.com/codex/euler-s-totient-function) table is filled in overall $O(N)$ time.

### Worked example: small chains and the checkpoint sums

A few small chains show the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) in action:

$$5 \to 4 \to 2 \to 1,\qquad \ell(5)=4,$$

$$7 \to 6 \to 2 \to 1,\qquad \ell(7)=4,$$

$$11 \to 10 \to 4 \to 2 \to 1,\qquad \ell(11)=5.$$

So for the small test case $N=100$ and $T=4$, the qualifying [primes](https://ourbigbook.com/codex/prime) are $5$ and $7$, whose sum is $12$. For $N=1000$ and $T=5$, the qualifying [primes](https://ourbigbook.com/codex/prime) are $11,13,19$, whose sum is $43$. Those two values are exactly the checkpoint cases used by the C++ implementation.

### The final summation is a simple filter once the tables exist

After the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) has produced the [prime](https://ourbigbook.com/codex/prime) list and all values $\varphi(n)$, and after the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) has produced all values $\ell(n)$, nothing difficult remains. One final pass over the [prime](https://ourbigbook.com/codex/prime) list is enough: keep the [primes](https://ourbigbook.com/codex/prime) with $\ell(p)=T$ and add them. There is no need to follow any chain on demand during this last stage, because each chain length is already available as a table lookup.

## How the Code Works

### First pass: build the prime list and the totient table

The C++, Python, and Java implementations all start with a [linear sieve](https://ourbigbook.com/codex/linear-sieve) over $2,3,\dots,N$. In the same loop they identify [primes](https://ourbigbook.com/codex/prime), mark [composites](https://ourbigbook.com/codex/composite-number), and assign $\varphi(n)$ using the two-case [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) above. This is the mathematically decisive preprocessing step, because every later calculation depends on $\varphi(n)$.

### Second pass: fill chain lengths in ascending order

With $\varphi(1),\varphi(2),\dots,\varphi(N)$ already known, the implementations allocate a second array for chain lengths, set $\ell(1)=1$, and process $n=2,3,\dots,N$ in order. Each entry is obtained from the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation)

$$\ell(n)=1+\ell(\varphi(n)).$$

Because $\varphi(n) < n$, the right-hand side always refers to an earlier entry. No [recursion](https://ourbigbook.com/codex/recursion) is needed; the table is filled iteratively in one linear sweep.

### Third pass: inspect primes only and accumulate the answer

Once chain lengths are known, the final pass is over [primes](https://ourbigbook.com/codex/prime) only. Whenever a [prime](https://ourbigbook.com/codex/prime) has the target length, it is added to the running total. The Python and Java implementations hardcode the [Project Euler](https://ourbigbook.com/codex/project-euler) parameters $N=40{,}000{,}000$ and $T=25$. The C++ implementation uses the same [algorithm](https://ourbigbook.com/codex/algorithm) but also supports alternate bounds and target lengths, and it verifies itself on the two small checkpoint sums before the full computation.

## Complexity Analysis

The [linear sieve](https://ourbigbook.com/codex/linear-sieve) is $O(N)$ time because each [composite number](https://ourbigbook.com/codex/composite-number) is generated once. The chain-length pass is another $O(N)$ sweep, and the final [prime](https://ourbigbook.com/codex/prime) filter is $O(\pi(N))$, which is contained in $O(N)$. Therefore the overall [running time](https://ourbigbook.com/codex/running-time) is linear in the bound:

$$O(N).$$

The [memory usage](https://ourbigbook.com/codex/memory-usage) is also $O(N)$: one array for [composite](https://ourbigbook.com/codex/composite-number) markers, one for totients, one for chain lengths, and a list of [primes](https://ourbigbook.com/codex/prime). For Problem 214 this linear behavior is essential, because $N=40{,}000{,}000$ is far beyond the range where repeated per-prime chain simulation would be comfortable.
