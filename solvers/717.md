# Project Euler 717 Solution - Summation of a Modular Formula

<https://projecteuler.net/problem=717>:

* [717.py](717.py)

## Problem Summary

For each [odd prime](https://ourbigbook.com/codex/odd-prime) $p$, the computation associates an [integer](https://ourbigbook.com/codex/integer) $g(p)$ obtained from a modular expression involving powers of $2$, and then sums these values:

$$G(n)=\sum_{\substack{3\le p \lt n\\ p\text{ prime}}} g(p).$$

The difficulty is that the exponent $2^p$ is already enormous, and the quantity for each [prime](https://ourbigbook.com/codex/prime) is not taken merely [modulo](https://ourbigbook.com/codex/modulo) $p$ but depends on how a [integer congruence](https://ourbigbook.com/codex/integer-congruence) lifts from [modulo](https://ourbigbook.com/codex/modulo) $p$ to [modulo](https://ourbigbook.com/codex/modulo) $p^2$. The implemented method therefore combines exponent reduction, modular inversion, a controlled lift to $p^2$, and a [prime](https://ourbigbook.com/codex/prime) [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve).

## Mathematical Approach

Fix an [odd prime](https://ourbigbook.com/codex/odd-prime) $p$. The implementation computes $g(p)$ by first finding a residue [modulo](https://ourbigbook.com/codex/modulo) $p$, then lifting it to a compatible residue [modulo](https://ourbigbook.com/codex/modulo) $p^2$, and finally extracting the multiple of $p$ that measures the difference between the two levels.

### Step 1: Compress the Tower Exponent

We begin with the residue

$$b_p \equiv 2^{2^p}\pmod{p}.$$

Computing $2^{2^p}$ directly is hopeless, but [Fermat's little theorem](https://ourbigbook.com/codex/fermat-s-little-theorem) gives $2^{p-1}\equiv 1 \pmod p$, so exponents can be reduced [modulo](https://ourbigbook.com/codex/modulo) $p-1$. Therefore

$$2^{2^p}\equiv 2^{\,2^p\bmod (p-1)}\pmod p.$$

If we define

$$a_p = 2^p \bmod (p-1),$$

then the needed residue becomes

$$b_p \equiv 2^{a_p}\pmod p.$$

This reduces a gigantic exponent tower to two ordinary [modular exponentiations](https://ourbigbook.com/codex/modular-exponentiation).

### Step 2: Solve the Halving Congruence Modulo $p$

Because $p$ is odd, the number $2$ is invertible [modulo](https://ourbigbook.com/codex/modulo) $p$. Its inverse is

$$2^{-1}\equiv \frac{p+1}{2}\pmod p,$$

since $2\cdot \frac{p+1}{2}=p+1\equiv 1\pmod p$.

Now choose the unique residue $h_p\in\{0,1,\dots,p-1\}$ satisfying

$$2h_p\equiv b_p\pmod p.$$

Equivalently,

$$h_p \equiv b_p\cdot \frac{p+1}{2}\pmod p.$$

This is the modular analogue of dividing the residue $b_p$ by $2$.

### Step 3: Lift from Modulo $p$ to Modulo $p^2$

Next form the residue

$$w_p \equiv h_p\,2^p \pmod{p^2},\qquad 0\le w_p \lt p^2.$$

The key observation is that $w_p$ has the same value as $b_p$ [modulo](https://ourbigbook.com/codex/modulo) $p$. Indeed, by [Fermat's little theorem](https://ourbigbook.com/codex/fermat-s-little-theorem),

$$2^p \equiv 2 \pmod p,$$

so

$$w_p \equiv h_p\,2 \equiv b_p \pmod p.$$

Therefore the difference $w_p-b_p$ is divisible by $p$. If $w_p\ge b_p$, we can divide that difference directly by $p$. If $w_p<b_p$, we add one full modulus $p^2$ first, which preserves the [congruence class](https://ourbigbook.com/codex/congruence-class) [modulo](https://ourbigbook.com/codex/modulo) $p^2$ while making the representative nonnegative.

Thus $g(p)$ is defined by

$$g(p)=\frac{\delta_p}{p},$$

where $\delta_p$ is the unique [integer](https://ourbigbook.com/codex/integer) with

$$\delta_p \equiv w_p-b_p \pmod{p^2},\qquad 0\le \delta_p \lt p^2.$$

Because $w_p\equiv b_p\pmod p$, the [numerator](https://ourbigbook.com/codex/numerator) is automatically a multiple of $p$.

### Step 4: Interpret the Quotient

The residue $b_p$ captures the value of the large power [modulo](https://ourbigbook.com/codex/modulo) $p$. The residue $w_p$ is a compatible lift [modulo](https://ourbigbook.com/codex/modulo) $p^2$. Since the two agree [modulo](https://ourbigbook.com/codex/modulo) $p$, their difference must be of the form $p\cdot q$. The number $g(p)$ is exactly this quotient:

$$w_p=b_p+p\,g(p)\quad\text{inside } \mathbb{Z}/p^2\mathbb{Z}.$$

So $g(p)$ measures the first correction term that appears when passing from arithmetic [modulo](https://ourbigbook.com/codex/modulo) $p$ to arithmetic [modulo](https://ourbigbook.com/codex/modulo) $p^2$.

### Step 5: Sum Over Odd Primes

Once $g(p)$ is available for one [prime](https://ourbigbook.com/codex/prime), the target quantity is just

$$G(n)=\sum_{\substack{3\le p \lt n\\ p\text{ prime}}} g(p).$$

The remaining algorithmic task is therefore to enumerate every [odd prime](https://ourbigbook.com/codex/odd-prime) below $n$ and apply the same modular procedure to each one.

### Worked Example: $p=31$

This [prime](https://ourbigbook.com/codex/prime) is large enough to show every ingredient while still fitting on paper.

First reduce the tower exponent:

$$a_{31}=2^{31}\bmod 30=8.$$

Hence

$$b_{31}\equiv 2^8\equiv 256\equiv 8 \pmod{31}.$$

Now solve the halving [integer congruence](https://ourbigbook.com/codex/integer-congruence):

$$2h_{31}\equiv 8\pmod{31},$$

so the least nonnegative solution is

$$h_{31}=4.$$

Next compute the lifted power [modulo](https://ourbigbook.com/codex/modulo) $31^2=961$:

$$2^{31}\equiv 374\pmod{961}.$$

Therefore

$$w_{31}\equiv 4\cdot 374=1496\equiv 535\pmod{961}.$$

Now subtract the [modulo](https://ourbigbook.com/codex/modulo)-$31$ residue:

$$535-8=527=31\cdot 17.$$

So

$$g(31)=17.$$

This is one of the checkpoints used by the implementations. Another small aggregate checkpoint is

$$G(100)=474.$$

## How the Code Works

The C++, Python, and Java implementations all follow the same structure. They first generate a [primality](https://ourbigbook.com/codex/primality) table up to $n$ with the classical [sieve of Eratosthenes](https://ourbigbook.com/codex/sieve-of-eratosthenes), then iterate only over [odd primes](https://ourbigbook.com/codex/odd-prime). For each such [prime](https://ourbigbook.com/codex/prime), they perform three [modular exponentiations](https://ourbigbook.com/codex/modular-exponentiation): one [modulo](https://ourbigbook.com/codex/modulo) $p-1$ to compress the exponent, one [modulo](https://ourbigbook.com/codex/modulo) $p$ to recover the residue $2^{2^p}\bmod p$, and one [modulo](https://ourbigbook.com/codex/modulo) $p^2$ to build the lifted quantity.

After that, the implementation multiplies by the [modular inverse](https://ourbigbook.com/codex/modular-inverse) of $2$ [modulo](https://ourbigbook.com/codex/modulo) $p$ in order to solve $2x\equiv b_p\pmod p$. The lifted residue is compared with the [modulo](https://ourbigbook.com/codex/modulo)-$p$ residue, and if the subtraction would be negative, one copy of $p^2$ is added before dividing by $p$. That guarantees an [integer](https://ourbigbook.com/codex/integer) quotient in the canonical range. The resulting $g(p)$ is then accumulated into the final sum.

The C++ and Java versions include dedicated modular multiplication routines to keep intermediate products safe under 64-bit arithmetic, while the Python version relies on built-in arbitrary-precision [integers](https://ourbigbook.com/codex/integer) and [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation).

## Complexity Analysis

The [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) up to $n$ costs $O(n\log\log n)$ time and $O(n)$ memory. For each [prime](https://ourbigbook.com/codex/prime) $p<n$, the [algorithm](https://ourbigbook.com/codex/algorithm) performs a constant number of fast [modular exponentiations](https://ourbigbook.com/codex/modular-exponentiation), each taking $O(\log p)$ modular multiplications. Summed over all [primes](https://ourbigbook.com/codex/prime), the arithmetic work is

$$O\!\left(\sum_{p \lt n,\ p\text{ prime}}\log p\right)=O(\pi(n)\log n),$$

which is smaller than the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) term for large $n$. Thus the full method runs in $O(n\log\log n+\pi(n)\log n)$ time and uses $O(n)$ memory.
