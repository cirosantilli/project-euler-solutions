# Project Euler 714 Solution - Duodigits

<https://projecteuler.net/problem=714>:

* [714.py](714.py)

This solution computes

- `d(n)`: the smallest positive multiple of `n` whose [decimal digits](https://ourbigbook.com/codex/decimal-digit) use **at most two distinct [digits](https://ourbigbook.com/codex/numerical-digit)**
- `D(k) = Σ d(n)` for `n = 1..k`

and prints `D(50000)` in scientific notation rounded to **13 significant [digits](https://ourbigbook.com/codex/numerical-digit)** (12 after the decimal point).

## Main techniques

### 1) Exhaustive duodigit generation (bounded)
All duodigits up to a fixed maximum length are generated:

- repdigits: `1`, `22`, `333`, …
- two-digit duodigits: for each [digit](https://ourbigbook.com/codex/numerical-digit) pair `{a,b}`, enumerate all non-trivial bit patterns choosing `a` vs `b`

Because any number with fewer [digits](https://ourbigbook.com/codex/numerical-digit) is smaller than any number with more [digits](https://ourbigbook.com/codex/numerical-digit), searching in increasing length (and within each length, increasing numeric order) guarantees we find the true minimum.

In this implementation we generate all duodigits up to **15 [digits](https://ourbigbook.com/codex/numerical-digit)** and scan that sorted list to find `d(n)` for all `n` not divisible by `10`.

### 2) Special handling for `n` divisible by `10`
If `n` is divisible by `10`, then any multiple must end in [digit](https://ourbigbook.com/codex/numerical-digit) `0`, so [digit](https://ourbigbook.com/codex/numerical-digit) `0` **must** appear in the duodigit.

Any number using only [digits](https://ourbigbook.com/codex/numerical-digit) `{0, d}` can be written as

- `d × X`

where `X` is a number using only [digits](https://ourbigbook.com/codex/numerical-digit) `{0,1}` (no carries occur when multiplying by a single [digit](https://ourbigbook.com/codex/numerical-digit)).

So for `n = 10m`:

1. For each `d ∈ {1..9}`, reduce to `X ≡ 0 (mod m / gcd(m,d))`
2. Find the smallest `{0,1}`-[digit](https://ourbigbook.com/codex/numerical-digit) multiple `X` using [BFS](https://ourbigbook.com/codex/breadth-first-search) on [remainders](https://ourbigbook.com/codex/remainder)
3. Map `1 → d` to get a `{0,d}`-[digit](https://ourbigbook.com/codex/numerical-digit) multiple of `m`, then append `0` to multiply by `10`

This avoids needing very long general duodigit searches for multiples of `10`.

### 3) BFS over remainders for smallest `{0,1}` multiple
For each modulus `k ≤ 5000`, the smallest number made of [digits](https://ourbigbook.com/codex/numerical-digit) `{0,1}` (leading [digit](https://ourbigbook.com/codex/numerical-digit) `1`) divisible by `k` is found with a classic [BFS](https://ourbigbook.com/codex/breadth-first-search):

- [graph vertices](https://ourbigbook.com/codex/vertex-of-a-graph): [remainders](https://ourbigbook.com/codex/remainder) `0..k-1`
- [graph edges](https://ourbigbook.com/codex/edge-of-a-graph): append [digit](https://ourbigbook.com/codex/numerical-digit) `0` or `1`

[BFS](https://ourbigbook.com/codex/breadth-first-search) guarantees the shortest length, and [digit](https://ourbigbook.com/codex/numerical-digit) order yields the lexicographically smallest among those, which corresponds to the smallest [integer](https://ourbigbook.com/codex/integer).

### 4) Exact rounding without floats
The final sum can exceed typical floating-point precision. The output formatting routine performs **string-based rounding** to exactly 13 significant [digits](https://ourbigbook.com/codex/numerical-digit) and prints scientific notation like:

`2.957098800000e7`

(Example format from the problem statement.)
