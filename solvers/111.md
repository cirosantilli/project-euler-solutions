# Project Euler 111 Solution - Primes with Runs

<https://projecteuler.net/problem=111>:

* [111.py](111.py)

## Problem Summary

For each [digit](https://ourbigbook.com/codex/numerical-digit) $d \in \{0,1,\dots,9\}$, let $M(10,d)$ be the largest number of times that $d$ can appear in a 10-digit [prime](https://ourbigbook.com/codex/prime-number), and let $S(10,d)$ be the [sum](https://ourbigbook.com/codex/sum) of all 10-digit [primes](https://ourbigbook.com/codex/prime-number) that attain this maximum repetition count. The goal is to compute

$$\sum_{d=0}^{9} S(10,d).$$

The important point is that the [optimization](https://ourbigbook.com/codex/optimization) is digit-specific. For each fixed [digit](https://ourbigbook.com/codex/numerical-digit) $d$, we are not looking for all [primes](https://ourbigbook.com/codex/prime-number) with many repeated [digits](https://ourbigbook.com/codex/numerical-digit) in general; we are looking for [primes](https://ourbigbook.com/codex/prime-number) with as many copies of that one chosen [digit](https://ourbigbook.com/codex/numerical-digit) as possible.

## Mathematical Approach

The implementations solve the problem by turning "maximum repetition" into the equivalent question "how few positions must be changed before a [prime](https://ourbigbook.com/codex/prime-number) appears?" That reformulation matches the [combinatorial structure](https://ourbigbook.com/codex/combinatorial-structure) of the search exactly.

### Minimal replacement count instead of maximal repetition

Fix a [digit](https://ourbigbook.com/codex/numerical-digit) $d$. Let $r_d$ be the smallest [integer](https://ourbigbook.com/codex/integer) $r \ge 1$ for which there exists a 10-digit [prime](https://ourbigbook.com/codex/prime-number) with exactly $r$ [digits](https://ourbigbook.com/codex/numerical-digit) different from $d$. Then a [prime](https://ourbigbook.com/codex/prime-number) found at that first successful level contains $10-r_d$ copies of $d$, so

$$M(10,d)=10-r_d.$$

If we write $\mathcal{P}(d,r)$ for the [set](https://ourbigbook.com/codex/set) of 10-digit [primes](https://ourbigbook.com/codex/prime-number) with exactly $r$ non-$d$ [digits](https://ourbigbook.com/codex/numerical-digit), then the desired [sum](https://ourbigbook.com/codex/sum) for [digit](https://ourbigbook.com/codex/numerical-digit) $d$ is

$$S(10,d)=\sum_{p\in \mathcal{P}(d,r_d)} p.$$

This is why the search can stop immediately once [primes](https://ourbigbook.com/codex/prime-number) are found: any larger value of $r$ would only decrease the number of repeated $d$'s, so it can never improve $M(10,d)$.

### The correct state space: choose positions, then choose digits

For a fixed pair $(d,r)$, start from the word $dddddddddd$. Choose a [set](https://ourbigbook.com/codex/set) $P\subseteq\{0,1,\dots,9\}$ of $r$ positions that will be changed, and then assign to each chosen position a [digit](https://ourbigbook.com/codex/numerical-digit) from $\{0,\dots,9\}\setminus\{d\}$. Because changed positions are forced to receive [digits](https://ourbigbook.com/codex/numerical-digit) different from $d$, every valid assignment has exactly $r$ non-$d$ [digits](https://ourbigbook.com/codex/numerical-digit) and is generated exactly once.

Before any [decimal](https://ourbigbook.com/codex/decimal) or [primality](https://ourbigbook.com/codex/primality) filters, the raw search space at level $r$ is therefore

$$\binom{10}{r} 9^r.$$

This factorization into [combinations](https://ourbigbook.com/codex/combination-combinatorics) of positions and assignments of [digits](https://ourbigbook.com/codex/numerical-digit) is the central combinatorial object in the solution, and all three implementations mirror it directly.

### Decimal constraints that remove entire families of candidates

Not every assignment can represent a 10-digit [prime](https://ourbigbook.com/codex/prime-number). Two elementary facts eliminate many cases before [primality testing](https://ourbigbook.com/codex/primality-testing).

First, the leading [digit](https://ourbigbook.com/codex/numerical-digit) cannot be zero. If $d=0$ and the first position is not among the changed positions, then the candidate is not a 10-digit [integer](https://ourbigbook.com/codex/integer) at all.

Second, every [prime](https://ourbigbook.com/codex/prime-number) greater than $5$ ends in $1$, $3$, $7$, or $9$. So if the last position is unchanged and $d\notin\{1,3,7,9\}$, that entire pattern is impossible. If the last position is changed, only [digits](https://ourbigbook.com/codex/numerical-digit) in $\{1,3,7,9\}\setminus\{d\}$ need to be tried there.

The C++ implementation applies the ending-digit rule explicitly before calling the [prime](https://ourbigbook.com/codex/prime-number) test. The same mathematics is still present in the Python and Java versions, even when the filter is enforced implicitly by the [prime](https://ourbigbook.com/codex/prime-number) test.

### Worked example: why the digit $0$ cannot succeed with one replacement

This is a good example of the difference between a structural argument and blind [brute force](https://ourbigbook.com/codex/brute-force-search). Suppose only one position were allowed to differ from $0$.

If the first [digit](https://ourbigbook.com/codex/numerical-digit) is not changed, the number begins with $0$, so it is not a valid 10-digit number. If the first [digit](https://ourbigbook.com/codex/numerical-digit) is the unique changed position, then the final [digit](https://ourbigbook.com/codex/numerical-digit) is still $0$, so the number is divisible by $10$ and cannot be [prime](https://ourbigbook.com/codex/prime-number). Therefore one replacement is impossible for $d=0$.

So we know immediately that

$$r_0\ge 2,\qquad M(10,0)\le 8.$$

The search still confirms this computationally, but the conclusion comes from place-value arithmetic alone.

### Why the first nonempty level is exactly the one we need

Suppose the search reaches a value $r$ and finds at least one [prime](https://ourbigbook.com/codex/prime-number). Then every one of those [primes](https://ourbigbook.com/codex/prime-number) has exactly $10-r$ copies of $d$. On the other hand, the search has already proved that no [prime](https://ourbigbook.com/codex/prime-number) exists for any smaller replacement count $1,2,\dots,r-1$. Hence no 10-digit [prime](https://ourbigbook.com/codex/prime-number) can contain more than $10-r$ copies of $d$, and the current level is automatically optimal.

That observation is the key [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics) of the whole approach: descending repetition counts are equivalent to ascending replacement counts, and the first successful level already determines both $M(10,d)$ and $S(10,d)$.

## How the Code Works

### Outer search over digits and replacement counts

The C++, Python, and Java implementations loop over $d=0,1,\dots,9$. For each [digit](https://ourbigbook.com/codex/numerical-digit) they try $r=1,2,\dots,10$, where $r$ is the number of positions that are not equal to $d$. That is the computational version of searching for $r_d$, the minimal replacement count.

### Candidate generation with exact repetition control

At a fixed $(d,r)$, the implementation fills a 10-slot [digit](https://ourbigbook.com/codex/numerical-digit) [array](https://ourbigbook.com/codex/array) with $d$, enumerates all $\binom{10}{r}$ choices of changed positions, and then enumerates all [digit](https://ourbigbook.com/codex/numerical-digit) assignments on those positions that avoid the value $d$. Because the repeated [digit](https://ourbigbook.com/codex/numerical-digit) is restored after each branch, every completed [array](https://ourbigbook.com/codex/array) still represents a number with exactly $10-r$ copies of $d$.

Leading-zero cases are rejected immediately. The C++ implementation also skips numbers whose final [digit](https://ourbigbook.com/codex/numerical-digit) is even or equal to $5$, because such numbers cannot be [prime](https://ourbigbook.com/codex/prime-number) unless the whole number is $2$ or $5$, which is impossible here.

### Primality testing and accumulation

Once a candidate passes the [decimal](https://ourbigbook.com/codex/decimal) filters, it is converted to an [integer](https://ourbigbook.com/codex/integer) and tested for [primality](https://ourbigbook.com/codex/primality). The C++ implementation uses modular [multiplication](https://ourbigbook.com/codex/multiplication), [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation), and a deterministic Miller-Rabin test that is valid for 64-bit inputs in this range. The Python and Java implementations rely on mature high-level [primality](https://ourbigbook.com/codex/primality) routines. All [primes](https://ourbigbook.com/codex/prime-number) found at the first successful level for [digit](https://ourbigbook.com/codex/numerical-digit) $d$ are added together, and the final answer is the [sum](https://ourbigbook.com/codex/sum) of those ten digit-specific totals.

## Complexity Analysis

If $r_d$ is the first successful replacement count for [digit](https://ourbigbook.com/codex/numerical-digit) $d$, then the work for that [digit](https://ourbigbook.com/codex/numerical-digit) is bounded by

$$O\!\left(\sum_{r=1}^{r_d}\binom{10}{r}9^r \cdot T_{\mathrm{prime}}\right),$$

where $T_{\mathrm{prime}}$ is the cost of one [primality test](https://ourbigbook.com/codex/primality-test) on a 10-digit [integer](https://ourbigbook.com/codex/integer). This expression is problem-adaptive: it measures exactly the amount of search the implementations perform before the optimal repetition count is certified.

Memory usage is $O(10)$ for the current [digit](https://ourbigbook.com/codex/numerical-digit) [array](https://ourbigbook.com/codex/array) plus small temporary storage for the [primes](https://ourbigbook.com/codex/prime-number) found at the first successful level. Since the target length is fixed at 10 [digits](https://ourbigbook.com/codex/numerical-digit) and the search stops as soon as the optimum is reached for each [digit](https://ourbigbook.com/codex/numerical-digit), the practical runtime is very small.
