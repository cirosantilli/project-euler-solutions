## Model

- [Decimal digits](https://ourbigbook.com/codex/decimal-digit) use standard 7-segment matchstick counts.
- `+` and `×` each cost 2 matchsticks.
- [Operator precedence](https://ourbigbook.com/codex/operator-precedence) is standard (`×` binds tighter than `+`).

Define:

- `P(n)`: minimum sticks to display `n` using **[digits](https://ourbigbook.com/codex/digit) and [multiplication](https://ourbigbook.com/codex/multiplication) only**.
- `M(n)`: minimum sticks to display `n` using **[digits](https://ourbigbook.com/codex/digit), [multiplication](https://ourbigbook.com/codex/multiplication), and [addition](https://ourbigbook.com/codex/addition)**.
- `T(N) = sum_{n=1..N} M(n)`.

To enumerate [divisors](https://ourbigbook.com/codex/divisor) efficiently we build an [SPF](https://ourbigbook.com/codex/smallest-prime-factor) (smallest-prime-factor) [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) up to `N`,

`P(n)` is small for `n <= 10^6`, so it fits in a `bytearray`.

## Technique 3: Exact optimization for two additive terms

Any expression is a sum of multiplicative “terms”.
The solver first computes the exact optimum among:

- one term: `P(n)`
- two terms: `P(a) + P(b) + 2` with `a+b=n`

This is done with:
- cost buckets for `P(.)` and enumeration of all pairs producing strong improvements, and
- a fallback scan over low `P(a)` values for the few high-cost cases.

## Technique 4: Three-term improvement pass

Two-term [optimization](https://ourbigbook.com/codex/optimization) is almost sufficient, but there is a rare case where allowing
three terms (`a + b + c`) saves a matchstick.

A 3-term expression costs:

P(a) + P(b) + P(c) + 4
