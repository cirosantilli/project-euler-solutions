# Project Euler 168 Solution - Number Rotations

<https://projecteuler.net/problem=168>:

* [168.py](168.py)

## Problem Summary

We seek decimal [integers](https://ourbigbook.com/codex/integer) $N$ with at least two [digits](https://ourbigbook.com/codex/numerical-digit), no trailing zero, and at most 100 [digits](https://ourbigbook.com/codex/numerical-digit), such that moving the last [digit](https://ourbigbook.com/codex/numerical-digit) of $N$ to the front produces an [integer multiple](https://ourbigbook.com/codex/integer-multiple) of $N$. The required output is the sum of all such numbers [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$.

If $N$ has [digits](https://ourbigbook.com/codex/numerical-digit) $x_{d-1}x_{d-2}\dots x_1x_0$, then the rotated number is $x_0x_{d-1}x_{d-2}\dots x_1$. This rotation preserves the number of [digits](https://ourbigbook.com/codex/numerical-digit), so the quotient $m=\frac{R}{N}$ must satisfy $1\le m\le 9$. That observation already compresses the search to a small set of multipliers.

## Mathematical Approach

Let $d$ be the number of [digits](https://ourbigbook.com/codex/numerical-digit), let $r=x_0$ be the last [digit](https://ourbigbook.com/codex/numerical-digit), and write

$$N=10q+r,\qquad 1\le r\le 9.$$

The rotation of $N$ is

$$R=r\cdot 10^{d-1}+q,$$

and the condition in the problem is

$$R=mN,\qquad m\in\{1,2,\dots,9\}.$$

The implementations use two equivalent viewpoints: a closed-form identity that shows there is at most one candidate for each triple $(d,m,r)$, and a [carry](https://ourbigbook.com/codex/carry-arithmetic) [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) that constructs that candidate [digit](https://ourbigbook.com/codex/numerical-digit) by [digit](https://ourbigbook.com/codex/numerical-digit) without ever forming a huge [integer](https://ourbigbook.com/codex/integer).

### One Candidate for Each Length, Multiplier, and Last Digit

Starting from $R=mN$, multiply by 10 and eliminate $q$:

$$10R=r\cdot 10^d+10q=r\cdot 10^d+N-r=10mN.$$

So every solution must satisfy

$$\boxed{(10m-1)N=r(10^d-1).}$$

Therefore

$$\boxed{N=\frac{r(10^d-1)}{10m-1}.}$$

This is a crucial simplification. Once $d$, $m$, and $r$ are fixed, the number $N$ is either uniquely determined or impossible. The search is no longer “all $d$-[digit](https://ourbigbook.com/codex/numerical-digit) numbers”; it is only 81 triples for each [digit](https://ourbigbook.com/codex/numerical-digit) length.

The formula also explains familiar special cases. When $m=1$, we get

$$N=\frac{r(10^d-1)}{9},$$

so every solution is a [repdigit](https://ourbigbook.com/codex/repdigit) $rr\dots r$, which rotation leaves unchanged.

### Carry Propagation from Right to Left

The code does not test [divisibility](https://ourbigbook.com/codex/divisibility) by building the fraction above. Instead it reads the multiplication $mN=R$ exactly as schoolbook arithmetic. Write

$$N=x_{d-1}x_{d-2}\dots x_1x_0$$

with $x_0=r$. Since $R=x_0x_{d-1}\dots x_1$, the units [digit](https://ourbigbook.com/codex/numerical-digit) of $mN$ must be $x_1$, the tens [digit](https://ourbigbook.com/codex/numerical-digit) must be $x_2$, and so on. If $c_i$ is the [carry](https://ourbigbook.com/codex/carry-arithmetic) entering step $i$ and $c_0=0$, then for $0\le i\le d-2$,

$$m x_i+c_i=x_{i+1}+10c_{i+1}.$$

After the last ordinary [digit](https://ourbigbook.com/codex/numerical-digit) has been generated, the multiplication must close perfectly:

$$m x_{d-1}+c_{d-1}=x_0=r.$$

This final equality is stronger than an [integer congruence](https://ourbigbook.com/codex/integer-congruence). It says the most significant output [digit](https://ourbigbook.com/codex/numerical-digit) is exactly $r$ and there is no extra [carry](https://ourbigbook.com/codex/carry-arithmetic) beyond it. If the generated top [digit](https://ourbigbook.com/codex/numerical-digit) $x_{d-1}$ were 0, the candidate would really have fewer than $d$ [digits](https://ourbigbook.com/codex/numerical-digit), so it must also be rejected.

### Why the Recurrence Solves the Whole Problem

The [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) is not an approximation; it is exactly the decimal multiplication rule for $mN$. If it starts from $x_0=r$, produces [digits](https://ourbigbook.com/codex/numerical-digit) $x_1,x_2,\dots,x_{d-1}$, and then closes back to $r$, the resulting number satisfies $mN=R$. Conversely, any valid rotated multiple must obey those same [carry](https://ourbigbook.com/codex/carry-arithmetic) equations. So the problem is equivalent to iterating this finite-state process over all $(d,m,r)$.

That viewpoint is especially useful because the [Project Euler](https://ourbigbook.com/codex/project-euler) task asks only for the sum [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$, not for the full [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) of each solution. The implementations can therefore keep a running value of

$$N\bmod M=\sum_{i=0}^{d-1} x_i 10^i \bmod M,\qquad M=10^5,$$

while the [digits](https://ourbigbook.com/codex/numerical-digit) are being generated, instead of storing $N$ itself.

### Worked Example: $142857$

The classical example comes from $d=6$, $m=5$, and $r=7$. The closed form gives

$$N=\frac{7(10^6-1)}{49}=142857.$$

The [carry](https://ourbigbook.com/codex/carry-arithmetic) [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) reveals the same number [digit](https://ourbigbook.com/codex/numerical-digit) by [digit](https://ourbigbook.com/codex/numerical-digit):

$$5\cdot 7=5+10\cdot 3,$$

$$5\cdot 5+3=8+10\cdot 2,$$

$$5\cdot 8+2=2+10\cdot 4,$$

$$5\cdot 2+4=4+10\cdot 1,$$

$$5\cdot 4+1=1+10\cdot 2.$$

Reading the produced [digits](https://ourbigbook.com/codex/numerical-digit) from most significant to least significant gives $142857$, and the closure step is

$$5\cdot 1+2=7,$$

which matches the original last [digit](https://ourbigbook.com/codex/numerical-digit). Therefore

$$142857\longrightarrow 714285=5\cdot 142857.$$

This is exactly the mechanism the code applies to every permitted length, multiplier, and final [digit](https://ourbigbook.com/codex/numerical-digit).

## How the Code Works

### Enumerating the Compressed Search Space

The C++, Python, and Java implementations loop over [digit](https://ourbigbook.com/codex/numerical-digit) lengths $d=2,3,\dots,100$, multipliers $m=1,2,\dots,9$, and last [digits](https://ourbigbook.com/codex/numerical-digit) $r=1,2,\dots,9$. Because the derivation above shows there is at most one candidate for each triple, nothing larger needs to be searched.

### Generating Digits and Accumulating $N \bmod 10^5$

For each triple, the implementation starts with the known last [digit](https://ourbigbook.com/codex/numerical-digit) $r$, then repeatedly applies the [carry](https://ourbigbook.com/codex/carry-arithmetic) rule

$$m x_i+c_i=x_{i+1}+10c_{i+1}.$$

Each new [digit](https://ourbigbook.com/codex/numerical-digit) $x_{i+1}$ is immediately added into the running [remainder](https://ourbigbook.com/codex/remainder)

$$v\leftarrow v+x_{i+1}\cdot 10^{i+1}\pmod{10^5},$$

while the current power of 10 is also maintained [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$. This keeps the memory footprint constant even when the actual number has 100 [digits](https://ourbigbook.com/codex/numerical-digit).

### Accepting or Rejecting a Triple

After $d-1$ [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) steps, the generated current [digit](https://ourbigbook.com/codex/numerical-digit) is the would-be leading [digit](https://ourbigbook.com/codex/numerical-digit). The implementations reject the triple if that [digit](https://ourbigbook.com/codex/numerical-digit) is 0, because then the number would not truly have $d$ [digits](https://ourbigbook.com/codex/numerical-digit). They also reject it unless the final closure value $m x_{d-1}+c_{d-1}$ is exactly $r$. When both tests succeed, the accumulated [remainder](https://ourbigbook.com/codex/remainder) is the contribution of that valid rotated multiple, and it is added to the global sum [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$.

## Complexity Analysis

For a fixed triple $(d,m,r)$, the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) runs for $d-1$ steps, so the work is $O(d)$. Summing over all [digit](https://ourbigbook.com/codex/numerical-digit) lengths up to $D$ gives

$$\sum_{d=2}^{D} 9\cdot 9\cdot O(d)=O(D^2).$$

For the actual problem $D=100$, this is tiny compared with any [brute-force](https://ourbigbook.com/codex/brute-force-search) scan over all [integers](https://ourbigbook.com/codex/integer) below $10^{100}$. The [memory usage](https://ourbigbook.com/codex/memory-usage) is $O(1)$, because the implementation stores only the current [digit](https://ourbigbook.com/codex/numerical-digit), the [carry](https://ourbigbook.com/codex/carry-arithmetic), a running [remainder](https://ourbigbook.com/codex/remainder) [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$, the current power of 10 [modulo](https://ourbigbook.com/codex/modulo-operation) $10^5$, and the total sum.
