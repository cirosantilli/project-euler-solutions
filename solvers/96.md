# Project Euler 96 Solution - Su Doku

<https://projecteuler.net/problem=96>:

* [96.py](96.py)
* [96.lean](96.lean)

## Problem Summary

The input consists of 50 standard [Sudoku](https://ourbigbook.com/codex/sudoku) grids. Each grid is a $9 \times 9$ [array](https://ourbigbook.com/codex/array) with [digits](https://ourbigbook.com/codex/numerical-digit) $0$ through $9$, where $0$ marks an empty cell. After solving a grid, the required contribution is the three-digit number formed by the first three entries of the top row.

If the completed grid is written as $x_{r,c}$ for $1 \le r,c \le 9$, then one puzzle contributes

$$100x_{1,1}+10x_{1,2}+x_{1,3}.$$

The final answer is the [sum](https://ourbigbook.com/codex/sum) of this quantity over all 50 solved grids. The real work is therefore to complete each partially filled grid while respecting the [Sudoku](https://ourbigbook.com/codex/sudoku) rules: every row, every column, and every $3 \times 3$ box must contain each [digit](https://ourbigbook.com/codex/numerical-digit) from 1 to 9 exactly once.

## Mathematical Approach

The implementations treat [Sudoku](https://ourbigbook.com/codex/sudoku) as a finite [search problem](https://ourbigbook.com/codex/search-problem) with a very strict legality [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics). At every recursive step, the current board is a partial completion that already agrees with all row, column, and box constraints.

### Rows, columns, boxes, and the legality invariant

For a partially filled grid, define the used-digit [sets](https://ourbigbook.com/codex/set)

$$R_r=\{x_{r,c}\ne 0:1\le c\le 9\},\qquad C_c=\{x_{r,c}\ne 0:1\le r\le 9\},$$

and for each box

$$B_b=\{x_{r,c}\ne 0:b(r,c)=b\}.$$

A box is identified by

$$b(r,c)=3\left\lfloor\frac{r-1}{3}\right\rfloor+\left\lfloor\frac{c-1}{3}\right\rfloor+1.$$

The essential [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics) is simple: no nonzero [digit](https://ourbigbook.com/codex/numerical-digit) may appear twice inside the same $R_r$, the same $C_c$, or the same $B_b$. Any recursive branch that would violate this [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics) can be discarded immediately.

### Candidate sets for an empty cell

For an empty position $(r,c)$, the allowable [digits](https://ourbigbook.com/codex/numerical-digit) are exactly

$$A(r,c)=\{1,2,\dots,9\}\setminus\bigl(R_r\cup C_c\cup B_{b(r,c)}\bigr).$$

This [set](https://ourbigbook.com/codex/set) is the mathematical core of the solver. If $A(r,c)=\varnothing$, the current partial grid cannot be extended to a full solution. If $|A(r,c)|=1$, the placement is forced. Otherwise the solver must branch on the candidates in $A(r,c)$.

The C++ implementation stores these used-digit [sets](https://ourbigbook.com/codex/set) as bit patterns, so the candidate [set](https://ourbigbook.com/codex/set) is recovered with bitwise operations. The Python and Java implementations compute the same [set](https://ourbigbook.com/codex/set) more directly by scanning the corresponding row, column, and box whenever they test a trial [digit](https://ourbigbook.com/codex/numerical-digit).

### The recursive search recurrence

Let $S$ be a legal partial [Sudoku](https://ourbigbook.com/codex/sudoku) state. If there are no empty cells left, then $S$ is already a complete solution. Otherwise choose one empty cell $u$, compute its candidate [set](https://ourbigbook.com/codex/set) $A(u)$, and try each legal [digit](https://ourbigbook.com/codex/numerical-digit) in turn. In logical form, the search is

$$\operatorname{Solve}(S)=\bigvee_{d\in A(u)} \operatorname{Solve}(S[u\leftarrow d]).$$

Here $S[u\leftarrow d]$ means the new state after writing [digit](https://ourbigbook.com/codex/numerical-digit) $d$ into cell $u$. A branch returns failure as soon as some empty cell has no legal [digit](https://ourbigbook.com/codex/numerical-digit) left.

The C++ implementation improves this [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) by choosing the empty cell with the smallest candidate set ([minimum remaining values heuristic](https://ourbigbook.com/codex/minimum-remaining-values-heuristic)), which reduces the [branching factor](https://ourbigbook.com/codex/branching-factor). The Python and Java implementations keep a list of empty cells and recurse through that list in order. Both strategies enumerate only legal completions, and [backtracking](https://ourbigbook.com/codex/backtracking) guarantees completeness because every admissible [digit](https://ourbigbook.com/codex/numerical-digit) assignment is eventually explored unless a solution is found earlier.

### Worked Example: why the checkpoint grid begins with 534

One built-in checkpoint uses a nearly complete grid whose first row is

$$[0,3,4,6,7,8,9,1,2].$$

The missing entry is $x_{1,1}$. Row 1 is missing only the [digit](https://ourbigbook.com/codex/numerical-digit) 5. Column 1 contains

$$[0,6,1,8,4,7,9,2,3],$$

so that column is also missing only 5. The upper-left $3\times 3$ box contains

$$[0,3,4;\ 6,7,2;\ 1,9,8],$$

which again excludes every [digit](https://ourbigbook.com/codex/numerical-digit) except 5. Therefore

$$A(1,1)=\{5\},\qquad x_{1,1}=5.$$

Once that forced move is made, the top-left three-digit value is

$$100\cdot 5+10\cdot 3+4=534.$$

This small example shows exactly how the solver reasons: legal [digits](https://ourbigbook.com/codex/numerical-digit) are determined by row, column, and box exclusions, and forced cells collapse immediately before any deeper branching is needed.

## How the Code Works

All three implementations read the 50 grids, solve each grid independently, and add the quantity $100x_{1,1}+10x_{1,2}+x_{1,3}$ to a running total. The [recursion](https://ourbigbook.com/codex/recursion) updates the board in place, and a failed branch is undone before trying the next candidate.

### Shared structure across the three implementations

Each implementation parses the nine text rows of a puzzle into a $9 \times 9$ board. Empty cells are represented by zeroes. Once a solution is found, the first three cells of the top row are read and converted into the required three-digit contribution.

### What differs between C++, Python, and Java

The C++ implementation first checks that the given clues do not already violate [Sudoku](https://ourbigbook.com/codex/sudoku) constraints. It maintains row, column, and box occupancy [bit masks](https://ourbigbook.com/codex/bit-mask), recomputes candidate [bit masks](https://ourbigbook.com/codex/bit-mask) efficiently, and at each recursive level chooses the still-empty cell with the fewest legal digits. The Python and Java implementations instead store the empty positions once and recurse through them in order; legality is tested by direct scans of the row, column, and $3\times 3$ box for each trial [digit](https://ourbigbook.com/codex/numerical-digit). Mathematically the [search tree](https://ourbigbook.com/codex/search-tree) is the same kind of backtracking tree, but the C++ version prunes it more aggressively.

## Complexity Analysis

If a grid has $m$ empty cells, the worst-case [search tree](https://ourbigbook.com/codex/search-tree) has [branching factor](https://ourbigbook.com/codex/branching-factor) at most 9 and depth $m$, so the crude [upper bound](https://ourbigbook.com/codex/upper-bound) is $O(9^m)$. That is the unavoidable exponential behavior of generic [backtracking](https://ourbigbook.com/codex/backtracking) on [Sudoku](https://ourbigbook.com/codex/sudoku) constraints.

Inside one recursive step, the bookkeeping is [constant-time](https://ourbigbook.com/codex/constant-time) on a fixed $9 \times 9$ board. In the Python and Java implementations, checking one tentative [digit](https://ourbigbook.com/codex/numerical-digit) means scanning at most 9 cells in the row, 9 in the column, and 9 in the box. In the C++ implementation, candidate computation is bitwise, but it also scans the board to find the empty cell with minimum candidate count. Memory usage is $O(m)$ for the recursion stack, plus the fixed board representation and the auxiliary row, column, and box state.

Because the board size is fixed and there are only 50 puzzles, the practical running time is small even though the worst-case search bound is exponential.
