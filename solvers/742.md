# Project Euler 742 Solution - Minimum Area of a Convex Grid Polygon

<https://projecteuler.net/problem=742>:

* [742.py](742.py)

## Problem
We seek the minimum area **A(N)** of a *symmetrical convex grid [polygon](https://ourbigbook.com/codex/polygon)* with **N** [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon):

- all [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) have [integer](https://ourbigbook.com/codex/integer) coordinates,
- [strictly convex polygon](https://ourbigbook.com/codex/strictly-convex-polygon) (every internal angle < 180°),
- symmetric about both a horizontal and a vertical axis.

The task is to compute **A(1000)**.

---

## Key Techniques Used

### 1) Symmetry Reduction
With horizontal and vertical [symmetry](https://ourbigbook.com/codex/symmetry), the [polygon](https://ourbigbook.com/codex/polygon) can be described by a much smaller structure.

Instead of describing all [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon), we describe a sequence of primitive edge directions in the first quadrant.  
Reflections across axes generate the remaining edges automatically.

This reduces the search space from “all lattice [polygons](https://ourbigbook.com/codex/polygon)” to “all valid sets of primitive [vectors](https://ourbigbook.com/codex/vector)”.

---

### 2) Primitive Direction Vectors
For minimality, we can restrict to *primitive* edge vectors:

> A vector `(dx,dy)` is primitive if `gcd(|dx|,|dy|)=1`.

Non-primitive edges can be shortened without violating [convexity](https://ourbigbook.com/codex/convexity) or lattice constraints, reducing area.

Thus we represent candidate edges by primitive pairs `(a,b)` with `a>0`, `b>0`, `gcd(a,b)=1`.

---

### 3) Elliptic (Weighted) Vector Selection
Empirically (and consistent with known lattice-geometry results), optimal solutions arise from taking all primitive
[vectors](https://ourbigbook.com/codex/vector) inside an **axis-aligned [ellipse](https://ourbigbook.com/codex/ellipse)**.

We model this by minimizing a weighted norm:

w(a,b) = a² + t·b²

We scan `t` over a dense grid in `(0,1]` ([symmetry](https://ourbigbook.com/codex/symmetry) makes `t>1` redundant).

---

### 4) Fast Area Computation via Prefix Determinants
The [polygon](https://ourbigbook.com/codex/polygon) is built from its edge vectors, but computing area via [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) would be slower.

Instead we use a [determinant](https://ourbigbook.com/codex/determinant) identity:

For a closed [polygon](https://ourbigbook.com/codex/polygon) with edge vectors `e0,e1,...`, area equals:

Area = 1/2 Σ det(P_i, P_{i+1})

where `P_i` are [prefix sums](https://ourbigbook.com/codex/prefix-sum) of edges.

For centrally symmetric [polygons](https://ourbigbook.com/codex/polygon), the full area is exactly equal to the [determinant](https://ourbigbook.com/codex/determinant) sum over the half-cycle.

That lets us compute area in **O(m)** time where `m ≈ N/2`, using running [prefix sums](https://ourbigbook.com/codex/prefix-sum).

---

## Complexity
Let:

- `k = (N-4)/4` interior primitive [vectors](https://ourbigbook.com/codex/vector),
- `M` = number of candidate primitive [vectors](https://ourbigbook.com/codex/vector) generated under some coordinate limit.

For each `t`:
- selecting k smallest by [heap](https://ourbigbook.com/codex/heap-data-structure): `O(M log k)`
- [sorting](https://ourbigbook.com/codex/sorting) selected [vectors](https://ourbigbook.com/codex/vector) by [slope](https://ourbigbook.com/codex/slope): `O(k log k)`
- area via prefix [determinants](https://ourbigbook.com/codex/determinant): `O(k)`

With `N=1000`, `k=249`, this remains comfortably fast in plain Python.
