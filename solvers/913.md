# Project Euler 913 Solution - Row-major vs Column-major

<https://projecteuler.net/problem=913>:

* [913.py](913.py)

## Key idea: swaps = N − cycles

Swapping any two entries is the same as applying a **[transposition](https://ourbigbook.com/codex/transposition)**. For a [permutation](https://ourbigbook.com/codex/permutation) of `N` items, the minimum number of transpositions required to realize it is:

- `N − (#cycles)`

because each [cycle](https://ourbigbook.com/codex/permutation-cycle) of length `L` can be fixed in `L−1` swaps.

So the task is reduced to counting **[cycles](https://ourbigbook.com/codex/permutation-cycle)** in the [permutation](https://ourbigbook.com/codex/permutation) that maps the row-major placement to the column-major placement.

---

## The permutation becomes modular multiplication

Index the `n × m` positions by `i = 0..nm−1` (row-major index). The element `i` ends up at

```
(i mod n) * m + floor(i / n)
```

A classic (and very useful) fact for this mapping is:

- For `i = 0..(nm−2)`, the mapping is equivalent to

```
 i  ->  (i * m) mod (nm − 1)
```

- The last index `nm−1` is a [fixed point](https://ourbigbook.com/codex/fixed-point).

This works because `gcd(m, nm−1) = 1`, so [multiplication](https://ourbigbook.com/codex/multiplication) by `m` is a [permutation](https://ourbigbook.com/codex/permutation) [modulo](https://ourbigbook.com/codex/modulo-operation) `nm−1`.

---

## Counting cycles with number theory

Let `M = nm − 1` and consider the [permutation](https://ourbigbook.com/codex/permutation) on residues `0..M−1`:

```
T(x) = (x * m) mod M
```

Elements partition by `d = gcd(x, M)`. For a fixed [divisor](https://ourbigbook.com/codex/divisor) `Q` of `M`, the set

- `{ x : gcd(x, M) = M/Q }`

has size `φ(Q)`, and all of those elements have the same [cycle](https://ourbigbook.com/codex/permutation-cycle) length, equal to the **[multiplicative order](https://ourbigbook.com/codex/multiplicative-order)** of `m (mod Q)`.

That yields:

```
#cycles (including x = 0) =  Σ_{Q | M}  φ(Q) / ord_Q(m)
```

Then the full `n × m` [permutation](https://ourbigbook.com/codex/permutation) has one extra [fixed point](https://ourbigbook.com/codex/fixed-point) (`nm−1`), so:

```
S(n, m) = nm − 1 − Σ_{Q | (nm−1)}  φ(Q) / ord_Q(m)
```

---

## Efficient computation of orders

For each [divisor](https://ourbigbook.com/codex/divisor) `Q` we need `ord_Q(m)`. Using [prime factorization](https://ourbigbook.com/codex/prime-factorization):

- For `Q = ∏ p_i^{a_i}` ([coprime](https://ourbigbook.com/codex/coprime) factors),

```
ord_Q(m) = lcm( ord_{p_i^{a_i}}(m) )
```

For a [prime power](https://ourbigbook.com/codex/prime-power) `p^a`, the order divides the [Carmichael function](https://ourbigbook.com/codex/carmichael-function) `λ(p^a)`:

- `λ(p^a) = (p−1)p^{a−1}` for [odd primes](https://ourbigbook.com/codex/odd-prime)
- special handling for `2^a`

Compute the order by starting from `λ(p^a)` and repeatedly dividing by [prime factors](https://ourbigbook.com/codex/prime-factor) when the [modular power](https://ourbigbook.com/codex/modular-power) test still returns `1`.

---

## Why the `n^4, m^4` case stays tractable

In the required sum we evaluate `S(n^4, m^4)` for `2 ≤ n ≤ m ≤ 100`.

Let `t = nm` (so `t ≤ 10000`). Then:

- `n^4 m^4 = (nm)^4 = t^4`
- `M = t^4 − 1 = (t−1)(t+1)(t^2+1)`

All three factors are at most about `10^8`, so `M` can be factored quickly by [trial division](https://ourbigbook.com/codex/trial-division) of those parts, avoiding heavy large-integer factorization.

---

## Implementation notes

- Trial-division factorization is cached.
- `λ(p^a)` and its [prime divisors](https://ourbigbook.com/codex/prime-divisor) are cached per `(p, a)`.
- The [divisor sum](https://ourbigbook.com/codex/divisor-sum) is computed by DFS over [prime exponents](https://ourbigbook.com/codex/prime-exponent), maintaining:
  - `φ(Q)` multiplicatively
  - `ord_Q(m)` via incremental `lcm`

The code also includes the problem’s given checks as `assert`s.
