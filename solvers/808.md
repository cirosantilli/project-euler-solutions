# Project Euler 808 Solution - Reversible Prime Squares

<https://projecteuler.net/problem=808>:

* [808.py](808.py)

## Problem Summary

We seek numbers $s$ with three simultaneous properties: $s$ must be the square of a [prime](https://ourbigbook.com/codex/prime), $s$ must not be palindromic in base 10, and the decimal reversal of $s$ must again be the square of a [prime](https://ourbigbook.com/codex/prime). The task is to list these reversible [prime](https://ourbigbook.com/codex/prime) squares in increasing order and sum the first $50$ of them.

If $s$ qualifies and $t=\operatorname{rev}(s)$, then $t$ is also a reversible [prime](https://ourbigbook.com/codex/prime) square unless $s=t$, which is exactly the palindromic case that must be excluded. The search therefore focuses on a very special subset of [prime](https://ourbigbook.com/codex/prime) squares rather than on all [integers](https://ourbigbook.com/codex/integer).

## Mathematical Approach

Let

$$\mathcal{R}=\left\{p^2 : p\in\mathbb{P},\ p^2\ne \operatorname{rev}(p^2),\ \operatorname{rev}(p^2)=q^2,\ q\in\mathbb{P}\right\}.$$

The implementations search this set directly. The mathematics is simple but precise: restrict the search to [prime](https://ourbigbook.com/codex/prime) roots, reverse the decimal [digits](https://ourbigbook.com/codex/numerical-digit), and certify that the reversed value is also a [prime](https://ourbigbook.com/codex/prime) square.

### Step 1: Restrict the Search Space to Prime Squares

Every admissible value has the form

$$s=p^2,\qquad p\in\mathbb{P}.$$

So there is no reason to test arbitrary [integers](https://ourbigbook.com/codex/integer). It is enough to enumerate [primes](https://ourbigbook.com/codex/prime) $p$ and examine their squares. Because the map $p\mapsto p^2$ is [strictly increasing](https://ourbigbook.com/codex/strictly-increasing) for [positive integers](https://ourbigbook.com/codex/positive-integer), scanning [prime](https://ourbigbook.com/codex/prime) roots in increasing order automatically scans candidate squares in increasing order as well.

### Step 2: Reverse the Decimal Expansion and Exclude Fixed Points

For a candidate square $s$, define its decimal reversal by

$$r=\operatorname{rev}(s).$$

The problem requires a genuinely different reversed value, so palindromes are rejected immediately:

$$s\ne r.$$

This is more than a cosmetic filter. If $s=r$, then the reversal gives back the same number instead of a distinct reversible partner. Also, for any [prime](https://ourbigbook.com/codex/prime) $p>5$, the square $p^2$ ends in $1$ or $9$, so its reversal begins in $1$ or $9$; there is no ambiguity from leading zeros.

### Step 3: Characterize When the Reversal Is Also a Prime Square

A [positive integer](https://ourbigbook.com/codex/positive-integer) is a [prime](https://ourbigbook.com/codex/prime) square exactly when it is a [perfect square](https://ourbigbook.com/codex/perfect-square) and its positive [square root](https://ourbigbook.com/codex/square-root) is [prime](https://ourbigbook.com/codex/prime). Therefore $s$ belongs to $\mathcal{R}$ if and only if

$$s=p^2,\qquad s\ne \operatorname{rev}(s),\qquad \operatorname{rev}(s)=q^2,\qquad p,q\in\mathbb{P}.$$

So the test for a reversed value $r$ is exact:

$$a=\left\lfloor\sqrt{r}\right\rfloor,\qquad a^2=r,\qquad a\in\mathbb{P}.$$

If either the square test fails or the [primality test](https://ourbigbook.com/codex/primality-test) fails, the original square is discarded.

### Step 4: Reversible Prime Squares Come in Distinct Pairs

Suppose $s=p^2\in\mathcal{R}$ and let $t=\operatorname{rev}(s)=q^2$. Reversing again gives

$$\operatorname{rev}(t)=s.$$

Because palindromes are excluded, we have $s\ne t$. Hence reversible [prime](https://ourbigbook.com/codex/prime) squares typically appear as two-way pairs $(s,t)$. The [algorithm](https://ourbigbook.com/codex/algorithm) does not need any special pairing logic: once it tests every [prime](https://ourbigbook.com/codex/prime) square in increasing order, both members of a valid pair will be encountered naturally.

### Step 5: Worked Example

The smallest example comes from

$$13^2=169,\qquad \operatorname{rev}(169)=961=31^2.$$

Since both $13$ and $31$ are [prime](https://ourbigbook.com/codex/prime), $169$ is valid. The reverse direction also works:

$$31^2=961,\qquad \operatorname{rev}(961)=169=13^2,$$

so $961$ is valid as well.

Two quick counterexamples illustrate the other filters. First,

$$11^2=121,\qquad \operatorname{rev}(121)=121,$$

so $121$ is rejected for being palindromic. Second,

$$17^2=289,\qquad \operatorname{rev}(289)=982,$$

and $982$ is not a [perfect square](https://ourbigbook.com/codex/perfect-square), so $289$ is rejected.

### Step 6: Why an Expanding Prime Bound Is Enough

The implementations generate [primes](https://ourbigbook.com/codex/prime) up to a current bound $B$, test every square $p^2$ with $p\le B$, and keep all valid values found in that pass. If fewer than $50$ values have been collected, the bound is enlarged and the search is repeated. This works because the candidate squares are examined in [strictly increasing](https://ourbigbook.com/codex/strictly-increasing) order. Once a pass finds at least $50$ reversible [prime](https://ourbigbook.com/codex/prime) squares, the first $50$ found are exactly the first $50$ elements of $\mathcal{R}$.

## How the Code Works

The C++, Python, and Java implementations all follow the same logical pipeline. They begin by constructing a [prime sieve](https://ourbigbook.com/codex/prime-sieve) up to a current bound and then iterate through the [primes](https://ourbigbook.com/codex/prime) in ascending order. Each [prime](https://ourbigbook.com/codex/prime) is squared, and palindromic squares are discarded before any more expensive work is done.

For every remaining square, the implementation reverses its decimal [digits](https://ourbigbook.com/codex/numerical-digit), computes an exact [integer square root](https://ourbigbook.com/codex/integer-square-root) of the reversed value, and checks whether the reversal is a [perfect square](https://ourbigbook.com/codex/perfect-square). If it is, the [square root](https://ourbigbook.com/codex/square-root) is then tested for [primality](https://ourbigbook.com/codex/primality). The [primality](https://ourbigbook.com/codex/primality) check uses deterministic [Miller-Rabin](https://ourbigbook.com/codex/miller-rabin-primality-test) after an initial screen by a short list of small [primes](https://ourbigbook.com/codex/prime), so the result is exact for the [integer](https://ourbigbook.com/codex/integer) range under consideration.

Whenever the reversed value is confirmed to be a [prime](https://ourbigbook.com/codex/prime) square, the original square is appended to the answer list. If the list reaches $50$ entries, the implementations sum those values and return the total. Otherwise they increase the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) bound and restart with a larger search range. The arithmetic details differ slightly by language, but the mathematical test is identical in all three implementations.

## Complexity Analysis

Let $B$ be the current [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) bound on the [prime](https://ourbigbook.com/codex/prime) root. Building the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) costs $O(B\log\log B)$ time and $O(B)$ memory. The number of candidates tested is $\pi(B)$, one for each [prime](https://ourbigbook.com/codex/prime) up to $B$. For each candidate, [digit](https://ourbigbook.com/codex/numerical-digit) reversal and [integer square root](https://ourbigbook.com/codex/integer-square-root) use $O(\log B)$ [digit](https://ourbigbook.com/codex/numerical-digit) work, while deterministic [Miller-Rabin](https://ourbigbook.com/codex/miller-rabin-primality-test) uses a fixed witness set, so in this setting the [primality](https://ourbigbook.com/codex/primality) certification is effectively constant-time per candidate and more formally requires $O(\log B)$ [modular multiplications](https://ourbigbook.com/codex/modular-multiplication). In practice the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) dominates the growth, with small extra work per [prime](https://ourbigbook.com/codex/prime) root.
