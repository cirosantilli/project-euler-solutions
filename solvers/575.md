# Project Euler 575 Solution - Wandering Robots

<https://projecteuler.net/problem=575>:

* [575.py](575.py)

## Key idea

After an “unfathomably long time”, Leonhard’s location follows the **[stationary distribution](https://ourbigbook.com/codex/stationary-distribution)** of a [finite Markov chain](https://ourbigbook.com/codex/finite-markov-chain) on an `n × n` grid (with moves to the 4-neighborhood and possibly staying put). The final answer is the average of two possible programs (coin flip).

## Technique 1: Stationary distribution by detailed balance

Both movement rules define a **[reversible](https://ourbigbook.com/codex/reversible-markov-chain) [random walk](https://ourbigbook.com/codex/random-walk)** on an undirected [grid graph](https://ourbigbook.com/codex/grid-graph):

- **Rule (i)**: choose uniformly among `{stay}` plus all adjacent rooms.  
  If a cell has `k` exits, every option has [probability](https://ourbigbook.com/codex/probability) `1/(k+1)`.

  This is the “choose a random incident [edge](https://ourbigbook.com/codex/edge-of-a-graph)” walk on a [graph](https://ourbigbook.com/codex/graph) where each [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) has **one [self-loop](https://ourbigbook.com/codex/loop-graph-theory)**.  
  The stationary weight is proportional to `k+1`.

- **Rule (ii)**: stay with [probability](https://ourbigbook.com/codex/probability) `1/2`, otherwise choose a random adjacent room.  
  This is a **lazy** version of the [simple random walk](https://ourbigbook.com/codex/simple-random-walk). Laziness does not change the [stationary distribution](https://ourbigbook.com/codex/stationary-distribution).  
  The stationary weight is proportional to `k`.

On an `n × n` grid, cells have `k = 4` (interior), `k = 3` (edge), `k = 2` (corner), so each [stationary distribution](https://ourbigbook.com/codex/stationary-distribution) only depends on these three classes.

## Technique 2: Reduce the 1,000,000-state problem to counting

We only need:

1. The **total stationary weight** of all interior/edge/corner cells (closed forms).
2. How many **perfect-square room numbers** land in each class.

A room number `x` maps to coordinates `(r, c)` by row-major indexing:

- `r = (x−1)//n + 1`
- `c = (x−1)%n + 1`

[Perfect squares](https://ourbigbook.com/codex/perfect-square) are `1², 2², …, n²`, so we just iterate `s = 1..n` (only 1000 iterations for the real task) and classify each square cell as interior/edge/corner.

## Technique 3: Exact rational arithmetic + rounding

All [probabilities](https://ourbigbook.com/codex/probability) are [rational numbers](https://ourbigbook.com/codex/rational-number) with small [integer](https://ourbigbook.com/codex/integer) weights, so we keep everything as `(numerator, denominator)` pairs, reduce by `gcd`, and only at the end format the result to **12 decimal places** using [integer](https://ourbigbook.com/codex/integer) rounding (half-up).

## Output

`main.py` prints the requested [probability](https://ourbigbook.com/codex/probability) for the `1000 × 1000` grid, rounded to 12 decimal places, and includes an `assert` for the sample value:

- `solve(5) == 0.177976190476`
