# Project Euler 552 Solution - Chinese Leftovers II

<https://projecteuler.net/problem=552>:

* [552.py](552.py)

## Core idea

We build the [sequence](https://ourbigbook.com/codex/sequence) \(A_n\) incrementally using the **[Chinese Remainder Theorem](https://ourbigbook.com/codex/chinese-remainder-theorem)** ([CRT](https://ourbigbook.com/codex/chinese-remainder-theorem)).

Let \(P_{n-1} = \prod_{i=1}^{n-1} p_i\).  
If we already have \(A_{n-1}\) satisfying all constraints up to \(p_{n-1}\), then

- \(A_n \equiv A_{n-1} \pmod{P_{n-1}}\)
- \(A_n \equiv n \pmod{p_n}\)

So \(A_n = A_{n-1} + tP_{n-1}\) for some \(t\), and we solve

\[
A_{n-1} + tP_{n-1} \equiv n \pmod{p_n}
\]

Because \(p_n\) is [prime](https://ourbigbook.com/codex/prime) and \(\gcd(P_{n-1}, p_n)=1\), we can compute

\[
t \equiv (n - A_{n-1}) \cdot (P_{n-1}^{-1} \bmod p_n) \pmod{p_n}
\]

using a [modular inverse](https://ourbigbook.com/codex/modular-inverse) (via [Fermat's little theorem](https://ourbigbook.com/codex/fermat-s-little-theorem): \(x^{-1} \equiv x^{p-2} \bmod p\)).

This gives the exact (big-integer) \(A_n\) and the running product \(P_n\).

## Finding which primes divide *any* \(A_n\)

A [prime](https://ourbigbook.com/codex/prime) \(q\) can only divide \(A_n\) while it’s **not yet among the first \(n\) [primes](https://ourbigbook.com/codex/prime)**, because if \(q=p_i\) is already constrained then
\(A_n \bmod q = i \ne 0\).

We want all [primes](https://ourbigbook.com/codex/prime) \(q \le 300000\) that divide at least one \(A_n\). The solver
does not materialize the enormous [integer](https://ourbigbook.com/codex/integer) \(A_n\). Instead, for each [prime](https://ourbigbook.com/codex/prime) `q`
it stores two [residue classes](https://ourbigbook.com/codex/residue-class):

\[
a(q)\equiv A_n\pmod q,\qquad m(q)\equiv P_n\pmod q.
\]

When a new [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) step uses correction `t` and [prime](https://ourbigbook.com/codex/prime) `p_n`, every still-future
[prime](https://ourbigbook.com/codex/prime) `q` is updated by:

\[
a(q)\leftarrow a(q)+t\,m(q)\pmod q,
\]

\[
m(q)\leftarrow m(q)\,p_n\pmod q.
\]

After the update, `q` divides the current `A_n` exactly when `a(q) == 0`.

## Only future primes are scanned

Once `q = p_j` has entered the [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) system, every later term has [residue class](https://ourbigbook.com/codex/residue-class) `j`
[modulo](https://ourbigbook.com/codex/modulo-operation) `q`, which is nonzero because `j < p_j`. Therefore stage `n` only scans
the [primes](https://ourbigbook.com/codex/prime) after `p_n`; earlier [primes](https://ourbigbook.com/codex/prime) are skipped forever.

Each marked [prime](https://ourbigbook.com/codex/prime) is included once in the final sum.

## Complexity notes

- [Prime](https://ourbigbook.com/codex/prime) generation: [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) up to 300000.
- [CRT](https://ourbigbook.com/codex/chinese-remainder-theorem) stages: one per [prime](https://ourbigbook.com/codex/prime) up to the limit.
- [Residue class](https://ourbigbook.com/codex/residue-class) updates: a triangular scan over the not-yet-entered [primes](https://ourbigbook.com/codex/prime).
- Storage: the [prime](https://ourbigbook.com/codex/prime) list, two [residue class](https://ourbigbook.com/codex/residue-class) arrays, and one marker array.

The final output printed by `main.py` is \(S(300000)\).
