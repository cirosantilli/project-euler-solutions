# Project Euler 59 Solution - XOR Decryption

<https://projecteuler.net/problem=59>:

* [59.py](59.py)
* [59.lean](59.lean)

## Key idea
The [ciphertext](https://ourbigbook.com/codex/ciphertext) is produced by XOR-ing each [plaintext](https://ourbigbook.com/codex/plaintext) ASCII [byte](https://ourbigbook.com/codex/byte) with a repeating 3-character lowercase key.  
Since the key length is only 3 and each character is in `a..z`, there are only `26^3 = 17576` keys to try.

## Approach
1. **Load cipher [bytes](https://ourbigbook.com/codex/byte)** from `0059_cipher.txt` (tries a few common paths); if unavailable, the program includes a fallback embedded copy.
2. **Brute-force all 3-letter lowercase keys**.
3. For each candidate key:
   - Decrypt on the fly using [Bitwise XOR](https://ourbigbook.com/codex/bitwise-exclusive-or) with the repeating key.
   - Reject the key immediately if any decrypted [byte](https://ourbigbook.com/codex/byte) is not printable ASCII (plus newline/carriage return).
   - Compute a simple **English-likeness score** based on spaces and common letter frequencies.
4. Select the key with the best score and output the **[sum](https://ourbigbook.com/codex/sum) of ASCII codes** of the decrypted [plaintext](https://ourbigbook.com/codex/plaintext).

## Complexity
- `17576` keys × `~1500` [bytes](https://ourbigbook.com/codex/byte) ≈ 26 million [Bitwise XOR](https://ourbigbook.com/codex/bitwise-exclusive-or)/score steps → runs comfortably in seconds on PyPy3.

## Output
Prints a single [integer](https://ourbigbook.com/codex/integer): the [sum](https://ourbigbook.com/codex/sum) of ASCII values of the decrypted message.
