# Project Euler 462 Solution - Permutation of 3-smooth Numbers

<https://projecteuler.net/problem=462>:

* [462.py](462.py)

## Core idea: turn the divisor constraint into a poset
Every 3‑[smooth number](https://ourbigbook.com/codex/smooth-number) can be written uniquely as:

- \(x = 2^a 3^b\) for [integers](https://ourbigbook.com/codex/integer) \(a,b \ge 0\)

For a fixed \(N\), the set \(S(N)\) is exactly the set of [exponent](https://ourbigbook.com/codex/exponent) pairs \((a,b)\) such that
\(2^a 3^b \le N\).

The rule “each element comes after all of its [proper divisors](https://ourbigbook.com/codex/proper-divisor)” becomes:

- \((a_1,b_1)\) must come before \((a_2,b_2)\) whenever \(a_1 \le a_2\) and \(b_1 \le b_2\)
  (and the pairs are different)

So we’re counting **[linear extensions](https://ourbigbook.com/codex/linear-extension)** of a 2D dominance-order [poset](https://ourbigbook.com/codex/partially-ordered-set).

## Ferrers/Young diagram shape
Fix \(b\). The maximum allowed \(a\) is:

\[
a_{\max}(b) = \left\lfloor \log_2\left(\frac{N}{3^b}\right) \right\rfloor
\]

So each \(b\) gives a row of length \(a_{\max}(b) + 1\). As \(b\) increases, \(N/3^b\) decreases,
so these row lengths are **non‑increasing**: a [Ferrers (Young) diagram](https://ourbigbook.com/codex/ferrers-diagram).

That’s the key structural simplification: **counting valid [permutations](https://ourbigbook.com/codex/permutation) = counting [standard Young tableaux](https://ourbigbook.com/codex/standard-young-tableau)** of that shape.

## Hook-length formula
For a [Ferrers diagram](https://ourbigbook.com/codex/ferrers-diagram) with \(n\) cells, the number of [standard Young tableaux](https://ourbigbook.com/codex/standard-young-tableau) is:

\[
F = \frac{n!}{\prod_{\text{cells }c} h(c)}
\]

where \(h(c)\) is the cell’s **[hook length](https://ourbigbook.com/codex/hook-length)** (cells to the right + cells below + 1).

Because the diagram for \(N = 10^{18}\) has only about ~1100 cells, we can compute:

- \(n!\) as a big [integer](https://ourbigbook.com/codex/integer)
- the [hook product](https://ourbigbook.com/codex/hook-product) as a big [integer](https://ourbigbook.com/codex/integer)
- divide exactly (the result is guaranteed to be an [integer](https://ourbigbook.com/codex/integer))

No [floating-point arithmetic](https://ourbigbook.com/codex/floating-point-arithmetic) is needed for the main computation.

## Fast construction details
- Row length for a given \(b\) is `bit_length(N // 3**b)`, i.e. \(\lfloor \log_2(\cdot)\rfloor + 1\).
- Column heights are computed efficiently from the non‑increasing row lengths.
- [Hook lengths](https://ourbigbook.com/codex/hook-length) follow:
  \[
  h(i,j) = (\text{row\_len} - j) + (\text{col\_height}(j) - i) - 1
  \]

## Output formatting
[Project Euler](https://ourbigbook.com/codex/project-euler) requests [scientific notation](https://ourbigbook.com/codex/scientific-notation) with **10 [digits](https://ourbigbook.com/codex/numerical-digit) after the decimal point**.
The solution formats the exact [integer](https://ourbigbook.com/codex/integer) and performs **half‑up [rounding](https://ourbigbook.com/codex/rounding)** using string slicing.
