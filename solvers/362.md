# Project Euler 362 Solution - Squarefree Factors

<https://projecteuler.net/problem=362>:

* [362.py](362.py)

We want

- **Fsf(n)**: the number of factorizations of `n` into **[squarefree](https://ourbigbook.com/codex/squarefree-integer)** factors `> 1`, where order does not matter.
- **S(N)**: `sum_{k=2..N} Fsf(k)`, specifically `S(10^10)`.

## 1) Rewriting the counting problem (Fsf)

Let

```
n = p1^e1 * p2^e2 * ... * pk^ek
```

A [squarefree](https://ourbigbook.com/codex/squarefree-integer) factor can contain each [prime](https://ourbigbook.com/codex/prime) **at most once**. So each factor corresponds to a **nonempty subset** of `{p1, …, pk}`.

If we let `m_A` be the multiplicity of subset `A` in the factor multiset, then:

- For each [prime](https://ourbigbook.com/codex/prime) `pi`, its [exponent](https://ourbigbook.com/codex/exponent) must be matched exactly:

```
sum_{A contains i} m_A = ei
```

So **Fsf(n)** becomes:

> The number of [nonnegative integer](https://ourbigbook.com/codex/nonnegative-integer) solutions `{m_A}` to the [linear system](https://ourbigbook.com/codex/linear-system) above  
> (one variable for each nonempty subset).

This depends only on the **[exponent](https://ourbigbook.com/codex/exponent) multiset** `(e1,…,ek)`, not on the [prime](https://ourbigbook.com/codex/prime) values.

### Computing Fsf from exponents

That solution count is exactly a multivariate generating-function [coefficient](https://ourbigbook.com/codex/coefficient):

```
Fsf = [x1^e1 ... xk^ek]  ∏_{A≠∅} 1 / (1 - ∏_{i∈A} xi)
```

Because `k ≤ 10` for `n ≤ 10^10`, the [state space](https://ourbigbook.com/codex/state-space) is small. The implementation performs a compact multi-dimensional “unbounded knapsack” [DP](https://ourbigbook.com/codex/dynamic-programming) in mixed radix to extract the needed [coefficient](https://ourbigbook.com/codex/coefficient) efficiently, with [memoization](https://ourbigbook.com/codex/memoization) on the [exponent](https://ourbigbook.com/codex/exponent) tuple.

Special case:
- If all [exponents](https://ourbigbook.com/codex/exponent) are `1` ([squarefree](https://ourbigbook.com/codex/squarefree-integer) `n`), then `Fsf(n)` is the **[Bell number](https://ourbigbook.com/codex/bell-number)** `B_k` ([set partitions](https://ourbigbook.com/codex/set-partition) of the `k` [primes](https://ourbigbook.com/codex/prime)).

## 2) Summing up to 10^10 without iterating all n

Every `n > 1` has a [unique factorization](https://ourbigbook.com/codex/unique-factorization) with **increasing [primes](https://ourbigbook.com/codex/prime)**:

```
n = p1^a1 * p2^a2 * ... * pk^ak,   with p1 < p2 < ... < pk
```

So we can sum over all possible **ordered [exponent](https://ourbigbook.com/codex/exponent) [sequences](https://ourbigbook.com/codex/sequence)** `(a1,...,ak)` and count how many [prime](https://ourbigbook.com/codex/prime) tuples realize them:

```
S(N) = Σ_{exponent sequences a}  Fsf(sorted(a)) * count_primes(a, N)
```

### Counting prime tuples for a fixed exponent sequence

For a [sequence](https://ourbigbook.com/codex/sequence) `(a1,...,ak)`, we count tuples `p1 < ... < pk` such that

```
p1^a1 * ... * pk^ak ≤ N
```

This is done by [recursion](https://ourbigbook.com/codex/recursion) over the [prime](https://ourbigbook.com/codex/prime) choices, with an important pruning step:

- For each [recursion](https://ourbigbook.com/codex/recursion) level, we compute the **minimal possible product** for the remaining suffix using the *next* consecutive [primes](https://ourbigbook.com/codex/prime).
- Once the minimal suffix can’t fit, we **break** ([monotonicity](https://ourbigbook.com/codex/monotonicity) guarantees no later [primes](https://ourbigbook.com/codex/prime) can work).

The last [prime](https://ourbigbook.com/codex/prime) choice uses `π(x)` ([prime](https://ourbigbook.com/codex/prime) counting) instead of iterating [primes](https://ourbigbook.com/codex/prime).

## 3) Fast π(x) via Lehmer prime counting

Counting [primes](https://ourbigbook.com/codex/prime) up to `10^10` requires something faster than sieving to `10^10`.

This solution uses **[Lehmer's prime counting algorithm](https://ourbigbook.com/codex/lehmer-prime-counting-algorithm)**:

- A [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) up to about `N^(2/3)` (≈ 5 million) provides small [primes](https://ourbigbook.com/codex/prime) and a lookup table `π(x)` for `x ≤ sieve_limit`.
- [Lehmer prime-counting algorithm](https://ourbigbook.com/codex/lehmer-prime-counting-algorithm) reduces `π(x)` to a few recursive `π()` calls and `φ(x, s)` computations.

A small cache for `φ(x, s)` (only for small `x`) keeps memory reasonable while still accelerating `π(x)`.
