# Project Euler 867 Solution - Tiling Dodecagon

<https://projecteuler.net/problem=867>:

* [867.py](867.py)

This repository solves the “[tiling](https://ourbigbook.com/codex/tessellation) a regular [dodecagon](https://ourbigbook.com/codex/dodecagon)” task for `n = 10` and prints the result [modulo](https://ourbigbook.com/codex/modulo-operation) `1_000_000_007`.

## Key ideas

### 1) Corner forcing in a dodecagon
At each 150° corner of a regular [dodecagon](https://ourbigbook.com/codex/dodecagon), the only way to fill the angle using unit [regular polygons](https://ourbigbook.com/codex/regular-polygon) (with edges aligned) is to combine a [unit square](https://ourbigbook.com/codex/unit-square) and a unit [equilateral triangle](https://ourbigbook.com/codex/equilateral-triangle). That local restriction propagates:

- If a side is adjacent to the square at its endpoints, the entire strip along that side is forced to be squares (so rectangles are uniquely tiled).
- The adjacent side (paired with [triangles](https://ourbigbook.com/codex/triangle) at the endpoints) can only be completed using unit [triangles](https://ourbigbook.com/codex/triangle) and unit [hexagons](https://ourbigbook.com/codex/hexagon).

This lets us “peel” the [dodecagon](https://ourbigbook.com/codex/dodecagon) layer by layer, reducing it to a smaller equiangular 12‑gon plus 6 identical corner regions.

### 2) A recursion on alternating side lengths
Define an equiangular 12‑gon by alternating side lengths `(u, v)`.

Peeling a layer of thickness `(u - w)` turns `(u, v)` into `(v, w)` and creates **six** congruent corner regions. The [recurrence relation](https://ourbigbook.com/codex/recurrence-relation) therefore has the form:

- a [base case](https://ourbigbook.com/codex/base-case) when the inner shape becomes a regular [hexagon](https://ourbigbook.com/codex/hexagon),
- a sum over all valid peel thicknesses `w`,
- a `corner_count^6` multiplier for the six identical corners.

A small indicator term handles the one exceptional “unit [dodecagon](https://ourbigbook.com/codex/dodecagon)” [tiling](https://ourbigbook.com/codex/tessellation).

### 3) Counting triangle/hexagon tilings via independent sets
Both the central [hexagon](https://ourbigbook.com/codex/hexagon) and the corner regions can be tiled only with **unit [triangles](https://ourbigbook.com/codex/triangle) and unit [hexagons](https://ourbigbook.com/codex/hexagon)**.

Start from the all‑[triangle](https://ourbigbook.com/codex/triangle) triangulation. Placing a unit [hexagon](https://ourbigbook.com/codex/hexagon) corresponds to selecting a “center” position in a derived lattice; selected centers must be non‑adjacent to avoid overlap. The remaining area is then automatically filled by unit [triangles](https://ourbigbook.com/codex/triangle).

So the counting problem becomes:

> Count [independent sets](https://ourbigbook.com/codex/independent-set) in a small lattice [graph](https://ourbigbook.com/codex/graph).

### 4) Bitmask DP with a subset‑sum speedup
The center lattice can be scanned row by row. Each row is encoded by a [bitmask](https://ourbigbook.com/codex/bit-mask); valid masks have no adjacent `1` bits.

Between consecutive rows, adjacency constraints depend only on whether the next row is longer by 1 or shorter by 1. For a fixed next‑row mask, the set of compatible previous‑row masks is exactly a **subset constraint**, enabling a fast subset‑sum (zeta transform) to aggregate transitions efficiently.

This makes the computation for all required subregions fast enough in pure Python.
