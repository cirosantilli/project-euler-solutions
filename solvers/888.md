# Project Euler 888 Solution - 1249 Nim

<https://projecteuler.net/problem=888>:

* [888.py](888.py)

This solution counts [losing positions](https://ourbigbook.com/codex/losing-position) in a multi-pile [impartial game](https://ourbigbook.com/codex/impartial-game) where a move is either:

- remove `1, 2, 4, or 9` stones from a pile, or
- split a pile into two non-empty piles.

A position with multiple piles is losing exactly when the [XOR](https://ourbigbook.com/codex/xor) of the piles’ [Grundy numbers](https://ourbigbook.com/codex/grundy-number) is `0`.

## Techniques used

### 1) Sprague–Grundy reduction

For one pile of size `n`, its [Grundy number](https://ourbigbook.com/codex/grundy-number) `g(n)` is the [mex](https://ourbigbook.com/codex/minimum-excludant) of the [Grundy numbers](https://ourbigbook.com/codex/grundy-number) of all reachable positions:

- subtraction moves: `g(n-1), g(n-2), g(n-4), g(n-9)` (when defined),
- split moves: `g(i) XOR g(n-i)` for `1 ≤ i < n`.

The program computes a table of `g(n)` for a moderate prefix and stores them in a list.

### 2) Using a small split window

The split move naively requires scanning all `i < n`, which is quadratic.
Empirically (and consistent with the structure of this game), it is enough to consider splits where one part is at most a few hundred stones.
The program uses a conservative fixed bound and **verifies** it matches the full split computation on a sizeable prefix.

This keeps the Grundy precomputation essentially linear in the table size.

### 3) Periodicity check for fast counting

After a short “preperiod”, the computed [Grundy values](https://ourbigbook.com/codex/grundy-value) repeat with a fixed period.
The code does not assume this silently: it computes two consecutive periods and asserts that the repetition holds across the entire overlap.
Once validated, counting how many pile sizes `≤ N` yield each [Grundy value](https://ourbigbook.com/codex/grundy-value) becomes an `O(1)` arithmetic task.

### 4) Counting multisets with XOR = 0 via a ±1 filter

We need the number of **unordered** selections of `m` pile sizes from `{1..N}` such that the [XOR](https://ourbigbook.com/codex/xor) of their [Grundy numbers](https://ourbigbook.com/codex/grundy-number) is `0`.

A key simplification is that, in [XOR](https://ourbigbook.com/codex/xor), only the **[integer parity](https://ourbigbook.com/codex/integer-parity)** of how many times a given pile size is chosen matters.
This leads to a [generating function](https://ourbigbook.com/codex/generating-function) where each pile size contributes:

- even copies: `1 + x^2 + x^4 + …`
- odd copies:  `x * (sign depending on g(n))` times the same even series

This can be handled by introducing four sign variables (one per Grundy bit), then applying a 16-point “[roots of unity](https://ourbigbook.com/codex/root-of-unity)” / Walsh–Hadamard-style filter by substituting each sign as `±1`.
For each of the 16 substitutions, the whole product collapses to a [rational function](https://ourbigbook.com/codex/rational-function) depending only on one [integer](https://ourbigbook.com/codex/integer) `a` (how many pile sizes map to `+1` under that substitution):

\[
(1-x)^{-a} (1+x)^{-(N-a)}.
\]

The desired count is the average of the `x^m` coefficients over all 16 substitutions.

Overall complexity for the counting step is `O(16·m)`.

### 5) Working modulo a composite number

The requested modulus is not guaranteed [prime](https://ourbigbook.com/codex/prime).
The code factors the modulus into [prime powers](https://ourbigbook.com/codex/prime-power), computes each coefficient [modulo](https://ourbigbook.com/codex/modulo-operation) each [prime power](https://ourbigbook.com/codex/prime-power), and recombines them using the [Chinese Remainder Theorem](https://ourbigbook.com/codex/chinese-remainder-theorem).

Because `m` is small, binomial-series coefficients are built incrementally while tracking [prime factors](https://ourbigbook.com/codex/prime-factor) explicitly (removing factors of `p` before taking [modular inverses](https://ourbigbook.com/codex/modular-inverse)).
