# Project Euler 367 Solution - Bozo Sort

<https://projecteuler.net/problem=367>:

* [367.py](367.py)

This problem asks for the expected number of *3-element shuffles* needed to sort a random [permutation](https://ourbigbook.com/codex/permutation) of `1..11`, where each step:

1. Checks whether the [sequence](https://ourbigbook.com/codex/sequence) is sorted (the identity [permutation](https://ourbigbook.com/codex/permutation)).
2. If not, picks **3 distinct positions uniformly** and applies a **[uniform random permutation](https://ourbigbook.com/codex/uniform-random-permutation)** of the chosen 3 elements (all `3! = 6` outcomes equally likely, including “no change”).

Because the input is averaged over all `11!` [permutations](https://ourbigbook.com/codex/permutation), the starting distribution is **uniform over** `S₁₁`.

## Main ideas used

### 1) Markov chain as a random walk on `Sₙ`
The [algorithm](https://ourbigbook.com/codex/algorithm) is a [Markov chain](https://ourbigbook.com/codex/markov-chain) on [permutations](https://ourbigbook.com/codex/permutation). Each shuffle corresponds to multiplying the current [permutation](https://ourbigbook.com/codex/permutation) by a [random element](https://ourbigbook.com/codex/random-element) that:
- is the identity with [probability](https://ourbigbook.com/codex/probability) `1/6`,
- is a transposition with total [probability](https://ourbigbook.com/codex/probability) `1/2`,
- is a 3-cycle with total [probability](https://ourbigbook.com/codex/probability) `1/3`.

This walk is **symmetric** ([probability](https://ourbigbook.com/codex/probability) of `g` equals [probability](https://ourbigbook.com/codex/probability) of `g⁻¹`) and **class-invariant** (depends only on [cycle type](https://ourbigbook.com/codex/cycle-type)), so it has a very clean spectral description.

### 2) Expected hitting time from the stationary (uniform) distribution
For a symmetric [random walk](https://ourbigbook.com/codex/random-walk) on a [finite group](https://ourbigbook.com/codex/finite-group) with **uniform [stationary distribution](https://ourbigbook.com/codex/stationary-distribution)**, the expected time to *hit the identity* when starting from uniform can be written purely in terms of [irreducible representations](https://ourbigbook.com/codex/irreducible-representation):

\[
\mathbb{E}[T_{\text{id}}] \;=\; \sum_{\rho \neq \text{trivial}} \frac{d_\rho^2}{1-\lambda_\rho},
\]

where:
- `dρ` is the irrep dimension,
- `λρ` is the [eigenvalue](https://ourbigbook.com/codex/eigenvalue) of the [transition operator](https://ourbigbook.com/codex/transition-operator) on that irrep.

So we never build the `11! × 11!` [transition matrix](https://ourbigbook.com/codex/transition-matrix).

### 3) Representation theory of `Sₙ` via partitions
[Irreducible representations](https://ourbigbook.com/codex/irreducible-representation) of `Sₙ` are indexed by [integer partitions](https://ourbigbook.com/codex/integer-partition) of `n`.
For each partition `λ` we need:
- the dimension `dλ` ([hook-length formula](https://ourbigbook.com/codex/hook-length-formula)),
- the normalized character ratios at a transposition and at a 3-cycle.

The [eigenvalue](https://ourbigbook.com/codex/eigenvalue) for this problem is:

\[
\lambda_\lambda = \tfrac16 + \tfrac12 r_2(\lambda) + \tfrac13 r_3(\lambda),
\]
where `r₂ = χ(transposition)/d` and `r₃ = χ(3-cycle)/d`.

### 4) Characters for small cycles using Murnaghan–Nakayama
To get `χ(2,1^{n-2})` and `χ(3,1^{n-3})`, we use the **[Murnaghan–Nakayama rule](https://ourbigbook.com/codex/murnaghan-nakayama-rule)** specialized to a single `k`-cycle:

\[
\chi^\lambda(k,1^{n-k}) = \sum_{\text{rim hooks of size }k} (-1)^{\text{height}}\, f^{\nu},
\]

where removing that [rim hook](https://ourbigbook.com/codex/rim-hook) from `λ` leaves a smaller partition `ν`, and `f^ν` is its dimension.

Since `k ∈ {2,3}` and `n=11`, [rim hooks](https://ourbigbook.com/codex/rim-hook) can be enumerated by [brute force](https://ourbigbook.com/codex/brute-force-search) over subsets of boxes (only up to `C(11,3)=165` candidates per partition).

### 5) Exact arithmetic
All values are computed with `fractions.Fraction`, so the final [expectation](https://ourbigbook.com/codex/expectation) is exact and only the very last step does rounding to the nearest [integer](https://ourbigbook.com/codex/integer).
