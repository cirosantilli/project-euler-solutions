## Approach

We need the 10,001st [prime](https://ourbigbook.com/codex/prime-number).

### Key ideas
- Use the standard [upper bound](https://ourbigbook.com/codex/upper-bound) for the `n`th [prime](https://ourbigbook.com/codex/prime-number) (valid for `n >= 6`):
  \[
  p_n < n(\ln n + \ln\ln n)
  \]
  This gives a good initial [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) limit, and we can double the limit if it turns out to be too small.
- Use the [Sieve of Eratosthenes](https://ourbigbook.com/codex/sieve-of-eratosthenes), optimized to store only [odd numbers](https://ourbigbook.com/codex/odd-number):
  - Index `i` represents the number `2*i + 1`.
  - Mark [multiples](https://ourbigbook.com/codex/integer-multiple) starting from `p*p`.

### Complexity
- Time: `O(L log log L)` for [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) limit `L`
- Space: `O(L)` but halved by storing only odds

The computed result is printed at the end.
