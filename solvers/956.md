# Project Euler 956 Solution - Super Duper Sum

<https://projecteuler.net/problem=956>:

* [956.py](956.py)

## Problem Summary

The quantity behind Problem 956 can be collapsed to a single [integer](https://ourbigbook.com/codex/integer)

$$N_n=\prod_{t=1}^{n} t^{c_t},\qquad c_t=\binom{n-t+2}{2}=\frac{(n-t+1)(n-t+2)}{2}.$$

The required value is the sum of those [divisors](https://ourbigbook.com/codex/divisor) $d\mid N_n$ for which the total exponent count

$$\Omega(d)=\sum_p \alpha_p$$

is divisible by $m$, where $d=\prod_p p^{\alpha_p}$. The implementations evaluate the case $n=m=1000$ and reduce the answer [modulo](https://ourbigbook.com/codex/modulo-operation) $999999001$.

A brute-force [divisor](https://ourbigbook.com/codex/divisor) enumeration is impossible. Even after [prime factorization](https://ourbigbook.com/codex/prime-factorization), the exponent bounds $E_p$ of $N_{1000}$ are enormous, so the [number of divisors](https://ourbigbook.com/codex/number-of-divisors) is astronomically large. The workable approach is to separate the contribution of each [prime](https://ourbigbook.com/codex/prime) and track only the residue of the exponent sum [modulo](https://ourbigbook.com/codex/modulo-operation) $m$.

## Mathematical Approach

The entire solution is a prime-by-prime generating-function computation. The key is that the condition $\Omega(d)\equiv 0 \pmod m$ depends only on exponent residues, while the [divisor](https://ourbigbook.com/codex/divisor) value $d$ factors multiplicatively over [primes](https://ourbigbook.com/codex/prime).

### Collapsing the weighted product

The code never expands the nested product directly. Instead it records how many times each [integer](https://ourbigbook.com/codex/integer) $t$ appears after everything is flattened. That multiplicity is the [triangular number](https://ourbigbook.com/codex/triangular-number) $c_t$, so the whole object is exactly $N_n=\prod t^{c_t}$.

For any [prime](https://ourbigbook.com/codex/prime) $p$, the exponent of $p$ in $N_n$ is therefore

$$E_p=v_p(N_n)=\sum_{t=1}^{n} c_t\,v_p(t).$$

Once all $E_p$ are known, the original problem has been reduced to a divisor-sum problem on the [prime factorization](https://ourbigbook.com/codex/prime-factorization)

$$N_n=\prod_p p^{E_p}.$$

### Divisors as exponent vectors

Every [divisor](https://ourbigbook.com/codex/divisor) of $N_n$ has the form

$$d=\prod_p p^{\alpha_p},\qquad 0\le \alpha_p\le E_p.$$

The quantity being summed is the value of the [divisor](https://ourbigbook.com/codex/divisor) itself, not just the number of admissible [divisors](https://ourbigbook.com/codex/divisor). So a choice of [exponent vector](https://ourbigbook.com/codex/exponent-vector) $(\alpha_p)$ contributes

$$\prod_p p^{\alpha_p}.$$

The only global constraint is

$$\Omega(d)=\sum_p \alpha_p\equiv 0 \pmod m.$$

This is exactly the kind of condition that can be handled by a residue-class [convolution](https://ourbigbook.com/codex/convolution).

### A generating function that matches the divisor sum

For a fixed [prime](https://ourbigbook.com/codex/prime) $p$, introduce

$$F_p(x)=\sum_{a=0}^{E_p} p^a x^a.$$

Multiplying these factors over all [primes](https://ourbigbook.com/codex/prime) gives

$$F(x)=\prod_p F_p(x).$$

The [coefficient](https://ourbigbook.com/codex/coefficient) of $x^k$ in $F(x)$ is precisely the sum of all [divisor](https://ourbigbook.com/codex/divisor) values $d\mid N_n$ with $\Omega(d)=k$, because choosing the term $p^{\alpha_p}x^{\alpha_p}$ from each [prime](https://ourbigbook.com/codex/prime) contributes the [divisor](https://ourbigbook.com/codex/divisor) value and records the total exponent count in the power of $x$.

We do not need the exact exponent total $k$; only its residue [modulo](https://ourbigbook.com/codex/modulo-operation) $m$ matters. So we can work in the [quotient ring](https://ourbigbook.com/codex/quotient-ring) where $x^m=1$. In that setting, each [prime](https://ourbigbook.com/codex/prime) contributes only $m$ [residue classes](https://ourbigbook.com/codex/residue-class):

$$F_p(x)\equiv \sum_{r=0}^{m-1} C_{p,r}x^r \pmod{x^m-1},$$

with

$$C_{p,r}=\sum_{\substack{0\le a\le E_p\\ a\equiv r \pmod m}} p^a.$$

The desired answer is then the [coefficient](https://ourbigbook.com/codex/coefficient) of $x^0$ in the product of these reduced [polynomials](https://ourbigbook.com/codex/polynomial).

### Closed form for one residue class

If $E_p<r$, then $C_{p,r}=0$. Otherwise the admissible exponents are

$$a=r,\ r+m,\ r+2m,\ \dots,\ r+(N_{p,r}-1)m,$$

where

$$N_{p,r}=\left\lfloor\frac{E_p-r}{m}\right\rfloor+1.$$

Let $q=p^m$. Then

$$C_{p,r}=p^r\sum_{j=0}^{N_{p,r}-1} q^j.$$

[Modulo](https://ourbigbook.com/codex/modulo-operation) $M=999999001$, this becomes a [geometric series](https://ourbigbook.com/codex/geometric-series). If $q\not\equiv 1 \pmod M$, then

$$C_{p,r}\equiv p^r\,(q^{N_{p,r}}-1)\,(q-1)^{-1}\pmod M.$$

If $q\equiv 1 \pmod M$, the [denominator](https://ourbigbook.com/codex/denominator) would vanish, and the sum collapses to

$$C_{p,r}\equiv p^r\,N_{p,r}\pmod M.$$

This is the only subtle modular case in the entire computation.

### Worked example: $n=m=3$

Here

$$c_1=6,\qquad c_2=3,\qquad c_3=1,$$

so

$$N_3=1^6\cdot 2^3\cdot 3=24=2^3\cdot 3.$$

We want [divisors](https://ourbigbook.com/codex/divisor) whose total exponent count is a multiple of $3$. For the [prime](https://ourbigbook.com/codex/prime) $2$ with exponent $3$, the residue-class sums are

$$C_{2,0}=1+2^3=9,\qquad C_{2,1}=2,\qquad C_{2,2}=4.$$

For the [prime](https://ourbigbook.com/codex/prime) $3$ with exponent $1$, they are

$$C_{3,0}=1,\qquad C_{3,1}=3,\qquad C_{3,2}=0.$$

To obtain total residue $0\pmod 3$, we combine residue pairs $(0,0)$, $(2,1)$, and $(1,2)$. Therefore the required sum is

$$9\cdot 1+4\cdot 3+2\cdot 0=21.$$

Indeed the valid [divisors](https://ourbigbook.com/codex/divisor) are $1$, $8$, and $12$, and their sum is $21$. This small case is exactly the same [convolution](https://ourbigbook.com/codex/convolution) that the full solution performs for $n=m=1000$.

### Why only $m$ states are needed

After reducing exponents [modulo](https://ourbigbook.com/codex/modulo-operation) $m$, the [coefficient](https://ourbigbook.com/codex/coefficient) [vector](https://ourbigbook.com/codex/vector) for each [prime](https://ourbigbook.com/codex/prime) has length $m$. Multiplying in another [prime](https://ourbigbook.com/codex/prime) means a [cyclic convolution](https://ourbigbook.com/codex/cyclic-convolution) on those $m$ residues. No larger [state space](https://ourbigbook.com/codex/state-space) is needed, because the problem never distinguishes between exponent totals that differ by a multiple of $m$.

## How the Code Works

### Prime-exponent preprocessing

The C++, Python, and Java implementations first build a smallest-prime-factor table up to $n$. Then they scan $t=1,2,\dots,n$, factor each $t$, and add $c_t\,v_p(t)$ to the stored exponent of every [prime](https://ourbigbook.com/codex/prime) $p$ appearing in $t$. At the end of this pass they know every nonzero $E_p$ in the factorization of $N_n$.

### Residue tables for each prime

For each [prime](https://ourbigbook.com/codex/prime) $p$, the implementation computes the $m$ numbers $C_{p,0},C_{p,1},\dots,C_{p,m-1}$ [modulo](https://ourbigbook.com/codex/modulo-operation) $M$. Instead of summing powers one by one, it maintains the current factor $p^r$ and evaluates the remaining [geometric series](https://ourbigbook.com/codex/geometric-series) in [closed form](https://ourbigbook.com/codex/closed-form). The branch $p^m\equiv 1\pmod M$ is handled separately so that no invalid [modular inverse](https://ourbigbook.com/codex/modular-inverse) is taken.

### The dynamic-programming invariant

After processing any [subset](https://ourbigbook.com/codex/subset) of the [primes](https://ourbigbook.com/codex/prime), the [state vector](https://ourbigbook.com/codex/state-vector) satisfies the [invariant](https://ourbigbook.com/codex/invariant)

The state $\mathrm{dp}[r]$ is the sum of [divisor](https://ourbigbook.com/codex/divisor) values formed from the processed [primes](https://ourbigbook.com/codex/prime) whose total exponent residue is $r$.

When a new [prime](https://ourbigbook.com/codex/prime) is incorporated, the update is the [cyclic convolution](https://ourbigbook.com/codex/cyclic-convolution)

$$\mathrm{next}[(r+t)\bmod m]\;{+}{=}\;\mathrm{dp}[r]\cdot C_{p,t}\pmod M.$$

After the final [prime](https://ourbigbook.com/codex/prime) has been processed, $\mathrm{dp}[0]$ is exactly the required answer. The C++ and Java versions also compare the modular routine against a tiny exact computation on a small sample, which is a good sanity check for the formulae.

## Complexity Analysis

The [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) used to build [smallest prime factors](https://ourbigbook.com/codex/smallest-prime-factor) is linear in $n$. Factoring every $t\le n$ by repeated division through that table is close to linear for these input sizes and is much cheaper than the final [convolution](https://ourbigbook.com/codex/convolution) phase.

The dominant cost is the residue [DP](https://ourbigbook.com/codex/dynamic-programming). If $\pi(n)$ denotes the number of [primes](https://ourbigbook.com/codex/prime) up to $n$, then the transition over all [primes](https://ourbigbook.com/codex/prime) uses $O(\pi(n)m^2)$ modular operations, because each [prime](https://ourbigbook.com/codex/prime) contributes an $m\times m$ [cyclic convolution](https://ourbigbook.com/codex/cyclic-convolution). [Memory usage](https://ourbigbook.com/codex/memory-usage) is $O(n+m)$: the [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) and exponent arrays take $O(n)$, and the [algorithm](https://ourbigbook.com/codex/algorithm) needs only a constant number of [DP](https://ourbigbook.com/codex/dynamic-programming) buffers of length $m$.
