# Project Euler 265 Solution - Binary Circles

<https://projecteuler.net/problem=265>:

* [265.py](265.py)

## Problem Summary

For a fixed $n$, we want [binary circles](https://ourbigbook.com/codex/binary-circle) in which every $n$-[bit](https://ourbigbook.com/codex/bit) block appears exactly once as a cyclic substring. The problem asks for the sum of the binary [integers](https://ourbigbook.com/codex/integer) represented by all such [circles](https://ourbigbook.com/codex/circle), using the canonical representation chosen by the solver.

The implementation does not search the space of [bit](https://ourbigbook.com/codex/bit) strings directly. Instead, it models the problem as an [Eulerian-cycle](https://ourbigbook.com/codex/eulerian-cycle) search in a [De Bruijn graph](https://ourbigbook.com/codex/de-bruijn-graph) and enumerates every valid cycle with depth-first [backtracking](https://ourbigbook.com/codex/backtracking).

## Mathematical Approach

### 1. From Binary Circles to De Bruijn Graphs

A [binary circle](https://ourbigbook.com/codex/binary-circle) of order $n$ is a cyclic [bit](https://ourbigbook.com/codex/bit) [sequence](https://ourbigbook.com/codex/sequence) whose cyclic length-$n$ substrings are exactly the $2^n$ possible $n$-[bit](https://ourbigbook.com/codex/bit) patterns. That condition is naturally encoded by the [De Bruijn graph](https://ourbigbook.com/codex/de-bruijn-graph) of order $n$.

The [graph](https://ourbigbook.com/codex/graph) has:

$$|V|=2^{n-1},\qquad |E|=2^n.$$

Each [vertex](https://ourbigbook.com/codex/vertex-graph-theory) is an $(n-1)$-[bit](https://ourbigbook.com/codex/bit) string. Each [edge](https://ourbigbook.com/codex/edge) is an $n$-[bit](https://ourbigbook.com/codex/bit) string, viewed as a transition from its first $n-1$ [bits](https://ourbigbook.com/codex/bit) to its last $n-1$ [bits](https://ourbigbook.com/codex/bit).

### 2. Edge Transition Rule

If the current [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) is $u$ and we append a [bit](https://ourbigbook.com/codex/bit) $b\in\{0,1\}$, then the next [edge](https://ourbigbook.com/codex/edge) label is

$$e=((u\ll 1)\,|\,b)\ \&\ (2^n-1),$$

and the next [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) is its suffix of length $n-1$:

$$v=e\ \&\ (2^{n-1}-1).$$

So the [DFS](https://ourbigbook.com/codex/depth-first-search) is literally walking through the [De Bruijn graph](https://ourbigbook.com/codex/de-bruijn-graph) one [edge](https://ourbigbook.com/codex/edge) at a time, where every [edge](https://ourbigbook.com/codex/edge) corresponds to one $n$-[bit](https://ourbigbook.com/codex/bit) block.

### 3. Why Eulerian Cycles Are Exactly the Answers

Traversing every [edge](https://ourbigbook.com/codex/edge) exactly once means that every $n$-[bit](https://ourbigbook.com/codex/bit) pattern appears exactly once. That is precisely the definition of the required [binary circle](https://ourbigbook.com/codex/binary-circle).

Conversely, any [binary circle](https://ourbigbook.com/codex/binary-circle) determines a [closed walk](https://ourbigbook.com/codex/closed-walk) in the [graph](https://ourbigbook.com/codex/graph), because consecutive length-$n$ windows overlap in their last $n-1$ [bits](https://ourbigbook.com/codex/bit). Therefore the problem is equivalent to enumerating [Eulerian cycles](https://ourbigbook.com/codex/eulerian-cycle) in this [directed graph](https://ourbigbook.com/codex/directed-graph).

### 4. Canonical Rooting at $0^n$

Cycles are circular, so the same cycle can be rotated. The solver removes this rotational ambiguity by fixing the starting block to be $0^n$. In the code this is done by marking [edge](https://ourbigbook.com/codex/edge) 0 as already used and starting the [DFS](https://ourbigbook.com/codex/depth-first-search) at [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) 0.

This anchor gives one canonical representative per cycle. Without it, the same [circle](https://ourbigbook.com/codex/circle) would be found multiple times under different rotations.

### 5. Depth-First Search With Used-Edge Tracking

The recursive search keeps:

1\. a boolean [array](https://ourbigbook.com/codex/array-data-structure) of used [edges](https://ourbigbook.com/codex/edge),

2\. the current [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph),

3\. the partial [bit](https://ourbigbook.com/codex/bit) [sequence](https://ourbigbook.com/codex/sequence) being built.

At each step it tries [bit](https://ourbigbook.com/codex/bit) 0 and [bit](https://ourbigbook.com/codex/bit) 1. If the corresponding [edge](https://ourbigbook.com/codex/edge) has not been used, it marks the [edge](https://ourbigbook.com/codex/edge), appends the [bit](https://ourbigbook.com/codex/bit), and recurses to the suffix [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph). After returning, it undoes the choice and continues with the next branch.

This is a standard [backtracking](https://ourbigbook.com/codex/backtracking) enumeration of all [Eulerian cycles](https://ourbigbook.com/codex/eulerian-cycle) from the fixed root.

### 6. Why the Search Is Correct

The [mathematical invariant](https://ourbigbook.com/codex/invariant-mathematics) is simple: the [set](https://ourbigbook.com/codex/set) of used [edges](https://ourbigbook.com/codex/edge) is exactly the [set](https://ourbigbook.com/codex/set) of [edges](https://ourbigbook.com/codex/edge) already traversed in the partial walk, and the current [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) is the suffix of the last traversed [edge](https://ourbigbook.com/codex/edge).

If all $2^n$ [edges](https://ourbigbook.com/codex/edge) have been used and the walk returns to [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) 0, then the partial walk is a closed [Eulerian cycle](https://ourbigbook.com/codex/eulerian-cycle). If any [edge](https://ourbigbook.com/codex/edge) remains unused, then the walk is incomplete and cannot yet represent a valid [binary circle](https://ourbigbook.com/codex/binary-circle).

Because the [DFS](https://ourbigbook.com/codex/depth-first-search) tries every unused outgoing [edge](https://ourbigbook.com/codex/edge) at every step, every [Eulerian cycle](https://ourbigbook.com/codex/eulerian-cycle) rooted at $0^n$ is enumerated exactly once.

### 7. Converting a Cycle to an Integer

The code stores the current [bit](https://ourbigbook.com/codex/bit) stream in `sequence`. Once a full cycle has been found, the first $2^n$ [bits](https://ourbigbook.com/codex/bit) of that stream are interpreted as a binary [integer](https://ourbigbook.com/codex/integer):

$$X=\sum_{i=0}^{2^n-1} b_i\,2^{2^n-1-i}.$$

That value is added to the running total. The solver therefore sums the canonical [integer](https://ourbigbook.com/codex/integer) representative of every valid [binary circle](https://ourbigbook.com/codex/binary-circle).

A tiny worked example is $n=2$. The unique anchored cycle produces the [bit](https://ourbigbook.com/codex/bit) prefix

$$0011,$$

whose cyclic windows are

$$00,\ 01,\ 11,\ 10.$$

These are exactly the four 2-bit patterns, and the canonical [integer](https://ourbigbook.com/codex/integer) is

$$0011_2=3,$$

which matches the checkpoint $S(2)=3$.

### 8. Small Checkpoints

The program verifies two sample values:

$$S(2)=3,\qquad S(3)=52.$$

These checks are useful because they confirm both the [graph](https://ourbigbook.com/codex/graph) construction and the integer-conversion logic before larger searches are attempted.

For $n=3$, the two canonical cycles found by the solver are

$$00010111_2=23,\qquad 00011101_2=29,$$

so

$$S(3)=23+29=52.$$

## How the Code Works

The program accepts `--n` and `--skip-checkpoints`. `solve(n)` first computes the [edge](https://ourbigbook.com/codex/edge) count $2^n$ and the [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) mask $2^{n-1}-1$. The [array](https://ourbigbook.com/codex/array-data-structure) `used_edge` marks which $n$-[bit](https://ourbigbook.com/codex/bit) blocks have already been traversed. The vector `sequence` starts with $n$ zero [bits](https://ourbigbook.com/codex/bit), which is the anchored $0^n$ block.

The lambda `dfs` explores the two possible extensions from the current [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph). When a candidate [edge](https://ourbigbook.com/codex/edge) is unused, it is marked, its trailing [bit](https://ourbigbook.com/codex/bit) is appended, and the [recursion](https://ourbigbook.com/codex/recursion) continues from the suffix [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph). Once all [edges](https://ourbigbook.com/codex/edge) are used and the walk has returned to [graph vertex](https://ourbigbook.com/codex/vertex-of-a-graph) 0, the solver converts the collected [bit](https://ourbigbook.com/codex/bit) stream into a binary [integer](https://ourbigbook.com/codex/integer) and adds it to `total`.

The checkpoint routine simply compares the results of `solve(2)` and `solve(3)` against the expected sample values.

## Complexity Analysis

The solver enumerates [Eulerian cycles](https://ourbigbook.com/codex/eulerian-cycle) by [backtracking](https://ourbigbook.com/codex/backtracking), so the running time is exponential in $n$. That is unavoidable here because the number of valid [binary circles](https://ourbigbook.com/codex/binary-circle) itself grows rapidly with $n$.

Memory usage is $O(2^n)$, dominated by the edge-usage [array](https://ourbigbook.com/codex/array-data-structure) and the current [bit](https://ourbigbook.com/codex/bit) [sequence](https://ourbigbook.com/codex/sequence). The [recursion](https://ourbigbook.com/codex/recursion) depth is also proportional to the cycle length.
