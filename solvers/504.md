# Project Euler 504 Solution - Square on the Inside

<https://projecteuler.net/problem=504>:

* [504.py](504.py)

## Problem Summary

For each quadruple $(a,b,c,d)$ with $1\le a,b,c,d\le m$, consider the [Euclidean lattice](https://ourbigbook.com/codex/euclidean-lattice) [quadrilateral](https://ourbigbook.com/codex/quadrilateral) with [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) $(a,0)$, $(0,b)$, $(-c,0)$, and $(0,-d)$. The task is to count how many such [quadrilaterals](https://ourbigbook.com/codex/quadrilateral) contain a [perfect-square](https://ourbigbook.com/codex/perfect-square) number of interior [lattice points](https://ourbigbook.com/codex/lattice-point).

The implementations do not inspect [lattice points](https://ourbigbook.com/codex/lattice-point) one by one inside each [polygon](https://ourbigbook.com/codex/polygon). Instead, they convert the [geometry](https://ourbigbook.com/codex/geometry) into a closed arithmetic formula for the interior count and then test that value against a precomputed set of [perfect squares](https://ourbigbook.com/codex/perfect-square).

## Mathematical Approach

Let $I(a,b,c,d)$ denote the number of interior [lattice points](https://ourbigbook.com/codex/lattice-point) of the [quadrilateral](https://ourbigbook.com/codex/quadrilateral) determined by $(a,b,c,d)$. The whole problem is therefore to count the quadruples for which $I(a,b,c,d)$ is a [perfect square](https://ourbigbook.com/codex/perfect-square).

### Step 1: Write the Quadrilateral in Cyclic Order

The [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) are visited as

$$ (a,0)\to(0,b)\to(-c,0)\to(0,-d)\to(a,0). $$

Because each [polygon vertex](https://ourbigbook.com/codex/vertex-of-a-polygon) lies on one of the coordinate axes, the figure naturally breaks into four [right triangles](https://ourbigbook.com/codex/right-triangle) around the origin. That [symmetry](https://ourbigbook.com/codex/symmetry) is what makes the [area](https://ourbigbook.com/codex/area) and boundary formulas compact.

### Step 2: Compute the Area

The four [triangles](https://ourbigbook.com/codex/triangle) have [areas](https://ourbigbook.com/codex/area) $\frac{ab}{2}$, $\frac{bc}{2}$, $\frac{cd}{2}$, and $\frac{da}{2}$. Adding them gives

$$A=\frac{ab+bc+cd+da}{2}.$$

Factoring the same expression yields an equivalent form that is convenient in code:

$$2A=ab+bc+cd+da=(a+c)(b+d).$$

So the [area](https://ourbigbook.com/codex/area) depends only on simple products of neighboring or opposite [side](https://ourbigbook.com/codex/side-of-a-polygon) lengths on the axes.

### Step 3: Count the Boundary Lattice Points

A [side](https://ourbigbook.com/codex/side-of-a-polygon) joining $(u,0)$ and $(0,v)$ has displacement $(-u,v)$. A standard lattice-point fact says that such a segment contributes $\gcd(u,v)$ boundary steps, or equivalently $\gcd(u,v)+1$ [lattice points](https://ourbigbook.com/codex/lattice-point) including both endpoints.

Applying this to the four [sides](https://ourbigbook.com/codex/side-of-a-polygon) gives the total number of boundary [lattice points](https://ourbigbook.com/codex/lattice-point)

$$B=\gcd(a,b)+\gcd(b,c)+\gcd(c,d)+\gcd(d,a).$$

This is the correct polygon-level boundary count: shared [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) are handled automatically by the formula $B=\sum \gcd(|\Delta x|,|\Delta y|)$.

### Step 4: Apply Pick's Theorem

[Pick's theorem](https://ourbigbook.com/codex/pick-s-theorem) states

$$A=I+\frac{B}{2}-1.$$

Solving for the interior count gives

$$I=A-\frac{B}{2}+1=\frac{ab+bc+cd+da-B}{2}+1.$$

Substituting the boundary expression produces the exact arithmetic test used by the implementations:

$$I(a,b,c,d)=\frac{(a+c)(b+d)-\gcd(a,b)-\gcd(b,c)-\gcd(c,d)-\gcd(d,a)}{2}+1.$$

So each quadruple is reduced to one [integer](https://ourbigbook.com/codex/integer), and the geometric question becomes a [perfect-square](https://ourbigbook.com/codex/perfect-square) test.

### Step 5: Worked Example

Take $(a,b,c,d)=(2,2,2,1)$. Then

$$2A=(2+2)(2+1)=12,$$

and

$$B=\gcd(2,2)+\gcd(2,2)+\gcd(2,1)+\gcd(1,2)=2+2+1+1=6.$$

Therefore

$$I=\frac{12-6}{2}+1=4.$$

Since $4=2^2$, this quadruple contributes to the answer. The same formula handles every other quadruple without any geometric case split.

## How the Code Works

The C++, Python, and Java implementations all follow the same plan. First they precompute $\gcd(x,y)$ for every $1\le x,y\le m$. That turns each boundary contribution into a table lookup instead of a fresh [gcd](https://ourbigbook.com/codex/greatest-common-divisor) computation inside the innermost loop.

Next they precompute all [perfect squares](https://ourbigbook.com/codex/perfect-square) up to a safe [upper bound](https://ourbigbook.com/codex/upper-bound). Since $(a+c)(b+d)\le 4m^2$ and $B\ge 4$, we have

$$I\le \frac{4m^2-4}{2}+1=2m^2-1,$$

so marking [perfect squares](https://ourbigbook.com/codex/perfect-square) up to $2m^2+1$ is comfortably sufficient.

Finally the implementations run four nested loops over $a$, $b$, $c$, and $d$. Inside those loops they reuse boundary values already determined by the outer indices, evaluate the formula for $I(a,b,c,d)$, and increment the answer exactly when that value is [perfect square](https://ourbigbook.com/codex/perfect-square).

For the sample case $m=4$, the full enumeration gives $42$, which matches the known reference value.

## Complexity Analysis

Building the [gcd](https://ourbigbook.com/codex/greatest-common-divisor) table stores $O(m^2)$ values and needs $O(m^2\log m)$ arithmetic if each entry is computed with the [Euclidean algorithm](https://ourbigbook.com/codex/euclidean-algorithm). Marking all relevant [perfect squares](https://ourbigbook.com/codex/perfect-square) is $O(m)$ time with an $O(m^2)$-sized lookup table under the bound above. The dominant cost is the exhaustive scan of all $m^4$ quadruples, with only $O(1)$ work per quadruple after precomputation. Therefore the overall complexity is $O(m^4)$ time and $O(m^2)$ memory.
