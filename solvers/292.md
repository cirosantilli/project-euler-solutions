# Project Euler 292 Solution - Pythagorean Polygons

<https://projecteuler.net/problem=292>:

* [292.py](292.py)

A **pythagorean [polygon](https://ourbigbook.com/codex/polygon)** is a *[convex](https://ourbigbook.com/codex/convexity)* [polygon](https://ourbigbook.com/codex/polygon) with:

- at least 3 [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon),
- no three [polygon vertices](https://ourbigbook.com/codex/vertex-of-a-polygon) collinear,
- [integer](https://ourbigbook.com/codex/integer) coordinates for every [polygon vertex](https://ourbigbook.com/codex/vertex-of-a-polygon),
- [integer](https://ourbigbook.com/codex/integer) length for every [polygon edge](https://ourbigbook.com/codex/polygon-edge).

Let `P(n)` be the number of such [polygons](https://ourbigbook.com/codex/polygon) (distinct up to translation) with [perimeter](https://ourbigbook.com/codex/perimeter) `≤ n`.

The problem asks for `P(120)` and provides:

- `P(4)  = 1`
- `P(30) = 3655`
- `P(60) = 891045`

---

## Core ideas used in `main.py`

### 1) Integer edge length ⇒ Pythagorean lattice vectors
An [polygon edge](https://ourbigbook.com/codex/polygon-edge) from `(x1,y1)` to `(x2,y2)` is a [lattice vector](https://ourbigbook.com/codex/lattice-vector) `(dx,dy)`.

Its length is [integer](https://ourbigbook.com/codex/integer) iff:

\[
dx^2 + dy^2 = c^2
\]

for some [integer](https://ourbigbook.com/codex/integer) `c`. So every allowed direction comes from a (possibly scaled) **[Pythagorean triple](https://ourbigbook.com/codex/pythagorean-triple)**.

The code generates **primitive** triples with [Euclid's formula](https://ourbigbook.com/codex/euclid-s-formula-for-pythagorean-triples) and then allows [integer](https://ourbigbook.com/codex/integer) scaling.

Axis-aligned [polygon edges](https://ourbigbook.com/codex/polygon-edge) `(k,0)` and `(0,k)` are included separately (they correspond to `c=1`).

---

### 2) Convex polygon ↔ edge vectors sorted by angle
A key geometric fact:

> If a [set](https://ourbigbook.com/codex/set) of edge [vectors](https://ourbigbook.com/codex/vector) sums to zero and you traverse them in increasing [polar angle](https://ourbigbook.com/codex/polar-angle) order,
> the resulting [closed walk](https://ourbigbook.com/codex/closed-walk) is a [convex polygon](https://ourbigbook.com/codex/convex-polygon) ([strictly convex](https://ourbigbook.com/codex/strictly-convex) if no direction repeats).

So we can count [polygons](https://ourbigbook.com/codex/polygon) by counting **[sets](https://ourbigbook.com/codex/set) of [directed edge](https://ourbigbook.com/codex/directed-edge) [vectors](https://ourbigbook.com/codex/vector)** that:

- have distinct directions (enforced by choosing **at most one** scaled [vector](https://ourbigbook.com/codex/vector) per primitive direction),
- sum to `(0,0)`,
- total [perimeter](https://ourbigbook.com/codex/perimeter) `≤ n`.

This automatically handles “distinct up to translation”, because translations don’t change edge [vectors](https://ourbigbook.com/codex/vector).

---

### 3) Split into upper/lower half-planes + symmetry
Partition directions by the sign of `dy`:

- **upper half**: `dy > 0` plus the `+x` axis,
- **lower half**: the negations of the upper directions.

If the upper selection sums to displacement `v`, then the lower selection must sum to `-v`.

By [symmetry](https://ourbigbook.com/codex/symmetry), “#ways to get `v` in upper” = “#ways to get `-v` in lower”, so the code computes a [DP](https://ourbigbook.com/codex/dynamic-programming)
for the upper half only and matches equal displacements during the final count.

---

### 4) 2D knapsack-style DP with perimeter constraint
For the [upper half-plane](https://ourbigbook.com/codex/upper-half-plane-complex-analysis), we do:

- state: `(perimeter, displacement)` → number of ways
- transition: for each primitive direction, either skip it or pick exactly one scale `s ≥ 1`

The [DP](https://ourbigbook.com/codex/dynamic-programming) is stored as `dp[p] = {displacement_key: count}`.

A compact [integer](https://ourbigbook.com/codex/integer) key encodes `(x,y)` to make dictionary operations cheaper.

---

### 5) Subtract degenerate “polygons”
The raw [DP](https://ourbigbook.com/codex/dynamic-programming) [convolution](https://ourbigbook.com/codex/convolution) includes two invalid cases:

- the empty selection (0 [polygon edges](https://ourbigbook.com/codex/polygon-edge)),
- a 2-edge back-and-forth segment `(v, -v)`.

These are subtracted explicitly.

---

## Result
Running `main.py` prints the answer to the original problem:

- `P(120) = 3600060866`

The script also asserts the three values given in the problem statement.
