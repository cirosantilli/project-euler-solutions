# Project Euler 200 Solution - Prime-proof Squbes

<https://projecteuler.net/problem=200>:

* [200.py](200.py)

## Problem Summary

A [sqube](https://ourbigbook.com/codex/sqube) is a number of the form

$$n=p^2q^3,\qquad p\neq q,\qquad p,q\text{ prime}.$$

The task is to find the 200th [sqube](https://ourbigbook.com/codex/sqube) whose [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) contains the contiguous substring "200" and which is *[prime-proof](https://ourbigbook.com/codex/prime-proof-number)*, meaning that every valid one-digit change produces a [composite number](https://ourbigbook.com/codex/composite-number). The arithmetic form $p^2q^3$ is the main structural restriction, and the decimal pattern and [prime-proof](https://ourbigbook.com/codex/prime-proof-number) property are two additional filters applied to that sparse family.

There is no closed formula for the 200th answer. The practical route is therefore to enumerate all [squbes](https://ourbigbook.com/codex/sqube) below a bound, sort them, and test each candidate with exact criteria that mirror the statement of the problem.

## Mathematical Approach

The solution is best understood as a search over a highly structured set, not as a scan over all [integers](https://ourbigbook.com/codex/integer). The number-theoretic part identifies which values can even be candidates, and the decimal and [primality](https://ourbigbook.com/codex/primality) parts then certify which of those candidates survive.

### Bounding the sqube search space

For a fixed bound $L$, every relevant candidate lies in

$$\mathcal S(L)=\{p^2q^3: p,q\text{ prime},\ p\neq q,\ p^2q^3\le L\}.$$

Because the smallest possible cube [prime](https://ourbigbook.com/codex/prime) is $2$, any such candidate satisfies

$$p^2\le \frac{L}{2^3}=\frac{L}{8},\qquad p\le \sqrt{L/8}.$$

Once $p$ is fixed, the cube [prime](https://ourbigbook.com/codex/prime) must satisfy

$$q^3\le \frac{L}{p^2},\qquad q\le \left(\frac{L}{p^2}\right)^{1/3}.$$

So the search space is finite and can be generated by nested loops over [primes](https://ourbigbook.com/codex/prime) with an early stop as soon as $p^2q^3$ exceeds the current bound.

A useful way to write the candidate count is

$$M(L)=\sum_{\substack{p\le \sqrt{L/8}\\ p\text{ prime}}}\#\left\{q\text{ prime}:q\neq p,\ q\le \left(\frac{L}{p^2}\right)^{1/3}\right\}.$$

This expression is not evaluated symbolically in the code, but it makes the [geometry](https://ourbigbook.com/codex/geometry) of the enumeration explicit.

### Recognizing the decimal substring "200"

A [positive integer](https://ourbigbook.com/codex/positive-integer) $x$ contains the substring "200" if and only if there exists some offset $m\ge 0$ such that

$$\left\lfloor \frac{x}{10^m}\right\rfloor \equiv 200 \pmod{1000}.$$

That condition says exactly that some consecutive block of three decimal [digits](https://ourbigbook.com/codex/numerical-digit) equals 200. Repeatedly checking $x\bmod 1000$ and then discarding the last [digit](https://ourbigbook.com/codex/numerical-digit) by [integer division](https://ourbigbook.com/codex/integer-division) by $10$ is therefore a sliding three-digit window through the [decimal expansion](https://ourbigbook.com/codex/decimal-expansion). This is the arithmetic content behind the substring filter.

### Prime-proof as a digit perturbation condition

Write the [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) of a $d$-[digit](https://ourbigbook.com/codex/numerical-digit) candidate as

$$x=\sum_{i=0}^{d-1} a_i10^i,\qquad 0\le a_i\le 9,\qquad a_{d-1}\neq 0.$$

If the [digit](https://ourbigbook.com/codex/numerical-digit) at position $i$ is replaced by another [digit](https://ourbigbook.com/codex/numerical-digit) $b$, the new number is

$$x'=x+(b-a_i)10^i.$$

All choices $b\neq a_i$ are allowed, except that the leading [digit](https://ourbigbook.com/codex/numerical-digit) may not be replaced by $0$. The number $x$ is [prime-proof](https://ourbigbook.com/codex/prime-proof-number) exactly when every valid value of $x'$ is [composite](https://ourbigbook.com/codex/composite-number).

This reformulation explains the code directly. A $d$-[digit](https://ourbigbook.com/codex/numerical-digit) [sqube](https://ourbigbook.com/codex/sqube) needs at most $9d$ [primality tests](https://ourbigbook.com/codex/primality-test), one for each alternative [digit](https://ourbigbook.com/codex/numerical-digit) at each position, and the candidate is rejected immediately if any modified number is [prime](https://ourbigbook.com/codex/prime).

### Why increasing the bound is mathematically safe

If $L_1\le L_2$, then $\mathcal S(L_1)\subseteq \mathcal S(L_2)$. After the substring filter and the [prime-proof](https://ourbigbook.com/codex/prime-proof-number) filter are applied, the same monotonicity still holds: every valid value found below $L_1$ remains present below $L_2$. Therefore, once a bound $L$ produces at least 200 valid [squbes](https://ourbigbook.com/codex/sqube), the 200th element of the sorted list below $L$ is already the true answer.

This is why two different implementation styles are correct. One implementation starts from a moderate bound and doubles it until enough values are found. The other two choose a very large fixed bound from the beginning. Both rely on the same [invariant](https://ourbigbook.com/codex/invariant-mathematics): enlarging the bound can only add larger candidates, never invalidate smaller ones.

### Worked Example: why $200$ itself qualifies

The number $200$ is already a [sqube](https://ourbigbook.com/codex/sqube), because

$$200=5^2\cdot 2^3.$$

It obviously contains the substring "200". To show that it is [prime-proof](https://ourbigbook.com/codex/prime-proof-number), inspect the three [digit](https://ourbigbook.com/codex/numerical-digit) positions.

Changing the hundreds [digit](https://ourbigbook.com/codex/numerical-digit) gives $100,300,400,\dots,900$, all [composite](https://ourbigbook.com/codex/composite-number). Changing the tens [digit](https://ourbigbook.com/codex/numerical-digit) gives $210,220,\dots,290$, also all [composite](https://ourbigbook.com/codex/composite-number) because they are even and larger than $2$. Changing the units [digit](https://ourbigbook.com/codex/numerical-digit) gives $201,202,\dots,209$; the even values are [composite](https://ourbigbook.com/codex/composite-number), $201$ and $207$ are divisible by $3$, $205$ is divisible by $5$, $203=7\cdot 29$, and $209=11\cdot 19$.

So every valid one-digit change of $200$ is [composite](https://ourbigbook.com/codex/composite-number). This is the exact logical pattern used for every candidate in the final search.

## How the Code Works

The C++, Python, and Java implementations all use the same pipeline: generate [squbes](https://ourbigbook.com/codex/sqube) below a bound, keep only those whose [decimal expansion](https://ourbigbook.com/codex/decimal-expansion) contains "200", and then verify prime-proofness by examining every allowed single-digit modification.

### Generating and ordering the squbes

Each implementation begins by producing enough [prime numbers](https://ourbigbook.com/codex/prime-number) with a [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve). It then loops over distinct [prime](https://ourbigbook.com/codex/prime) pairs and forms products of the shape $p^2q^3$ until the current bound is exceeded. The resulting values are collected in a structure that removes duplicates and preserves sorted order after the generation phase.

Two implementations explicitly enumerate both exponent assignments $p^2q^3$ and $p^3q^2$, then deduplicate. The C++ implementation covers the same family by letting the squared [prime](https://ourbigbook.com/codex/prime) and the cubed [prime](https://ourbigbook.com/codex/prime) play ordered roles inside a single formula. The mathematical candidate set is identical in all three languages.

### Applying the two filters

The substring test uses the [decimal representation](https://ourbigbook.com/codex/decimal-representation) and only values that pass this stage are sent to the [prime-proof](https://ourbigbook.com/codex/prime-proof-number) check.

For the [prime-proof](https://ourbigbook.com/codex/prime-proof-number) test, the implementation mutates one [digit](https://ourbigbook.com/codex/numerical-digit) arithmetically using powers of $10$, which is a direct realization of

$$x' = x + (b-a_i)10^i.$$

This avoids rebuilding a new decimal string for every neighbor. Obvious [composite](https://ourbigbook.com/codex/composite-number) changes of the units [digit](https://ourbigbook.com/codex/numerical-digit), such as even endings and endings in 5, are skipped before the [primality test](https://ourbigbook.com/codex/primality-test).

### Primality testing and stopping

Every modified number that is not eliminated by a cheap decimal rule must be checked for [primality](https://ourbigbook.com/codex/primality). The Python implementation uses deterministic [Miller-Rabin](https://ourbigbook.com/codex/miller-rabin-primality-test) bases valid for the relevant 64-bit range, with Python's built-in [modular exponentiation](https://ourbigbook.com/codex/modular-exponentiation). If any modified value is [prime](https://ourbigbook.com/codex/prime), the original [sqube](https://ourbigbook.com/codex/sqube) is rejected.

After that, the valid [squbes](https://ourbigbook.com/codex/sqube) are counted in increasing order. The C++ implementation can grow the bound geometrically until the target count is reached and also includes sanity checks: the first [squbes](https://ourbigbook.com/codex/sqube) are $72,108,200,392,500$, and the second [prime-proof](https://ourbigbook.com/codex/prime-proof-number) [sqube](https://ourbigbook.com/codex/sqube) containing "200" is $1992008$. The Python and Java implementations instead start from a sufficiently large fixed bound and stop once the 200th valid value is encountered.

## Complexity Analysis

Let $L$ be the final bound large enough to contain the 200th answer, and let $M(L)$ be the number of [squbes](https://ourbigbook.com/codex/sqube) generated below that bound. [Prime](https://ourbigbook.com/codex/prime) generation by a [number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) costs $O(B\log\log B)$, where $B$ is the largest sieved [integer](https://ourbigbook.com/codex/integer). In the adaptive version $B$ is essentially $\sqrt{L/8}$; in the fixed-bound versions it is chosen on the same [square root](https://ourbigbook.com/codex/square-root) scale.

Building the candidate list costs $O(M(L))$ [arithmetic operations](https://ourbigbook.com/codex/arithmetic-operation) before [sorting](https://ourbigbook.com/codex/sorting), and ordering the resulting values costs $O(M(L)\log M(L))$. The substring filter is only linear in the number of decimal [digits](https://ourbigbook.com/codex/numerical-digit) of each candidate and is comparatively cheap.

The expensive phase is the [prime-proof](https://ourbigbook.com/codex/prime-proof-number) certification. If $F(L)$ candidates survive the substring test and a candidate $x$ has $d(x)$ decimal [digits](https://ourbigbook.com/codex/numerical-digit), then the number of [primality tests](https://ourbigbook.com/codex/primality-test) is at most

$$\sum_{x\in F(L)} 9\,d(x).$$

In C++, each of these calls is a fixed-base [Miller-Rabin test](https://ourbigbook.com/codex/miller-rabin-primality-test), so for 64-bit inputs the [primality](https://ourbigbook.com/codex/primality) step is effectively near-constant time per call. In Python and Java, [trial division](https://ourbigbook.com/codex/trial-division) has worst-case cost $O(\sqrt{x})$ per call, but the number of tested neighbors stays manageable because the [sqube](https://ourbigbook.com/codex/sqube) family is sparse and the decimal filter removes most candidates first.

The [memory usage](https://ourbigbook.com/codex/memory-usage) is $O(M(L))$ for the stored [squbes](https://ourbigbook.com/codex/sqube), plus the [prime](https://ourbigbook.com/codex/prime) table. The key efficiency gain is structural: the search never scans all [integers](https://ourbigbook.com/codex/integer) up to $L$; it explores only numbers of the specific form $p^2q^3$, which is a dramatically smaller set.
