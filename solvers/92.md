# Project Euler 92 Solution - Square Digit Chains

<https://projecteuler.net/problem=92>:

* [92.py](92.py)
* [92.lean](92.lean)

We repeatedly replace a number by the [sum of squares](https://ourbigbook.com/codex/sum-of-squares) of its [digits](https://ourbigbook.com/codex/numerical-digit). Every positive starting number eventually enters the fixed loop at `1` or the loop at `89`. We must count how many starting numbers `< 10,000,000` end at `89`.

### Key insights

- For a number with at most `d` [digits](https://ourbigbook.com/codex/numerical-digit), the first digit-square sum is at most `81*d`.
- Starting values with the same digit-square sum have the same chain endpoint. Count these groups instead of walking every starting value.
- Read the digits of `limit_exclusive - 1` from left to right. For each prefix, track its digit-square sum, whether it still equals the bound's prefix, and how many prefixes share that state.
- Extend each state by every permitted next digit. Leading zeros preserve sums and allow shorter numbers to use the same traversal.
- Memoize whether each resulting sum reaches `1`, `89`, or another repeated value. Sum the group sizes whose endpoint is `89`; the all-zero number contributes nothing.

### Complexity

There are at most `2*(81*d + 1)` prefix states at each digit position, each with at most ten successors. Prefix counting therefore takes `O(d^2)` state transitions and `O(d)` stored states, apart from integer arithmetic and the small memoized chain walks. The supplied bound can have any number of decimal digits; the default is ten million. The reference walks each positive starting value until an endpoint or repeated value, without an iteration cutoff.

### Formal proof

The [source proof](92.py.lean) establishes termination and `Equiv(naive)` for every signed `limit_exclusive`. Bounds at most one return zero. Larger bounds use the complete decimal traversal, with no fixed digit width or whole-program evaluation.

The [digit-square orbit proof](../ProjectEulerSolutions/Lib/DigitSquareChains.lean) shows that every chain stays in `0..max(start, 199)`. This invariant proves termination without imposing a runtime cutoff. The [reference proof](../data/project-euler-statements/data/py/project_euler_statements/p92.py.lean) follows each complete chain walk and the counting sum. The optimized [terminal proof](92.py.lean.d/Terminal.lean) establishes correct endpoint classification and cache preservation through path compression.

The [prefix-distribution proof](../ProjectEulerSolutions/Lib/DigitSquareDistribution.lean) shows that digit branches enumerate every integer below the bound exactly once. The [distribution source proof](92.py.lean.d/Distribution.lean) connects this model to the actual nested loops and tuple-key dictionary updates, including the compiler's pooled initial tuple. The [final sum proof](92.py.lean.d/Sum.lean) executes the live dictionary cursor, nested target unpacking, endpoint filter, and weighted accumulation. The [execution proof](92.py.lean.d/Execution.lean) composes these steps into the complete solver result. The public contracts depend only on standard Lean axioms.
