# Project Euler 87 Solution - Prime Power Triples

<https://projecteuler.net/problem=87>:

* [87.py](87.py)
* [87.lean](87.lean)

We want to count distinct numbers below `50,000,000` that can be written as:

`p^2 + q^3 + r^4` where `p, q, r` are [primes](https://ourbigbook.com/codex/prime-number).

## Key observations
- The largest [prime](https://ourbigbook.com/codex/prime-number) needed for [square numbers](https://ourbigbook.com/codex/square-number) is `sqrt(limit)`, since `p^2 < limit`.
- Similarly, [integer cubes](https://ourbigbook.com/codex/integer-cube) and [fourth powers](https://ourbigbook.com/codex/fourth-power) automatically stay within the limit once we filter by checking `p^3 < limit` and `p^4 < limit`.
- Counts are small enough for a straightforward triple loop after precomputing [prime powers](https://ourbigbook.com/codex/prime-power):
  - [primes](https://ourbigbook.com/codex/prime-number) up to ~7071 for [square numbers](https://ourbigbook.com/codex/square-number)
  - ~73 [primes](https://ourbigbook.com/codex/prime-number) for [integer cubes](https://ourbigbook.com/codex/integer-cube) and ~23 [primes](https://ourbigbook.com/codex/prime-number) for [fourth powers](https://ourbigbook.com/codex/fourth-power)
  - total [tuples](https://ourbigbook.com/codex/tuple) are about 1.5 million, which is fast in PyPy.

## Approach
1. [Number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) all [primes](https://ourbigbook.com/codex/prime-number) up to `isqrt(limit)`.
2. Build sorted lists of all [prime](https://ourbigbook.com/codex/prime-number) [square numbers](https://ourbigbook.com/codex/square-number), [integer cubes](https://ourbigbook.com/codex/integer-cube), and [fourth powers](https://ourbigbook.com/codex/fourth-power) below the limit.
3. Iterate over `fourths`, `cubes`, then `squares`, using sorted-order `break` [pruning](https://ourbigbook.com/codex/search-pruning) when [sums](https://ourbigbook.com/codex/sum) exceed the limit.
4. Insert each valid [sum](https://ourbigbook.com/codex/sum) into a `set` to ensure uniqueness.
5. Answer is the size of the [set](https://ourbigbook.com/codex/set).

A small correctness check from the statement is included:
- There are exactly 4 representable numbers below 50.

Both Python implementations accept any integer limit and return zero for a nonpositive limit. Repeated representations count once, and the bound is strict: the smallest representable value is 28, so the counts below 28 and 29 are zero and one respectively.

## Formal verification

[PrimePowerTriples.lean](../ProjectEulerSolutions/Lib/PrimePowerTriples.lean) proves that the square-root prime bound is complete and that exhaustive prime triples and separately filtered powers produce exactly the same finite set. The extra candidate at `isqrt(limit) + 1` in the optimized sieve cannot add an invalid value. [PrimePowerTriplesSearch.lean](../ProjectEulerSolutions/Lib/PrimePowerTriplesSearch.lean) connects list enumeration to that set and proves that both sorted-order breaks preserve it.

The [reference source proof](../data/project-euler-statements/data/py/project_euler_statements/p87.py.lean) proves termination and the exact distinct count for every integer limit. It follows prime-list construction, all three nested loops, each accepted append, and the final `len(set(sums))`. The proof preserves the caller's heap and the prime list while accumulating repeated representations, then proves that deduplication has the mathematical set's cardinality.

The [optimized source helpers](87.py.lean.d/) prove the complete bytearray sieve for every integer bound, including its extended-slice writes. They also follow construction of all three power lists, prove their contents and ordering, verify the actual sorting calls, and allocate the empty result set. [PrimePowerTriplesPowers.lean](../ProjectEulerSolutions/Lib/PrimePowerTriplesPowers.lean) supplies the list membership and ordering lemmas.

The optimized pruned-search source proof and final Python equivalence remain unfinished. The older standalone Lean model is not used by these proofs.
