# Project Euler 434 Solution - Rigid Graphs

<https://projecteuler.net/problem=434>:

* [434.py](434.py)

## Key reduction: rigidity → connected bipartite graph

For an `m × n` grid of **square cells**, each cell can be “braced” by adding a [polygon diagonal](https://ourbigbook.com/codex/diagonal-of-a-polygon).
In this problem, the diagonal’s orientation doesn’t matter, and adding both [polygon diagonals](https://ourbigbook.com/codex/diagonal-of-a-polygon) is treated
the same as adding just one — so each cell is simply **present/absent**.

A classical result for braced rectangular grids (Bolker–Crapo) gives an elegant criterion:

- Build a **[bipartite graph](https://ourbigbook.com/codex/bipartite-graph)** with:
  - `m` [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) representing the **rows** of cells,
  - `n` [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) representing the **columns** of cells.
- For every braced cell `(row i, col j)`, add an [edge](https://ourbigbook.com/codex/edge-of-a-graph) between the corresponding row-vertex and column-vertex.

Then the grid framework is rigid in the plane **iff** this [bipartite graph](https://ourbigbook.com/codex/bipartite-graph) is a **[connected graph](https://ourbigbook.com/codex/connected-graph)**.

So:

- `R(m,n)` = number of **connected** [bipartite graphs](https://ourbigbook.com/codex/bipartite-graph) on a fixed labeled bipartition of sizes `(m,n)`
  (equivalently: connected [subgraphs](https://ourbigbook.com/codex/subgraph) of the [complete bipartite graph](https://ourbigbook.com/codex/complete-bipartite-graph) `K_{m,n}`).

## Counting connected bipartite graphs via a “rooted component” recurrence

Let:

- `F(m,n) = 2^(m*n)` be the number of *all* [bipartite graphs](https://ourbigbook.com/codex/bipartite-graph) on parts of sizes `(m,n)`
  (each of the `m*n` possible [edges](https://ourbigbook.com/codex/edge-of-a-graph) is independently present/absent).

To extract the connected ones, we use the standard “pick a root [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) and look at its component” trick:

1. Fix one specific [vertex](https://ourbigbook.com/codex/vertex-of-a-graph) on the `m`-side.
2. Suppose its [connected component](https://ourbigbook.com/codex/connected-component) contains:
   - `i` [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) from the `m`-side (including the fixed one),
   - `j` [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) from the `n`-side.
3. Choose which [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) these are: `C(m-1, i-1) * C(n, j)`.
4. Choose a **connected** [bipartite graph](https://ourbigbook.com/codex/bipartite-graph) on those [vertices](https://ourbigbook.com/codex/vertex-of-a-graph): `R(i,j)`.
   - A small technical [base case](https://ourbigbook.com/codex/base-case) is needed for the [recurrence relation](https://ourbigbook.com/codex/recurrence-relation):
     `R(1,0)=1` (a single isolated root [vertex](https://ourbigbook.com/codex/vertex-of-a-graph)).
5. The remaining [vertices](https://ourbigbook.com/codex/vertex-of-a-graph) can have **any** [bipartite graph](https://ourbigbook.com/codex/bipartite-graph) among themselves: `F(m-i, n-j)`,
   and there must be **no** [edges](https://ourbigbook.com/codex/edge-of-a-graph) between the component and the remainder (enforced by construction).

Summing over all possible `(i,j)` gives `F(m,n)`. Solving for `R(m,n)` yields:

`R(m,n) = F(m,n) - Σ_{(i,j)≠(m,n)} C(m-1,i-1) C(n,j) R(i,j) F(m-i,n-j)`.

This can be computed with [dynamic programming](https://ourbigbook.com/codex/dynamic-programming) in increasing `m` and `n`.

## Performance tricks used

- Precompute `2^k mod M` for `k ≤ N^2` to get `F(m,n)` in O(1).
- Precompute [binomial coefficients](https://ourbigbook.com/codex/binomial-coefficient) `C(n,k) mod M` with [Pascal's triangle](https://ourbigbook.com/codex/pascal-s-triangle).
- Overall complexity is about `O(N^4)` operations with `N=100`, which is fast enough in Python.
