# Solution Summary

This program computes the requested value for the [polynomial](https://ourbigbook.com/codex/polynomial) [divisibility](https://ourbigbook.com/codex/divisibility) problem without using external libraries.

## Main ideas

For a [prime](https://ourbigbook.com/codex/prime) `p`, the [polynomial](https://ourbigbook.com/codex/polynomial)

```text
f_p(x) = 1 + x + ... + x^(p-1)
```

is the [cyclotomic polynomial](https://ourbigbook.com/codex/cyclotomic-polynomial) for primitive `p`-th [roots of unity](https://ourbigbook.com/codex/roots-of-unity). If `z` is such a root, then `f_p` divides `g_s` exactly when `g_s(z) = 0`.

After reducing every [divisor](https://ourbigbook.com/codex/divisor) exponent [modulo](https://ourbigbook.com/codex/modulo-operation) `p`, this means the [coefficients](https://ourbigbook.com/codex/coefficient) of the residues must all be equal. A valid `s` cannot be divisible by `p`, so the condition becomes:

```text
the divisors of s must represent every nonzero residue modulo p exactly once.
```

Thus `tau(s) = p - 1`.

## Cyclic group formulation

The nonzero residues [modulo](https://ourbigbook.com/codex/modulo-operation) `p` form a [cyclic group](https://ourbigbook.com/codex/cyclic-group) of order `m = p - 1`. Choose a [primitive root](https://ourbigbook.com/codex/primitive-root) `r`, and replace every residue by its [discrete logarithm](https://ourbigbook.com/codex/discrete-logarithm) base `r`. A [prime factor](https://ourbigbook.com/codex/prime-factor) `q^e` in `s` contributes the interval

```text
0, log(q), 2 log(q), ..., e log(q)  (mod m)
```

The [divisors](https://ourbigbook.com/codex/divisor) of `s` cover all nonzero residues exactly once when these intervals form a direct tiling of the [cyclic group](https://ourbigbook.com/codex/cyclic-group).

## Dynamic programming

The code grows the covered subgroup size `h`, where `h` is always a [divisor](https://ourbigbook.com/codex/divisor) of `m`.

If the current subgroup has size `h`, the [quotient group](https://ourbigbook.com/codex/quotient-group) has size `M = m / h`. Expanding by a factor `L` uses a [prime](https://ourbigbook.com/codex/prime) `q` whose coset has exact order `L` in that [quotient group](https://ourbigbook.com/codex/quotient-group). This contributes `q^(L-1)` to `s` and moves the state from `h` to `hL`.

The [dynamic program](https://ourbigbook.com/codex/dynamic-program) stores the smallest exact [integer](https://ourbigbook.com/codex/integer) that reaches each subgroup size. The target state is `h = m`.

## Fast transition lookup

For a [prime](https://ourbigbook.com/codex/prime) `q`, only

```text
gcd(log_r(q), m)
```

is needed to determine all [quotient group](https://ourbigbook.com/codex/quotient-group) orders. The program scans ordinary [primes](https://ourbigbook.com/codex/prime) once for each `p` and records the least [prime](https://ourbigbook.com/codex/prime) producing each possible [gcd](https://ourbigbook.com/codex/greatest-common-divisor) class. This makes transition costs quick to look up during the [dynamic program](https://ourbigbook.com/codex/dynamic-program).
