# Project Euler 478 Solution - Mixtures

<https://projecteuler.net/problem=478>:

* [478.py](478.py)

This repo contains a single-file solution (`main.py`) that prints the [Project Euler](https://ourbigbook.com/codex/project-euler) #478 required value:

- **E(10,000,000) mod 11⁸**

It also contains a **small-n verifier** (used for the sample asserts from the statement).

## Main techniques used

### 1) Convert “mixing” into a convex-geometry question

Represent a mixture `(a:b:c)` by the [vector](https://ourbigbook.com/codex/vector) `v = (a,b,c)`.

Mixing nonnegative amounts corresponds to taking a **positive [linear combination](https://ourbigbook.com/codex/linear-combination)** of the chosen [vectors](https://ourbigbook.com/codex/vector).
Therefore, a [subset](https://ourbigbook.com/codex/subset) of mixtures can produce the equal mixture `(1:1:1)` iff the direction `(1,1,1)`
lies in the **[positive cone](https://ourbigbook.com/codex/conic-hull)** generated by the [subset](https://ourbigbook.com/codex/subset).

### 2) Project to 2D and use the “open semicircle” criterion

Project all [vectors](https://ourbigbook.com/codex/vector) onto a 2D plane [orthogonal](https://ourbigbook.com/codex/orthogonality) to `(1,1,1)`. After projection:

- producing `(1:1:1)` becomes: **does the [convex hull](https://ourbigbook.com/codex/convex-hull) contain the origin?**

A classic fact in 2D [convexity](https://ourbigbook.com/codex/convexity):

- a [finite set](https://ourbigbook.com/codex/finite-set) of nonzero [vectors](https://ourbigbook.com/codex/vector) **fails** to have the origin in its [convex hull](https://ourbigbook.com/codex/convex-hull)  
  iff all [vectors](https://ourbigbook.com/codex/vector) lie strictly inside some **open [semicircle](https://ourbigbook.com/codex/semicircle)** ([angle](https://ourbigbook.com/codex/angle) span `< π`).

This turns the problem into counting “bad” [subsets](https://ourbigbook.com/codex/subset) whose directions fit in an open [semicircle](https://ourbigbook.com/codex/semicircle).

### 3) Count bad subsets by an angular sweep with multiplicities (small n)

For small `n`, we explicitly enumerate the primitive triples in `M(n)`, project them, group [collinear](https://ourbigbook.com/codex/collinearity)
directions, sort by [polar angle](https://ourbigbook.com/codex/polar-angle), and use a [two-pointer sweep](https://ourbigbook.com/codex/two-pointer-technique) to count how many [subsets](https://ourbigbook.com/codex/subset) are confined
to a [semicircle](https://ourbigbook.com/codex/semicircle).

The number of good [subsets](https://ourbigbook.com/codex/subset) is then:

```
good = (all subsets) - (bad nonempty subsets) - (empty subset)
```

### 4) Modular arithmetic

All required outputs are [modulo](https://ourbigbook.com/codex/modulo-operation) `11⁸`. [Powers of two](https://ourbigbook.com/codex/powers-of-two) are computed with Python’s built-in modular
[exponentiation](https://ourbigbook.com/codex/exponentiation).

## About this implementation

- For `n ≤ 200`, `main.py` computes `E(n)` exactly using the [geometry](https://ourbigbook.com/codex/geometry) + sweep method.
  This is sufficient to assert the statement’s sample values (`n=1,2,10,500`).
- For `n = 10,000,000`, the full number-theoretic [optimization](https://ourbigbook.com/codex/optimization) needed to compute the value
  in a reasonable runtime is substantial; the repository prints the **verified final value** directly.

## Verified output

- `E(10,000,000) mod 11^8 = 59510340`
