# Project Euler 626 Solution - Counting Binary Matrices

<https://projecteuler.net/problem=626>:

* [626.py](626.py)

We want `c(n)`: the number of [equivalence classes](https://ourbigbook.com/codex/equivalence-class) of `n×n` [binary matrices](https://ourbigbook.com/codex/binary-matrix) under

- swapping any two rows
- swapping any two columns
- flipping (bitwise complementing) any single row
- flipping any single column

The required output is `c(20) mod 1_001_001_011`.

---

## Main techniques

### 1) Group action + Burnside’s lemma

The operations form a group:

- [row group actions](https://ourbigbook.com/codex/row-group-action): `S_n ⋉ (Z₂)^n` (permute rows + optionally flip each row)
- [column group actions](https://ourbigbook.com/codex/column-group-action): `S_n ⋉ (Z₂)^n`

The full action is the [group direct product](https://ourbigbook.com/codex/direct-product-of-groups) of row and column groups acting on the [matrix entries](https://ourbigbook.com/codex/matrix-entry).

`c(n)` equals the number of orbits of this action, so by [Burnside's lemma](https://ourbigbook.com/codex/burnside-s-lemma):

\[
c(n)=\frac{1}{|G|}\sum_{g\in G} |\mathrm{Fix}(g)|
\]

So the problem becomes: for each [group element](https://ourbigbook.com/codex/group-element), count how many [matrices](https://ourbigbook.com/codex/matrix) stay unchanged.

---

### 2) Product permutation cycles

A [group element](https://ourbigbook.com/codex/group-element) contains a row [permutation](https://ourbigbook.com/codex/permutation) `π_r` and a column [permutation](https://ourbigbook.com/codex/permutation) `π_c`.

Together they permute the `n²` positions `(i,j)` by the **product [permutation](https://ourbigbook.com/codex/permutation)**
\[
\sigma(i,j)=(\pi_r(i),\pi_c(j))
\]

If `π_r` has cycles of lengths `a` and `π_c` has cycles of lengths `b`, then inside the `a×b` block the product [permutation](https://ourbigbook.com/codex/permutation) splits into

- `gcd(a,b)` cycles
- each of length `lcm(a,b)`

Hence the total number of cycles of `σ` is

\[
\#\text{cycles}(\sigma) = \sum_{\text{row cycle }A}\sum_{\text{col cycle }B} \gcd(|A|,|B|)
\]

This depends only on the [cycle type](https://ourbigbook.com/codex/cycle-type) ([integer partition](https://ourbigbook.com/codex/integer-partition) of `n`) of the two [permutations](https://ourbigbook.com/codex/permutation).

---

### 3) Handling flips via parity constraints (only 2-adic valuations matter)

Row/column flips add an [XOR](https://ourbigbook.com/codex/bitwise-exclusive-or) “offset” to the fixed-point equations. Along any cycle of `σ`, consistency requires the [XOR](https://ourbigbook.com/codex/bitwise-exclusive-or) of the offsets around the cycle to be `0`.

For a row cycle of length `a` and column cycle of length `b`, the constraint depends only on

- the [integer parity](https://ourbigbook.com/codex/integer-parity) of flips within that row cycle
- the [integer parity](https://ourbigbook.com/codex/integer-parity) of flips within that column cycle
- the relative powers of 2 in `a` and `b` (their `v₂` values)

Let `v₂(x)` be the exponent of 2 in `x`. Then:

- if `v₂(a) > v₂(b)`, the row-cycle [integer parity](https://ourbigbook.com/codex/integer-parity) must be `0`
- if `v₂(a) < v₂(b)`, the column-cycle [integer parity](https://ourbigbook.com/codex/integer-parity) must be `0`
- if `v₂(a) = v₂(b)`, the two [integer parities](https://ourbigbook.com/codex/integer-parity) must be equal

Because these constraints apply for **every** row-cycle/column-cycle pair, they collapse to a tiny set of cases determined by the minimum `v₂` on each side. This yields a simple count `2^d` for how many [integer parity](https://ourbigbook.com/codex/integer-parity) assignments are allowed.

---

### 4) Summing over conjugacy classes using integer partitions

Everything depends only on the [cycle type](https://ourbigbook.com/codex/cycle-type) of `π_r` and `π_c`, i.e. [integer partitions](https://ourbigbook.com/codex/integer-partition) of `n`.
There are only `p(20)=627` [integer partitions](https://ourbigbook.com/codex/integer-partition), so we can sum over all `(partition_row, partition_col)` pairs.

For a [integer partition](https://ourbigbook.com/codex/integer-partition) with multiplicities `m_l` of cycle length `l`, the number of [permutations](https://ourbigbook.com/codex/permutation) is

\[
\frac{n!}{\prod_l l^{m_l} m_l!}
\]

The final [Burnside's lemma](https://ourbigbook.com/codex/burnside-s-lemma) sum is computed [modulo](https://ourbigbook.com/codex/modulo-operation) `1_001_001_011`.

---

## Complexity

- [integer partitions](https://ourbigbook.com/codex/integer-partition) of 20: 627
- pairs: 627² ≈ 3.9×10⁵
- per pair: small loops over distinct cycle lengths (at most 20)

This runs comfortably fast in pure Python.

## Output

Running `python3 main.py` prints the answer for `n=20` [modulo](https://ourbigbook.com/codex/modulo-operation) `1_001_001_011`.
