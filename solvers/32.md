# Project Euler 32 Solution - Pandigital Products

<https://projecteuler.net/problem=32>:

* [32.py](32.py)
* [32.lean](32.lean)

`solve(width=9)` sums distinct [products](https://ourbigbook.com/codex/product) `p = a * b` of two positive integers such that concatenating `a`, `b`, and `p` uses each decimal [digit](https://ourbigbook.com/codex/numerical-digit) `1..width` exactly once. Products are counted once even if they have multiple valid factor pairs. Widths below three or above nine return zero.

## Key insight: digit-length constraints
If the factors have `i` and `j` digits, their product has either `i+j-1` or `i+j` digits. Therefore a multiplication identity using `width` digits in total has exactly `width // 2` product digits. Set:

```python
product_width = width // 2
lower = 10 ** (product_width - 1)
upper = 10 ** product_width - 1
```

Choose the smaller factor first, so `a <= b`. Then `a*a <= upper`, giving the complete bound `a <= isqrt(upper)`. For each `a`, the second factor runs from `max(a, ceil(lower/a))` through `floor(upper/a)`. These bounds follow from the identity's digit count; neither factor has a separate search cap.

## Approach
Enumerate these factor intervals, compute each product, and check the concatenated decimal string. A bit mask detects out-of-range or repeated digits, and the length check ensures that every target digit occurs. Store accepted products in a set and sum them.

The independent reference splits every permutation of the target digits into three nonempty pieces and checks the multiplication. It also deduplicates products.

The Lean mathematical model proves completeness of both enumerations and equality of their deduplicated sums for arbitrary target widths through nine, without evaluating a fixed answer. Widths below three need more digits than available, and widths above nine would require a decimal digit ten. Source proofs cover the checker, positional conversion, optimized candidate step, and inner loop; the complete source equivalence proof remains pending.

With `U = upper`, the factor search tests at most `O(U log U)` pairs. Each digit check costs `O(width)`, ignoring integer arithmetic costs. Working memory is proportional to the number of distinct accepted products. The default prints 45228.
