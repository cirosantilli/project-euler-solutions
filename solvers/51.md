# Project Euler 51 Solution - Prime Digit Replacements

<https://projecteuler.net/problem=51>:

* [51.py](51.py)
* [51.lean](51.lean)

We search for the smallest [prime](https://ourbigbook.com/codex/prime-number) that belongs to a family of **8 [primes](https://ourbigbook.com/codex/prime-number)** formed by:
- choosing some [digit](https://ourbigbook.com/codex/numerical-digit) positions (not necessarily adjacent),
- replacing all chosen positions with the same [digit](https://ourbigbook.com/codex/numerical-digit) `0..9`,
- counting how many resulting numbers are [prime](https://ourbigbook.com/codex/prime-number) (leading zero is not allowed).

## Key observations / optimizations

1. **The [prime](https://ourbigbook.com/codex/prime-number) must be in its own family**
   If positions are replaced by [digit](https://ourbigbook.com/codex/numerical-digit) `r`, then to regenerate the original [prime](https://ourbigbook.com/codex/prime-number) `p`,
   all replaced positions in `p` must already contain the same [digit](https://ourbigbook.com/codex/numerical-digit).
   Therefore, for each [prime](https://ourbigbook.com/codex/prime-number) we only consider [subsets](https://ourbigbook.com/codex/subset) of positions where `p` has the same [digit](https://ourbigbook.com/codex/numerical-digit).

2. **Do not replace the last [digit](https://ourbigbook.com/codex/numerical-digit)**
   If the last [digit](https://ourbigbook.com/codex/numerical-digit) is replaced, most replacements produce [even numbers](https://ourbigbook.com/codex/even-number) or [multiples](https://ourbigbook.com/codex/integer-multiple) of 5,
   so it is impossible to reach 8 [primes](https://ourbigbook.com/codex/prime-number) out of 10. We skip any [subset](https://ourbigbook.com/codex/subset) containing the last [digit](https://ourbigbook.com/codex/numerical-digit).

3. **[Subset](https://ourbigbook.com/codex/subset) size multiple of 3 (mod 3 [pruning](https://ourbigbook.com/codex/search-pruning))**
   Since `10^k ≡ 1 (mod 3)`, changing `k` [digits](https://ourbigbook.com/codex/numerical-digit) changes the number mod 3 in a way that depends on `k mod 3`.
   If `k` is not a multiple of 3, at least 3 of the 10 replacements are divisible by 3, leaving too few slots
   to still have 8 [primes](https://ourbigbook.com/codex/prime-number). So we only test [subsets](https://ourbigbook.com/codex/subset) with size `k % 3 == 0`.

4. **Fast family generation arithmetically**
   For a chosen [digit](https://ourbigbook.com/codex/numerical-digit) `d` and [subset](https://ourbigbook.com/codex/subset) of positions, precompute:
   - `shift = sum(10^(position_weight))` for those positions.
   Then replacement by `r` yields:
   - `new = p + (r - d) * shift`
   avoiding expensive [string](https://ourbigbook.com/codex/string) reconstruction.

## Algorithm
For increasing digit lengths:
- [Number-theoretic sieve](https://ourbigbook.com/codex/number-theoretic-sieve) all [primes](https://ourbigbook.com/codex/prime-number) up to `10^digits - 1`.
- For each [prime](https://ourbigbook.com/codex/prime-number), generate all valid position [subsets](https://ourbigbook.com/codex/subset) (from repeated [digits](https://ourbigbook.com/codex/numerical-digit), excluding last [digit](https://ourbigbook.com/codex/numerical-digit), size multiple of 3).
- Count how many replacements are [prime](https://ourbigbook.com/codex/prime-number); once a [subset](https://ourbigbook.com/codex/subset) yields ≥ 8 [primes](https://ourbigbook.com/codex/prime-number), return the [prime](https://ourbigbook.com/codex/prime-number).
