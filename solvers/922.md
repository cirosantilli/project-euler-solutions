# Project Euler 922 Solution - Young's Game A

<https://projecteuler.net/problem=922>:

* [922.py](922.py)

This solution uses **[combinatorial game theory](https://ourbigbook.com/codex/combinatorial-game-theory)**, [convolution](https://ourbigbook.com/codex/convolution) techniques, and fast transforms
to count the number of ordered staircase selections where **Right wins**.

---

## 1. Game Decomposition

Each `(a,b,k)` staircase game reduces (in canonical [CGT](https://ourbigbook.com/codex/cgt) form) to:

- a **number part**: `b - a`
- an **impartial [nimber](https://ourbigbook.com/codex/grundy-number) part**: `*(k-1)` (a [Nim heap](https://ourbigbook.com/codex/nim-heap) of size `k-1`)

So the game is equivalent to:

> **(b − a) + [nimber](https://ourbigbook.com/codex/grundy-number)(k−1)**

This matches both sample constraints and allows efficient computation.

---

## 2. Winning Condition

For an ordered tuple of `m` staircases:

- Let `D = sum(b_i − a_i)`
- Let `G = XOR(k_i − 1)`

Then Right (moving first) wins iff:

- `D > 0`, OR
- `D == 0` AND `G != 0`

The [nimber](https://ourbigbook.com/codex/grundy-number) term is infinitesimal and cannot overturn a nonzero [integer](https://ourbigbook.com/codex/integer) advantage.

---

## 3. Counting via Convolution

We need to count distributions of:

- [integer](https://ourbigbook.com/codex/integer) sums `D` (range roughly `[-m(w-2), +m(w-2)]`)
- [XOR](https://ourbigbook.com/codex/xor) sums `G` (fits in 6 bits since `k-1 <= 61`)

This is a [convolution](https://ourbigbook.com/codex/convolution) problem over the group:

> **Z × (Z₂)^6**

---

## 4. Walsh–Hadamard Transform (XOR Convolution)

[XOR convolution](https://ourbigbook.com/codex/xor-convolution) becomes pointwise [multiplication](https://ourbigbook.com/codex/multiplication) after applying the
**[Fast Walsh–Hadamard Transform](https://ourbigbook.com/codex/fast-hadamard-transform) ([FWT](https://ourbigbook.com/codex/fast-hadamard-transform))**.

For each `D` [coefficient](https://ourbigbook.com/codex/coefficient) we store an array over [XOR](https://ourbigbook.com/codex/xor) states (size 64) and transform it.

After transforming, each [XOR](https://ourbigbook.com/codex/xor) frequency `t` becomes an independent [polynomial](https://ourbigbook.com/codex/polynomial) in `D`.

---

## 5. Polynomial Exponentiation

In the transformed space, choosing `m` staircases corresponds to raising each [polynomial](https://ourbigbook.com/codex/polynomial)
to the `m`th power.

Since `m=8`, [exponentiation](https://ourbigbook.com/codex/exponentiation) is fast (only a few squarings).

---

## 6. Inverse Transform + Final Sum

After powering, an inverse [FWT](https://ourbigbook.com/codex/fast-hadamard-transform) reconstructs `(D,G)` counts.

We sum all cases meeting the winning condition [modulo](https://ourbigbook.com/codex/modulo-operation) `1e9+7`.

---

## Complexity

- State size: about `1000 × 64`
- Transforms: tiny (64-point Hadamard)
- [Polynomial multiplications](https://ourbigbook.com/codex/polynomial-multiplication): manageable due to small degree and m=8

Runs quickly in pure Python.
