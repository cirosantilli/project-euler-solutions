# Project Euler 442 Solution - Eleven-free Integers

<https://projecteuler.net/problem=442>:

* [442.py](442.py)

This solution finds **E(10¹⁸)**, where **E(n)** is the *n-th positive “eleven-free” [integer](https://ourbigbook.com/codex/integer)* (a base‑10 number whose [digit](https://ourbigbook.com/codex/numerical-digit) string contains **no substring equal to 11ᵏ for any k ≥ 1**).

## Key techniques

### 1) Finite forbidden set (length cutoff)
For any target `x`, only forbidden strings with length `≤ len(str(x))` can appear as substrings.
So we only generate powers `11¹, 11², …` until their decimal length exceeds the current [digit](https://ourbigbook.com/codex/numerical-digit) length.

### 2) Aho–Corasick automaton (multi-pattern substring detection)
All forbidden decimal strings are inserted into a [trie](https://ourbigbook.com/codex/trie), then failure links are built ([BFS](https://ourbigbook.com/codex/breadth-first-search)).
This produces a DFA-like [finite-state automaton](https://ourbigbook.com/codex/finite-state-automaton) that can scan [digits](https://ourbigbook.com/codex/numerical-digit) left-to-right and track the longest suffix that is also a prefix of some forbidden pattern.

Each [automaton state](https://ourbigbook.com/codex/automaton-state) is marked **bad** if it corresponds to having matched a forbidden pattern (directly or via failure links). Any [digit](https://ourbigbook.com/codex/numerical-digit) transition into a bad state is disallowed.

### 3) Digit DP (count valid numbers ≤ X)
To compute how many eleven-free [positive integers](https://ourbigbook.com/codex/positive-integer) are `≤ X`, we do a standard [digit DP](https://ourbigbook.com/codex/digit-dynamic-programming) over:
- position in the decimal string,
- [automaton state](https://ourbigbook.com/codex/automaton-state),
- whether the number has “started” (to ignore leading zeros),
- tightness (whether the prefix equals `X`’s prefix).

This gives `count(X)` efficiently even for large `X` (≈ 20 [digits](https://ourbigbook.com/codex/numerical-digit)).

### 4) Binary search for the n-th valid integer
`count(X)` is monotone non-decreasing, so we:
1. grow an [upper bound](https://ourbigbook.com/codex/upper-bound) `high` until `count(high) ≥ n`,
2. [binary search](https://ourbigbook.com/codex/binary-search) the smallest `X` with `count(X) ≥ n`, which equals `E(n)`.

## Complexity
Let:
- `D = number of digits` (≈ 19–20 for this problem),
- `S = number of automaton states` (a few hundred at most).

Each `count(X)` is `O(D · S · 10)`, and [binary search](https://ourbigbook.com/codex/binary-search) needs ~60 calls, so the whole run is fast in pure Python.
