# Project Euler 92 Solution - Square Digit Chains

<https://projecteuler.net/problem=92>:

* [92.py](92.py)
* [92.lean](92.lean)

We repeatedly replace a number by the [sum of squares](https://ourbigbook.com/codex/sum-of-squares) of its [digits](https://ourbigbook.com/codex/numerical-digit). Every positive starting number eventually enters the fixed loop at `1` or the loop at `89`. We must count how many starting numbers `< 10,000,000` end at `89`.

### Key insights

- For a number with at most `d` [digits](https://ourbigbook.com/codex/numerical-digit), the first digit-square sum is at most `81*d`.
- Starting values with the same digit-square sum have the same chain endpoint. Count these groups instead of walking every starting value.
- Read the digits of `limit_exclusive - 1` from left to right. For each prefix, track its digit-square sum, whether it still equals the bound's prefix, and how many prefixes share that state.
- Extend each state by every permitted next digit. Leading zeros preserve sums and allow shorter numbers to use the same traversal.
- Memoize whether each resulting sum reaches `1`, `89`, or another repeated value. Sum the group sizes whose endpoint is `89`; the all-zero number contributes nothing.

### Complexity

There are at most `2*(81*d + 1)` prefix states at each digit position, each with at most ten successors. Prefix counting therefore takes `O(d^2)` state transitions and `O(d)` stored states, apart from integer arithmetic and the small memoized chain walks. The supplied bound can have any number of decimal digits; the default is ten million. The reference walks each positive starting value until an endpoint or repeated value, without an iteration cutoff.

The [digit-square orbit proof](../ProjectEulerSolutions/Lib/DigitSquareChains.lean)
shows that every chain stays in `0..max(start, 199)`. This is a proved invariant
used for termination, not a runtime cutoff: the mathematical walk stops only
at a repeated value, and its trace contains exactly the full forward orbit.
The [Python digit-loop proof](92.py.lean.d/Digits.lean) executes `divmod`, tuple
unpacking, multiplication, and accumulation for every nonnegative input,
preserving all caller heap objects. It is also proved equivalent to the
reference's digit-list generator.

The [complete reference source proof](../data/project-euler-statements/data/py/project_euler_statements/p92.py.lean)
follows the endpoint and repeat tests, private path-list mutations, digit calls,
and lazy counting sum for every signed exclusive bound. The
[cache lemmas](../ProjectEulerSolutions/Lib/DigitSquareMemo.lean) prove that
completed walks classify every recorded term correctly and that path compression
preserves cache correctness. The optimized
[`terminal` source proof](92.py.lean.d/Terminal.lean) follows the set and list
updates, digit calls, defaulted dictionary lookup, and forward cache writes.
It returns the correct classification for every nonnegative start and correct
input cache, preserving all existing objects except the cache being updated.

The [prefix-distribution proof](../ProjectEulerSolutions/Lib/DigitSquareDistribution.lean)
shows that permitted digit branches enumerate every integer under the extended
bound exactly once. Combining equal states preserves their multiplicities, and
selecting states that reach 89 gives the reference count. This covers any number
of digits, including leading zeroes. The [Python inner-loop proof](92.py.lean.d/Rows.lean)
connects each complete digit range to that mathematical expansion. It covers
short-circuit key construction, tuple-key dictionary lookup and assignment,
promotion of an empty dictionary, and retention of the original key object
when a state receives another contribution. Other heap objects and variables
are preserved.

The [initial-table proof](92.py.lean.d/Initialization.lean) follows the source's
pooled tuple key on both first use and reuse. The dictionary retains that key's
identity and represents exactly the initial prefix distribution. Its pool
invariant survives allocations and writes to separate dictionaries.

Full solver equivalence still requires nested-target support, execution proofs
for iteration over the prefix tables and bound digits, and the final weighted
sum, composed with the pooled-tuple runtime.
