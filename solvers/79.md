# Project Euler 79 Solution - Passcode Derivation

<https://projecteuler.net/problem=79>:

* [79.py](79.py)
* [79.lean](79.lean)

This is a **shortest common supersequence** problem: every login attempt must appear in the passcode in order, with gaps allowed. For example, `135` is a subsequence of `12345`, but is not a contiguous substring.

Requiring contiguous fragments instead gives the **shortest common superstring** problem, a [classical model of genome assembly](https://doi.org/10.1093/bioinformatics/btw450). P79 has a different bioinformatics connection: in [parallel DNA synthesis](https://arxiv.org/abs/2405.17499), a common supersequence describes nucleotide-addition steps that can produce all the desired strands, and shortening it reduces the number of steps.

Each successful login attempt is a 3-digit [string](https://ourbigbook.com/codex/string) `abc` meaning:

- `a` appears before `b`
- `b` appears before `c`

These are precedence constraints. Collect all [digits](https://ourbigbook.com/codex/numerical-digit) that appear, build a [directed graph](https://ourbigbook.com/codex/directed-graph) with [edges](https://ourbigbook.com/codex/edge) for each constraint (e.g., `a -> b`, `b -> c`), and then compute a **[topological ordering](https://ourbigbook.com/codex/topological-ordering)** of this [graph](https://ourbigbook.com/codex/graph).

For the supplied keylog, this graph is acyclic, so a valid [topological order](https://ourbigbook.com/codex/topological-order) uses each observed digit exactly once. Every valid passcode must include each observed digit at least once, making this ordering shortest. The provided solution uses [Kahn's algorithm](https://ourbigbook.com/codex/kahn-s-algorithm) (indegree-based [topological sort](https://ourbigbook.com/codex/topological-sorting)) with a [heap](https://ourbigbook.com/codex/heap) to select the lexicographically least ordering.

The solver implements this distinct-digit variant. General supersequence inputs can require repeated digits: attempts `123` and `231` fit in `1231`, although their digit-precedence graph has a cycle. Topological sorting alone does not solve that general case.

The [Lean source-level equivalence proofs](79.equivalence.source.lean) cover list and tuple inputs. The stronger claim that arbitrary iterable inputs produce identical observations under every pair of traversal orders is false: on the set `{"", "x"}`, the first invalid attempt determines the exception message. [The source-level counterexample](79.choice.source.lean) proves both complete executions on the same valid modeled heap. This does not distinguish the algorithms when they receive the same input order.
